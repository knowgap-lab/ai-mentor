# Составитель (скилл)

| Поле | Значение |

| Область | catalog |
| Владелец (утверждает) | пользователь (D144) |
| Реализуют | Claude-скилл `composer` (фаза 1, D83); результат проверяют CI ([schema](schema.md), [answer-rules](answer-rules.md), [variants](variants.md)) и независимая сессия ИИ (D211) |

## 1. Назначение

Готовит материалы урока для платформы: из карточки темы и файла урока (`ct-2027`) собирает типы заданий, блоки, этапы урока, варианты и рецепт ДЗ **в формате каталога** и открывает PR в приватный репозиторий каталога. Работает пачками на 2–4 недели вперёд (D140). Это фаза 1 составителя; в фазе 2 тот же выходной формат будут получать конвейер и агент для сравнения (D113, [eval.md](eval.md)).

Скилл **не решает**, что преподавать: порядок, темы и повторения заданы планом ([plan-import.md](plan-import.md)). Он переносит уже написанное репетитором содержание в структурированный вид.

### Шаблон урока

Шаблон урока — часть каталога, он **общий для всех учеников** (D163). Состав урока конкретного ученика собирает `core` из шаблона, переносов и отметок ([lessons](../personalization/lessons.md)). Файл `lessons/<пакет>/L<nn>.yaml`:

```yaml
id: ct-math:L07                       # урок плана, постоянный (место рождения)
topics: [ct-math:M10]
review: [ct-math:M04, ct-math:M08, ct-math:M06, ct-math:M09]
duration_min: 60
stages:
  - id: ct-math:L07.G1                # этап урока
    minutes: [0, 8]
    title: Разминка-вспоминание
    kind: warmup                      # warmup | homework_review | theory | practice | exit_test | homework_handout
    blocks: []
    practice:
      - {type: ct-math:M04.T13, subvariant: ct-math:M04.T13.S1, role: solve_alone, theory_block: ct-math:M04.B02}
  - id: ct-math:L07.G3
    minutes: [13, 30]
    title: Новая тема
    kind: theory
    blocks: [ct-math:M10.B05, ct-math:M10.B06]
    practice: []
homework:                             # рецепт ДЗ: один список задач (D146, D229, D230)
  budget_hours: 6
  items:
    - {source: new_topic, series: [{type: ct-math:M10.T01, count: 4}, {type: ct-math:M10.T02, count: 6}], difficulty: [1, 1]}
    - {source: review, series: [{type: ct-math:M04.T13, count: 1}, {type: ct-math:M06.T03, count: 1}]}
    - {source: ct_format, series: [{type: ct-math:M10.T18, count: 1}]}
generation_notes: |                   # «Заметки для генерации материалов» дословно
  Числа «чистые»…
```

## 3. Правила

### Что читает и чего не делает

- **CP-R1.** Один запуск = одна пачка уроков одного предмета (от 1 до 4 недель), результат — один PR (D140).
- **CP-R2.** Скилл читает только карточки тем, файлы уроков и каталог. Он никогда не читает данные учеников и не пишет вне репозитория каталога (D142).
- **CP-R3.** Скилл не придумывает содержание: каждое утверждение блока, каждый пример и каждая ссылка на тип взяты из карточки или файла урока. Ссылка в файле урока на строку банка, которой нет в карточке, — стоп с вопросом репетитору (`bank_ref_unknown`).

### Типы и подварианты

- **CP-R4.** Каждая строка раздела «Банк типов задач» карточки даёт тип `<пакет>:<тема>.T<nn>`, где `nn` — номер строки банка (CS-R26); тип создаётся один раз, при первом уроке, который его использует.
- **CP-R5.** Поля типа: `title` — «Тип задачи»; `difficulty` — столбец «Ур.»; `answer_format` — по столбцу «Позиция ЦТ» (А → `ct.choice1` или `ct.choiceN`; В1 → `ct.match`; В2 → `ct.digits`; остальные В → `ct.integer`); `primary_element` — `E1` темы; `prerequisites` — из предпосылок темы (LP-R3); `kind: exam`, если указана позиция, иначе `skill` (CS-R15); цитата — ссылка на строку банка.
- **CP-R6.** Стартовые часы уровней типа: пусть `T` — часы темы (`topic_hours`), `w` — сложность типа, `W` — сумма сложностей всех типов темы; тогда `base = T · w / W / 3`, `automatism = 2 · base`, округление до 0,25 ч вверх, минимум 0,25 (D203, D222). Репетитор может поправить значения в PR.
- **CP-R7.** Для каждого типа создаётся хотя бы один подвариант, сформулированный по условию из банка: «что дано / что найти». Если у типа в уроке разбираются разные формулировки, создаётся по подварианту на каждую.

### Блоки

- **CP-R8.** Блоки создаются из разделов карточки: каждый «Шаг N» раздела «Теория» → блок `theory`; каждый подраздел «Опорного конспекта» → блок `summary` или `rule`; каждый «Пример N» → `worked_example`; каждая строка «Типичных ошибок» → `typical_error`; каждая карточка раздела «Карточки для повторения» → `flashcard` (D220). Блок получает `topic_id`, `minutes` и Markdown с формулами LaTeX; ничего не пересказывается своими словами (CP-R3).
- **CP-R9.** Блок, уже существовавший в каталоге с тем же исходным фрагментом, повторно не создаётся: скилл ссылается на него (D140).
- **CP-R10.** Сложные или многошаговые построения (рисунок квадрата, график) оформляются виджетом `{widget, params}` или рисунком SVG из чисел условия; рисунок, нарисованный вручную, не принимается (D135, VR-R11).

### Этапы урока и практика

- **CP-R11.** Каждая строка таблицы «Ход урока» файла урока → этап: `minutes` из столбца «Мин», `title` из «Блок», `kind` по названию этапа, ссылки на блоки и типы из столбца «Опора». Сумма минут этапов равна `duration_min` (по заголовку «Ход урока (N минут)»), этапы идут без пропусков и пересечений.
- **CP-R12.** Каждый пункт раздела «Задачи на уроке» → элемент `practice` соответствующего этапа: тип, подвариант, роль (`solve_together` — «вместе», `solve_alone` — «сам», `teacher_solves` — «я решаю», `scaffolded` — «с пропусками»), и **обязательная ссылка на блок теории** `theory_block` (D96). Если ссылку невозможно определить, скилл спрашивает репетитора.
- **CP-R13.** Условные шаги («если шаг 3 не объясняли — вместо типа 5 вторая задача типа 1») разворачиваются в **линейную последовательность** без веток; условие остаётся в поле `note` пункта (D193).

### Варианты

- **CP-R14.** Для каждого типа, использованного в уроке пачки, скилл готовит варианты по VR-R1/VR-R2: не меньше 8 на тип (минимум CI — 5) и не меньше 2 на каждый подвариант, разбираемый на уроке. Первым вариантом типа идёт пример условия из банка карточки с ответом оттуда; остальные — с другими числами, но тем же подвариантом.
- **CP-R15.** Числа в условии — «чистые»; требования из раздела «Заметки для генерации материалов» (ловушки части А, запрещённые примеры, формат ответа) обязательны для каждого варианта (D212, CS-R19). Заметки хранятся в шаблоне урока дословно в `generation_notes`.
- **CP-R16.** Для каждой неверной опции части А скилл задаёт `trap_id` и причину из «Типичных ошибок» карточки или раздела «Разобранные примеры» (AR-R20).
- **CP-R17.** Скилл **не проверяет** ключи сам. Независимую проверку делает отдельная сессия ИИ, не видящая ключа и решения скилла (D211); её отчёт прикладывается к PR (VR-R13, VR-R15).

### Рецепт ДЗ

- **CP-R18.** Раздел «Домашняя работа» файла урока → `homework` шаблона урока: **одно** ДЗ, список элементов `items` без разбивки по дням и по частям A–E (D229, D230). Элемент — серия задач одного типа: `source` ∈ {`new_topic` — новая тема, по возрастанию сложности; `review` — повторение тем `review` вперемешку, по строкам банка; `ct_format` — задания в формате ЦТ}, типы, число задач и диапазон сложности. Карточки, перечитывание конспекта, чеклист и «журнал ошибок» из файла урока в рецепт **не переносятся** (D230); слова «таймер» и «без конспекта» остаются подсказкой в тексте урока (D227).
- **CP-R19.** Бюджет `budget_hours` берётся из строки «Нагрузка … ≈ N ч» файла урока и пересчитывается только на задачи, попадающие в рецепт. Сумма минут задач рецепта (оценки вариантов, D146) не должна превышать бюджета больше чем на 10 %, иначе скилл предупреждает в отчёте (`homework_budget_mismatch`).
- **CP-R20.** Все элементы рецепта проверяются автоматически по D104 (часть А — одна попытка, часть В — две).

### Заметки и приватность

- **CP-R21.** Каждое замечание репетитора по ходу работы («мне не нравится…», «поправь…») скилл записывает отдельным файлом `notes/<дата>-<слаг>.yaml` рядом с изменением: `change` (id затронутых сущностей), `ai_output` (что выдал ИИ), `fixed` (что исправлено), `why` (почему), `pseudonym` (если речь об ученике). Имена, города, школы и контакты не записываются; CI блокирует такие поля (D84, D98, D139, D142).
- **CP-R22.** В описании PR и в файлах нет сведений об учениках. Примеры ошибок пишутся без привязки к конкретному ученику.

### Контракт PR

- **CP-R23.** Новые сущности несут временные ключи `tmp:<строка>`; постоянные id выдаёт CI при слиянии (D160, CS-R6). Ссылки внутри PR используют те же временные ключи.
- **CP-R24.** У каждой темы, элемента, типа есть цитата (CS-R21); у каждого типа есть `task_rules` пакета и предпосылки на уровне элементов (D160).
- **CP-R25.** Скилл не изменяет сущности, уже слитые в main. Нужная правка оформляется по CS-R24: опечатка — тот же id; смена чисел, условия или ответа — новый вариант и `retired` старого; исправление ключа — тот же id и перепроверка.
- **CP-R26.** Описание PR содержит отчёт: что создано (число типов, блоков, вариантов, этапов), какие допущения сделал скилл (каждое — отдельным пунктом), какие вопросы остались к репетитору, результаты независимой проверки, предупреждения (`homework_budget_mismatch`, пробелы пула).
- **CP-R27.** Если задание неоднозначно, скилл не додумывает: допущение пишется в отчёт, а при невозможности продолжить — вопрос репетитору до открытия PR.

### Размещение

- **CP-R28.** Скилл лежит в публичном репозитории платформы (`tools/composer/`: `SKILL.md` и скрипты) и не содержит ни ключей ответов, ни сведений об учениках. Его выходные файлы лежат только в приватном репозитории каталога (D142, D221).

## 5. Ошибки

| Ситуация | Код | Поведение |
|---|---|---|
| Ссылка на несуществующую строку банка | `bank_ref_unknown` | стоп, вопрос репетитору |
| Не удаётся определить блок теории практики | `theory_block_unknown` | вопрос репетитору |
| Этапы не покрывают урок целиком | `stages_gap` | PR не открывается |
| Рецепт ДЗ не сходится с бюджетом на 10 % | `homework_budget_mismatch` | предупреждение в отчёте |
| Скилл не может продолжить без допущения | — | вопрос репетитору до PR (CP-R27) |
