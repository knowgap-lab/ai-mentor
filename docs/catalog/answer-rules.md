| Поле | Значение |

## 1. Назначение

Описывает **форматы ответа** пакета предмета ЦТ: как ученик вводит ответ, как ввод приводится к каноническому виду, сколько баллов он получает и какие требования предъявляются к ключу и опциям в каталоге. Правила хранятся **как данные пакета предмета**, а не в коде (D103, D185): Go и CI исполняют одну и ту же таблицу.

Источник правил — официальные схемы начисления первичных баллов РИКЗ 2025–2026 (сведены в `ct-2027/research/05-scoring-and-targets.md` и `01-math-format.md`). Пакет помечен `spec_version: rikz-2026` (D141).

## 3. Правила

### Форматы пакета ЦТ

| Формат | Где | Ввод ученика | Баллы | Решения |
|---|---|---|---|---|
| `ct.choice1` | часть А, один верный | номер опции 1–5 | верно — 1, иначе 0 | D23 |
| `ct.choiceN` | часть А, несколько верных (А6, А10 и др.) | набор номеров опций | полное совпадение набора — 1, иначе 0 | D151 |
| `ct.match` | математика В1 | буква → цифра: `А1Б3В4` | 2 / 1 / 0 (частично) | D103 |
| `ct.digits` | математика В2 | набор цифр: `124` | 2 / 1 / 0 (частично) | D103 |
| `ct.integer` | математика В3–В20, физика В1–В20 | целое число, может быть отрицательным | верно — 2, иначе 0 | D80 |

- **AR-R1.** У каждого типа ровно один формат из таблицы пакета (D23, CS-R16).
- **AR-R2.** Штрафа нет: неверный ответ и пропуск дают 0 (РИКЗ).
- **AR-R3.** В физике частичных баллов нет: все задания части В имеют формат `ct.integer` (РИКЗ).
- **AR-R4.** В `ct.choice1` выбор больше одной опции невозможен в интерфейсе; если такой ввод пришёл на сервер — `malformed`.
- **AR-R5.** В `ct.choiceN` ответ засчитывается, только если выбранный набор **в точности** равен набору верных опций; любое отличие — 0 (РИКЗ: «при одном отмеченном ответе там, где их два, задание не засчитывается»).

### Нормализация ввода (до оценки)

- **AR-R6.** Пробелы в начале, в конце и внутри ответа удаляются.
- **AR-R7.** Знаки `−` (U+2212), `–` (U+2013), `‐` (U+2010) и `-` считаются одним знаком минус. Знак `+` перед числом удаляется. `-0` и `0` — одно и то же.
- **AR-R8.** `ct.integer`: после AR-R6–R7 ввод обязан совпадать с `^-?[0-9]+$`, иначе `malformed` («введите целое число»). Ведущие нули отбрасываются (`007` → `7`). Ввод `12,0`, `12.5`, `1/2` — `malformed`, а не неверный ответ.
- **AR-R9.** `ct.match`: буквы сравниваются без учёта регистра; латинские двойники кириллических букв (`A`→`А`, `B`→`В`, `E`→`Е` и т. п.) заменяются кириллицей. После этого ввод — последовательность пар «буква + цифра», каждая буква из набора задания встречается ровно один раз; иначе `malformed`. Порядок пар не важен.
- **AR-R10.** `ct.digits`: ввод — только цифры; порядок не важен (`421` = `124`); повтор одной цифры — `malformed` с подсказкой (D210).
- **AR-R11.** Пустой ввод — `malformed`. `malformed` никогда не становится попыткой и не тратит попытку (D136).

### Оценка

- **AR-R12.** Результат `verdict`: `correct` — полный балл; `partial` — больше 0, но меньше полного; `wrong` — 0.
- **AR-R13.** Частичный балл 1 из 2 (D103, D208): `ct.match` — ровно одна буква с неверной цифрой, остальные верны; `ct.digits` — симметрическая разность наборов ученика и ключа ровно 1 (одна лишняя или одна недостающая цифра). Всё остальное, кроме полного совпадения, — 0. Формулировку сверяет агент с PDF схемы начисления РИКЗ 2026, утверждает репетитор.
- **AR-R14.** Если нормализованный неверный ответ совпадает с ловушкой варианта, в результат пишется её `trap_id` (D11). Для частей ответа (пара В1, цифра В2) ловушки в выпуске 1 не сопоставляются.
- **AR-R15.** Оценка — чистая функция `(формат, нормализованный ввод, ключ, ловушки) → результат`: без времени, без состояния, без обращений к базе. Её таблица примеров общая для Go и CI (D133, D180).

### Требования к ключу и опциям в каталоге (проверяет CI)

- **AR-R16.** Ключ `ct.integer` — точное целое без округления; если в решении получается дробь, условие обязано содержать фразу масштаба из списка пакета (например, «ответ умножьте на 10», «ответ запишите в сантиметрах») (D80, D150).
- **AR-R17.** Ключ `ct.digits` — цифры по возрастанию без повторов (D150).
- **AR-R18.** Ключ `ct.match` — каждой букве ровно одна цифра; разные буквы **могут** иметь одинаковую цифру (`А1Б1В4`), если условие задания этого явно не запрещает (D209, исправляет D150).
- **AR-R19.** Часть А: ровно 5 опций; все попарно различны после нормализации текста; ни одна неверная опция не совпадает с ключом; число верных опций указано явно и совпадает с ключом (`ct.choice1` — 1, `ct.choiceN` — ≥ 2) (D151).
- **AR-R20.** У каждой неверной опции части А есть `trap_id` с описанием причины ошибки (D11, D151).

## 5. Ошибки

| Ситуация | Код | Поведение |
|---|---|---|
| Ввод не проходит нормализацию | `malformed` | web подсвечивает поле и подсказывает формат; на сервере попытка не создаётся (D136) |
| Ключ ct.integer не целый и нет фразы масштаба | `key_not_integer` | PR заблокирован |
| Ключ ct.digits не по возрастанию или с повтором | `key_digits_order` | PR заблокирован |
| Ключ ct.match без какой-то буквы | `key_match_incomplete` | PR заблокирован |
| Опций не 5 или есть одинаковые | `options_not_distinct` | PR заблокирован |
| Неверная опция совпадает с ключом | `distractor_equals_key` | PR заблокирован |
| Число верных опций не совпадает с ключом | `correct_count_mismatch` | PR заблокирован |
| У неверной опции нет trap_id | `trap_missing` | PR заблокирован |
| У типа формат, которого нет в пакете | `answer_format_unknown` | PR заблокирован |

## 6. Вне рамок

- Хранение попытки, лимит попыток, показ ответа и вторая попытка в части В — [attempts](../platform/attempts.md), D104.
- Вид компонентов ввода в интерфейсе — [web](../platform/web.md), D136.
- Независимая проверка правильности ключа (подстановка, второй решатель) — [variants.md](variants.md), D119.
- Перевод первичных баллов в тестовые (таблица РИКЗ): лежит в пакете предмета как данные, но используется прогнозом и оптимизатором, а не проверкой.
- Символьные ответы (выражения, интервалы) — не планируются (D80).
