# Схема каталога

| Поле | Значение |
|---|---|
| Область | catalog |
| Владелец (утверждает) | пользователь (D144) |
| Реализуют | content (Python, CI и загрузчик) — пишет; core (Go), worker (Python), скилл составителя — читают или порождают исходники |
| Выпуск | 1 |
| Решения | D3, D16, D21, D23, D26, D37, D43, D47, D62, D66, D70, D71, D96, D112, D114–D116, D135, D141, D142, D146, D149, D160, D183, D187, D190, D202 |
| Статус | на ревью |

## 1. Назначение

Описывает, **из каких сущностей состоит каталог**, как они связаны, как называются (id) и что в них обязательно. Это первая спецификация: на неё опираются проверка ответов, журнал попыток, сборка уроков и ДЗ, импорт плана и скилл.

## 2. Вход и выход

| Вход | Откуда | Контракт |
|---|---|---|
| Исходники каталога (YAML и Markdown) | приватный репозиторий каталога (D142), их пишет скилл или человек через PR | `contracts/catalog.schema.json` |

| Выход | Куда | Контракт |
|---|---|---|
| Таблицы `catalog.*` | PostgreSQL через загрузчик (D118, D191) | `contracts/catalog.schema.json` |
| Ошибки проверки | CI в PR | коды из раздела 5 |

Модуль владеет только описанием структуры. Как CI проверяет ответы и ключи — в [answer-rules.md](answer-rules.md) и [variants.md](variants.md); как данные попадают в базу — в [loader.md](loader.md).

### Раскладка файлов в репозитории каталога

```
<пакет>/                       например ct-math/
  package.yaml                 пакет предмета: id, предмет, версия спецификации (D141), ссылка на правила ответа
  topics/<тема>.yaml           тема + её элементы + её типы и подварианты
  variants/<тема>/<тип>.yaml   варианты одного типа
  blocks/<тема>/<блок>.md      блок: frontmatter + Markdown с LaTeX (D135)
  tests/<тест>.yaml            тест (вариант ЦТ/ЦЭ/РТ) и его появления
  lessons/L<nn>.yaml           шаблон урока: этапы, практика, рецепт ДЗ (формат в composer.md, D223)
  notes/<дата>-<слаг>.yaml     заметки репетитора (D84, composer.md CP-R21)
  transfer-map.yaml            карта переноса при делении и слиянии (D116)
```

Образец файла темы (сокращённо):

```yaml
id: ct-math:M14
title: Обратные тригонометрические функции и простейшие уравнения
section: Тригонометрия
status: active
spec_version: rikz-2026            # D141
citations: [{doc: spec-2026, item: "4.3"}]
elements:
  - id: ct-math:M14.E1
    title: Аркфункции табличных чисел
    citations: [{doc: spec-2026, item: "4.3.1"}]
types:
  - id: ct-math:M14.T07
    title: Функция от арка
    kind: exam                       # exam | skill (D62)
    primary_element: ct-math:M14.E1  # ровно один (D149)
    prerequisites: [ct-math:M13.E2]  # только элементы (D70)
    answer_format: ct.number         # из пакета предмета (D23, D185)
    difficulty: 2                    # сложность 1–3, не уровень освоения
    levels:
      base: {hours: 0.5}
      automatism: {hours: 1.0}
    citations: [{doc: topic-card, ref: "M14 §Банк 7"}]
    subvariants:
      - id: ct-math:M14.T07.S1
        given: "значение тригонометрической функции от аркфункции"
```

## 3. Правила

### Идентификаторы

- **CS-R1.** Каждая сущность каталога, кроме теста, имеет id по схеме `<пакет>:<тема>[.<E|T|B><n>[.S<n>[.V<n>]]]` (D202). Пакет — `[a-z][a-z0-9-]*`, тема — `[A-Z][A-Z0-9]*`. Номера: `E` и `S` — 1–99 без ведущих нулей; `T` и `B` — 01–99, ровно 2 цифры; `V` — 001–999, ровно 3 цифры. Проверка — регулярное выражение:
  `^[a-z][a-z0-9-]*:[A-Z][A-Z0-9]*(\.(E[1-9][0-9]?|B(0[1-9]|[1-9][0-9])|T(0[1-9]|[1-9][0-9])(\.S[1-9][0-9]?(\.V(00[1-9]|0[1-9][0-9]|[1-9][0-9]{2}))?)?))?$`
- **CS-R2.** `S` бывает только под `T`, `V` — только под `S`. `E` и `B` бывают только сразу под темой (это следствие CS-R1, но проверяется с отдельным кодом ошибки для понятности).
- **CS-R3.** Тест имеет id `<пакет>:TEST.<год>-<этап>-<номер>`, например `ct-math:TEST.2025-CT-V2` (D183).
- **CS-R4.** id никогда не меняется и не используется повторно, даже после «устарел» (D21, D114).
- **CS-R5.** id означает место рождения: если сущность позже относится к другой теме, её id остаётся прежним, а принадлежность берётся из полей записи (D202).
- **CS-R6.** Новые сущности в PR несут временный ключ `tmp:<строка>`; постоянный номер выдаёт CI при слиянии — следующий свободный номер в своём родителе (D160).

### Иерархия и связи

- **CS-R7.** Каждая сущность принадлежит ровно одному пакету. Между пакетами допускаются только ссылки-предпосылки (D26).
- **CS-R8.** Элемент принадлежит ровно одной теме (D70).
- **CS-R9.** У типа ровно один `primary_element` и ноль или больше `prerequisites` (D149).
- **CS-R10.** Предпосылки ссылаются только на элементы, никогда на темы или типы (D70).
- **CS-R11.** Граф «тип → предпосылка-элемент → основной элемент других типов» не содержит циклов (D70, D71).
- **CS-R12.** Подвариант принадлежит ровно одному типу, вариант — ровно одному подварианту (D37, D149).
- **CS-R13.** Блок принадлежит ровно одной теме; `kind` ∈ {`theory`, `rule`, `summary`, `worked_example`, `typical_error`, `flashcard`, `widget`} (D43, D112, D220).
- **CS-R14.** Появление — это тройка (тест, позиция, тип); позиция — свойство появления, а не типа (D3). Позиции пакета ЦТ: `A1…A10`, `B1…B20`.

### Типы

- **CS-R15.** `kind` типа ∈ {`exam`, `skill`}. У типа `skill` нет появлений; его ценность приходит только через типы, для которых он предпосылка (D62).
- **CS-R16.** `answer_format` типа — один из форматов, объявленных в пакете предмета (D23, D185).
- **CS-R17.** У типа ровно две записи уровня освоения, `base` и `automatism`, у каждой — часы > 0, и часы `automatism` ≥ часов `base`. Стартовые часы скилл вычисляет из часов темы (`hours_lesson + hours_home` в `graph.json`) с учётом сложности типа; репетитор может поправить их в PR (D47, D66, D71, D203).
- **CS-R18.** `difficulty` ∈ {1, 2, 3} — сложность из банка карточки, не уровень освоения (D112).

### Варианты

- **CS-R19.** Вариант содержит: условие (Markdown + LaTeX, D135), ключ, оценку в минутах (D146), флаг `checkpoint_reserve` (D149), ссылку на блок теории `theory_block` (D96), необязательный `source` (D16). Для части А — опции и ловушки по [answer-rules.md](answer-rules.md).
- **CS-R20.** `theory_block` варианта указывает на блок вида `theory`, `rule` или `worked_example` той же темы или темы его основного элемента.

### Происхождение и версии

- **CS-R21.** Тема, элемент и тип имеют хотя бы одну цитату `citations` (документ и пункт или ссылка на карточку темы) (D160).
- **CS-R22.** Пакет предмета указывает `spec_version`; каждая тема наследует его, если не указала свой (D141).
- **CS-R23.** Удаление сущности запрещено; вывод из использования — `status: retired` с причиной (D21).
- **CS-R24.** Правки подчиняются D115: опечатка и оформление сохраняют id; смена чисел, условия или ответа — новый вариант, старый `retired`; исправление ошибочного ключа сохраняет id и вызывает перепроверку (D123).
- **CS-R25.** Деление и слияние записываются в `transfer-map.yaml` на уровне типов и элементов: каждая запись — `from: [id…] → to: [id…]` с причиной. При делении типа его подварианты вместе с вариантами целиком переходят в один из новых типов, и запись называет этот тип (`subvariants_to: <id>`); id подвариантов и вариантов не меняются. Каждый `retired` тип и элемент, у которого были появления или варианты, обязан встречаться в карте (D116, D205).
- **CS-R28.** Версия каталога — хеш merge-коммита в main плюс монотонный номер версии `catalog_version` (1, 2, 3…), который загрузчик присваивает при загрузке (D57, D206).

- **CS-R30.** Шаблон урока имеет id `<пакет>:L<nn>` (`nn` — номер урока плана: 01–99 с ведущим нулём или 100–999), его этап — `<пакет>:L<nn>.G<n>`, `n` — от 1. Регулярное выражение: `^[a-z][a-z0-9-]*:L(0[1-9]|[1-9][0-9]{1,2})(\.G[1-9][0-9]?)?$`. Номер этапа выдаётся по порядку в уроке; шаблон урока и этап принадлежат пакету, а не теме (D223).

### Связь со старыми данными

- **CS-R26.** Код темы из `ct-2027` (`M01…`, `P01…`) становится кодом темы в id (`ct-math:M01`, `ct-phys:P01`); номер строки банка карточки становится номером типа (`§Банк 7` → `T07`) (D190, D202).
- **CS-R27.** В выпуске 1 у каждой темы ровно один элемент `E1` «тема целиком»; предпосылка между темами `M13 → M14` становится предпосылкой `ct-math:M13.E1` у типов темы M14. Дробление темы на элементы (D70) идёт постепенно: новые элементы `E2…` появляются, а `E1` уходит в `retired` с записью в карте переноса (D204).
- **CS-R29.** Поле `tier` (A–D) из `graph.json` в каталог не переносится: оно зависит от цели ученика и вычисляется оптимизатором. Поле `level` (фундамент/ядро) переносится как справочное поле темы `foundation_level` и ни на какие расчёты не влияет (D207).

## 5. Ошибки

Все ошибки возникают в CI на PR и блокируют слияние (D119). Загрузчик повторно проверяет то же самое и отказывается загружать невалидный артефакт.

| Ситуация | Код | Поведение |
|---|---|---|
| id не по схеме | `id_invalid` | PR заблокирован, указан файл и строка |
| id удалён | `id_removed` | заблокирован |
| id использован повторно | `id_reused` | заблокирован |
| временный ключ в main | `tmp_key_in_main` | заблокирован |
| нет основного элемента | `primary_element_missing` | заблокирован |
| предпосылка не на элемент | `prereq_not_element` | заблокирован |
| цикл в предпосылках | `prereq_cycle` | заблокирован, показан цикл |
| неизвестный формат ответа | `answer_format_unknown` | заблокирован |
| нарушен порядок часов уровней | `level_hours_order` | заблокирован |
| нет цитаты | `citation_missing` | заблокирован |
| нет записи в карте переноса | `transfer_map_missing` | заблокирован |
| ссылка на несуществующий id | `dangling_ref` | заблокирован |
| поле, которого нет в схеме (например `tier`) | `field_not_allowed` | заблокирован |

## 6. Вне рамок

- Правила форматов ответа, баллов, нормализации, опций части А — [answer-rules.md](answer-rules.md).
- Размер пула, резерв, проверка ключей, шаблоны — [variants.md](variants.md).
- Загрузка в базу и версии в базе — [loader.md](loader.md).
- Импорт статичного плана — [plan-import.md](plan-import.md).
- Всё, что касается конкретного ученика: попытки, модель знаний, план.
- Частоты типов: они вычисляются из появлений (D187), но в каталоге не хранятся как ручное поле.
