# Импорт плана

| Поле | Значение |
|---|---|
| Область | catalog |
| Владелец (утверждает) | пользователь (D144) |
| Реализуют | content (Python): разбор исходников и сборка набора импорта; core (Go): приём и запись в `core.*` |
| Выпуск | 1 |
| Решения | D100, D105, D106, D120, D163, D190, D192, D193, D197, D202, D204, D207 |
| Статус | на ревью |

## 1. Назначение

Один раз переносит существующий статичный план подготовки из `ct-2027` в платформу: скелет каталога (темы, их элементы `E1`, предпосылки между темами) и уроки (порядок, недели, фазы, виды, темы и повторения). Результат — **версия плана 0**: в выпуске 1 это сам план, с выпуска 2 — эталон, с которым сравнивается оптимизатор (D163, D197).

Импорт **не создаёт** типы заданий, блоки и варианты: их готовит скилл составителя к каждому уроку ([composer.md](composer.md)).

## 2. Вход и выход

### Источник правды

В `ct-2027` файлы `PLAN.md`, `SCHEDULE.md` и `graph/graph.json` **сгенерированы** скриптом `tools/build.py` из карточек и файлов уроков. Поэтому импортируются только первичные источники, а сгенерированные файлы служат для сверки (LP-R4).

| Вход | Откуда | Содержимое |
|---|---|---|
| Карточки тем `<предмет>/topics/*.md` | `ct-2027` | frontmatter: `id, title, section, tier, level, prereqs, ct_positions, hours_lesson, hours_home` |
| Файлы уроков `<предмет>/plan/L*.md` | `ct-2027` | frontmatter: `subject, lesson, week, phase, kind, topics, review`; заголовок урока из первой строки `#`; текст урока для скилла |
| `graph/graph.json`, `PLAN.md` | `ct-2027` | только для сверки |
| Ученик и предмет, к которым привязывается план | параметры запуска | `student_id`, `subject`, `shift_weeks` |

| Выход | Куда | Контракт |
|---|---|---|
| Исходники скелета каталога (YAML тем с `E1`) | PR в приватный репозиторий каталога | `catalog.schema.json` |
| Набор уроков плана 0 для ученика и предмета | `core.*` через внутренний API | `internal-api.yaml` |
| Снимок плана 0: хеши всех исходных файлов | `core.*` | `internal-api.yaml` (D197) |
| Отчёт импорта (что создано, что пропущено, расхождения со сгенерированными файлами) | комментарий PR и файл отчёта | — |

Пишет в базу только `core` (D92, D163); скелет каталога попадает в базу обычным путём PR → CI → загрузчик ([loader.md](loader.md)).

## 3. Правила

### Скелет каталога (темы)

- **LP-R1.** Каждая карточка темы даёт тему `<пакет>:<код>` и ровно один элемент `<пакет>:<код>.E1` «тема целиком» (D204). Пакет: `math` → `ct-math`, `physics` → `ct-phys`.
- **LP-R2.** Код темы остаётся прежним (`M14` → `ct-math:M14`); таблица соответствия нужна только для исключений и по умолчанию пуста (CS-R26, уточняет D190).
- **LP-R3.** Предпосылка карточки `prereqs: [M13]` становится предпосылкой `ct-math:M13.E1` у **типов** темы M14. Пока у темы нет типов, предпосылки записываются в поле темы `prerequisite_elements` и скилл переносит их на созданные типы (D204).
- **LP-R4.** Поля переносятся так: `title` → название; `section` → раздел; `level` → `foundation_level` (D207); `hours_lesson + hours_home` → `topic_hours` (источник стартовых часов типов, D203); `ct_positions` → справочное поле `ct_positions` (не появления: появления берутся из тестов, D187). Поле `tier` не переносится (D207).
- **LP-R5.** Каждая тема и элемент получают цитату `{doc: topic-card, ref: <путь карточки>}` (CS-R21).

### Уроки (план 0)

- **LP-R6.** Для каждого файла урока создаётся урок плана 0 с полями: предмет, номер, `planned_week` (из `week`), `phase`, `kind`, `topics`, `review`, название, путь исходника, хеш исходника.
- **LP-R7.** `kind` ∈ {`diagnostic`, `new`, `consolidation`, `review`, `mock`, `analysis`}. Любое другое значение — ошибка импорта.
- **LP-R8.** Все виды урока импортируются как обычные уроки: бланки диагностики и тестов печатаются в PDF, ответы в выпуске 1 не вносятся (D192).
- **LP-R9.** `topics` и `review` ссылаются на существующие темы; `review` содержит только темы, введённые в уроках с меньшим номером (проверено на текущих данных).
- **LP-R10.** Номера уроков каждого предмета идут подряд с 1; `week` — понедельники, строго возрастают.
- **LP-R11.** `planned_week` сдвигается на `shift_weeks` недель (целое, по умолчанию 0), чтобы тот же план можно было привязать к другому ученику с другой датой начала. Номера и порядок не меняются. Если путь ученика другой, репетитор правит план в кабинете (D219).
- **LP-R12.** Конкретная дата, время и длительность урока в плане не хранятся: их задаёт правило расписания ученика ([lessons](../personalization/lessons.md), D105). Пока правила нет, урок отображается как «неделя с понедельника `planned_week`».

### Состояние импорта

- **LP-R13.** Импорт выполняется **один раз** для пары (ученик, предмет) (D190). Повторный запуск для той же пары отклоняется (`already_imported`), кроме режима `--dry-run`, который только строит отчёт расхождений.
- **LP-R14.** После импорта план живёт в `core.*`: изменения порядка, переносы и отмены вносятся через кабинет (D105, D106). Правки файлов в `ct-2027` на уже импортированный план не влияют; на содержимое уроков для скилла они влиять могут (LP-R20).
- **LP-R15.** Снимок плана 0 хранит хеши всех исходных файлов и неизменяем (D197). Дальнейшие расхождения реального плана с планом 0 показываются как отчёт для репетитора, а не как ошибка.
- **LP-R16.** Импорт атомарен: либо записаны все уроки обеих сторон (скелет в PR, уроки в `core`), либо ничего. Сбой не оставляет частично импортированный предмет.
- **LP-R17.** Уроки с `planned_week` раньше текущей недели получают состояние `held` без снимка и без отметок; репетитор может поставить отметки задним числом. ДЗ для них не собираются (D100, D105, D218).

### Сверка и ошибки данных

- **LP-R18.** Импорт сверяет результат со сгенерированными `graph.json` и `PLAN.md`: число тем, число уроков, порядок, недели. Расхождение — предупреждение в отчёте, не блокировка.
- **LP-R19.** Невалидный frontmatter (нет обязательного поля, неверный тип, неизвестная тема) блокирует импорт и указывает файл и строку.
- **LP-R20.** Текст урока не разбирается импортом. Скилл читает его целиком и по разделам (`Цель урока`, `Перед уроком`, `Ход урока`, `Задачи на уроке`, `Домашняя работа`, `Заметки для генерации материалов`) создаёт блоки, этапы, варианты и рецепт ДЗ ([composer.md](composer.md), D146, D193). Импорт лишь запоминает путь и хеш.

## 5. Ошибки

| Ситуация | Код | Поведение |
|---|---|---|
| Нет обязательного поля frontmatter | `frontmatter_invalid` | блокировка, файл и строка |
| Неизвестный вид урока | `kind_unknown` | блокировка |
| Ссылка на несуществующую тему | `topic_unknown` | блокировка |
| Повтор раньше введения | `review_before_intro` | блокировка |
| Пропуск в нумерации | `lesson_gap` | блокировка |
| Неделя не понедельник или порядок нарушен | `week_not_monday`, `week_not_increasing` | блокировка |
| Повторный импорт той же пары | `already_imported` | отказ |
| Сбой записи | `import_failed` | откат, ничего не записано, тревога (D129) |
| Расхождение со сгенерированными файлами | `generated_mismatch` | предупреждение в отчёте |
