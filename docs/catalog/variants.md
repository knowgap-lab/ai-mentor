# Варианты и шаблоны

| Поле | Значение |
|---|---|
| Область | catalog |
| Владелец (утверждает) | пользователь (D144) |
| Реализуют | content (Python, CI); скилл составителя порождает варианты; core (Go) выбирает варианты для выдачи |
| Выпуск | 1 (готовые варианты); 2 (шаблоны) |
| Решения | D16, D27, D37, D53, D56, D64, D65, D101, D115, D119, D146, D148, D149, D188, D193, D199 |
| Статус | на ревью |

## 1. Назначение

Описывает, **откуда берутся варианты**, сколько их нужно, как CI убеждается, что ключ верный, и какие варианты ученик уже видел. В выпуске 1 все варианты готовые (их пишет скилл), шаблоны появляются в выпуске 2 (D101).

## 2. Вход и выход

| Вход | Откуда | Контракт |
|---|---|---|
| Файлы `variants/<тема>/<тип>.yaml` | PR от скилла или человека | `catalog.schema.json` |
| Шаблоны (выпуск 2) | PR | `catalog.schema.json` |

| Выход | Куда | Контракт |
|---|---|---|
| Проверенные варианты в `catalog.*` | загрузчик | `catalog.schema.json` |
| Отчёт проверки ключей и превью вариантов | комментарий CI в PR | — |
| Выбор варианта для выдачи (функция) | core: уроки, ДЗ, срезы | — |

## 3. Правила

### Пул и резерв

- **VR-R1.** У каждого типа, который используется в опубликованном уроке, не меньше 5 активных вариантов; скилл по умолчанию готовит 8 (D101, D148).
- **VR-R2.** У каждого подварианта, который разбирается на уроке, не меньше 2 активных вариантов, чтобы закрепление в ДЗ (тот же подвариант, другие числа) было возможно всегда (D39, D188).
- **VR-R3.** Вариант с флагом `checkpoint_reserve` никогда не попадает в урок и ДЗ; срезы и пробники берут варианты только из резерва (D37, D149). С выпуска 2 в резерв уходит 20 % пула типа (округление вверх), но не меньше 1 варианта у каждого типа с появлениями в тестах; в выпуске 1 резерв не обязателен, срезы идут по PDF (D192, D213).
- **VR-R4.** Нарушение VR-R1–R2 блокирует PR (`pool_too_small`, `reinforcement_impossible`).

### Повторы

- **VR-R5.** Вариант считается **показанным** ученику, если он появился в любом виде: этап урока, ДЗ, PDF, срез, пробник, диагностика (D27, D193). Попытка для этого не нужна.
- **VR-R6.** Система никогда не выдаёт ученику показанный ему вариант (D27).
- **VR-R7.** Если для типа у ученика не осталось непоказанных вариантов, тип не попадает в выдачу, а репетитор получает предупреждение «нужны варианты» (D101).
- **VR-R8.** Выбор варианта детерминирован. Для закрепления (D39) берётся непоказанный вариант **того же** подварианта, что разбирался на уроке. В остальных случаях сначала берётся подвариант, который ученику показывали давнее всего (никогда не показанный — раньше всех), и внутри него — непоказанный вариант с наименьшим id (D37, D39).

### Содержимое варианта

- **VR-R9.** Обязательные поля варианта перечислены в [schema.md](schema.md) (CS-R19); формат ключа и опций — в [answer-rules.md](answer-rules.md).
- **VR-R10.** Оценка в минутах — целое число от 1 до 60; её ставит скилл, репетитор может поправить (D146).
- **VR-R11.** Рисунки (графики, схемы) строятся программой из тех же чисел, что и условие, в формате SVG; рисунок, нарисованный вручную, не принимается (D65).
- **VR-R12.** Условие соблюдает правила ЦТ: единицы измерения и константы даны в условии, ответ однозначен (AR-R16), задача решается без калькулятора (D64). «Без калькулятора» означает: в эталонном решении скилла каждое промежуточное число — целое или дробь со знаменателем ≤ 100, по модулю ≤ 10 000, без приближённых значений корней и π. Нарушение — `ct_rule_violation`; репетитор может явно разрешить исключение полем `calculator_exception: <причина>` (D212).

### Независимая проверка ключа

- **VR-R13.** Ключ каждого нового или изменённого варианта проверяется независимо (D56, D211): отдельная сессия ИИ решает вариант, не видя ключа и решения скилла; для `ct.integer` скрипт CI дополнительно подставляет ответ в условие, если условие это допускает (уравнение, вычисление). Обе проверки должны совпасть с ключом.
- **VR-R14.** Любое расхождение независимой проверки с ключом блокирует PR до решения репетитора (`key_mismatch`) (D119).
- **VR-R15.** CI публикует в PR превью: условие, ключ, рисунок — для каждого нового или изменённого варианта (D56).

### Правки

- **VR-R16.** Правки вариантов подчиняются CS-R24 (D115): опечатка — тот же id; смена чисел или условия — новый вариант, старый `retired`; исправление неверного ключа — тот же id и перепроверка попыток.
- **VR-R17.** `retired` вариант больше не выдаётся, но остаётся в базе и в истории попыток.

### Шаблоны (выпуск 2)

- **VR-R18.** Шаблон описывает один подвариант; CI разворачивает его в варианты с постоянными id и проверяет каждый развёрнутый вариант по VR-R11–R15 и [answer-rules.md](answer-rules.md) (D53).
- **VR-R19.** Развёртывание детерминировано: номер варианта `V<n>` получает параметры из генератора с зерном «id шаблона + n» (D53).
- **VR-R20.** CI отбрасывает развёрнутый вариант, совпадающий с уже существующим вариантом того же подварианта (одинаковые нормализованное условие и ключ) (D199).
- **VR-R21.** Сервер никогда не исполняет код шаблонов: в базу попадают только развёрнутые варианты (D53).

## 5. Ошибки

| Ситуация | Код | Поведение |
|---|---|---|
| Мало вариантов у типа урока | `pool_too_small` | PR заблокирован |
| Невозможно закрепление | `reinforcement_impossible` | PR заблокирован |
| Независимая проверка не совпала с ключом | `key_mismatch` | PR заблокирован до решения репетитора |
| Минуты вне 1–60 | `minutes_out_of_range` | PR заблокирован |
| Рисунок не сгенерирован программой | `figure_not_generated` | PR заблокирован |
| Нарушено правило ЦТ (единицы, константы, калькулятор) | `ct_rule_violation` | PR заблокирован |
| У ученика кончились варианты типа | — | тип не выдаётся, предупреждение репетитору (VR-R7) |
