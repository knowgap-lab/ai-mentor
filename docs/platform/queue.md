# Очередь заданий

| Поле | Значение |
|---|---|
| Область | platform |
| Владелец (утверждает) | напарник (D144) |
| Реализуют | core (Go) — вставка заданий; worker (Python) — выполнение |
| Выпуск | 2 (в выпуске 1 очереди и worker нет, D126) |
| Решения | D33, D76, D81, D87, D89, D91, D92, D124, D125, D129, D148, D156, D162, D175, D176, D252 |
| Статус | на ревью |

## 1. Назначение

Передаёт из `core` в worker сведения о том, что для ученика изменились факты или ограничения и производные данные (модель знаний, прогноз, план) надо пересчитать. Очередь хранится в PostgreSQL (схема `queue.*`), задания берутся с арендой и выполняются идемпотентно. Остановка worker не теряет данных: план просто устаревает (D76).

## 2. Вход и выход

| Вход | Откуда | Контракт |
|---|---|---|
| Событие журнала, класс которого запускает пересчёт (QU-R2) | `core`, [attempts](attempts.md), [recheck](recheck.md) | `events.schema.json` |
| Вставка задания функцией в той же транзакции, что и событие | `core` | `queue.schema.json` |

| Выход | Куда | Контракт |
|---|---|---|
| Результаты в `compute.*` (модель, прогноз, план) | пишет только worker (D92) | `compute-views.schema.json` |
| Тревога о лаге пересчёта репетитору, о `failed` — владельцу | [notifications](notifications.md) | — |
| Отметка «план на <время>» в кабинете | [web](web.md) | `core-api.yaml` |

## 3. Правила

### Постановка

- **QU-R1.** Задание вставляется функцией в той же транзакции, что и событие журнала, которое его вызвало (D33). Задание не создаётся без события.
- **QU-R2.** Классы событий (D87, D175):
  - *факты*: сданное ДЗ, срез, пробник, завершённая диагностика, отметка урока, перепроверка после исправления ключа, импортированные результаты РТ, ручной вердикт, переопределение типа репетитором. Запускают пересчёт модели знаний и плана;
  - *ограничения*: правка репетитора, одобренное предложение агента, цель, дата экзамена, бюджет часов, новая версия каталога, отмена урока, перенос расписания. Запускают пересчёт только плана.
- **QU-R3.** Ничего не запускается от одного ответа ученика (D81, D87).
- **QU-R4.** Задание тонкое: `{student_id, kind (model|plan), trigger_event_id}` (D156). Данные берёт сам worker из журнала.
- **QU-R5.** Ожидающие задания одного ученика сливаются в одно; `model` поглощает `plan`; `trigger_event_id` хранит максимальный (D156).
- **QU-R6.** Версия каталога входит во вход задания и в сохранённый план; план более старой версии не заменяет более новый (D124).
- **QU-R7.** Архивация ученика отменяет его ожидающие задания (D175).

### Выполнение

- **QU-R8.** Worker берёт задания по `FOR UPDATE SKIP LOCKED` с арендой 120 секунд и счётчиком попыток; по окончании аренды задание может взять другой экземпляр (D92, D125, D148).
- **QU-R9.** Для одного ученика одновременно идёт не более одного пересчёта (D89).
- **QU-R10.** Задание запоминает номер последнего прочитанного события журнала. Результат записывается в `compute.*` только если для ученика нет более нового события; иначе задание начинается заново с актуального состояния (D89, D156).
- **QU-R11.** Задание идемпотентно: повторное выполнение с теми же входными данными даёт тот же результат (D33).
- **QU-R12.** Ошибка — повтор с паузой 30 с · 2^(попытка − 1); после 5 попыток состояние `failed` и тревога владельцу (D125, D148, D129).

### Экземпляры

- **QU-R13.** Один код worker запускается двумя экземплярами с раздельными очередями: `recalc` (модель, оптимизатор, план) и `agent` (вызовы LLM с жёстким тайм-аутом). Код синхронный, без asyncio (D91). Очередь `agent` появляется в выпуске 4; после пересчёта worker ставит в неё `AgentTrigger` с номерами ревизий журнала и плана (D162).

### Наблюдаемость

- **QU-R14.** Если самое старое необработанное событие старше 15 минут, репетитору уходит одна тревога на ученика, пока лаг не исчезнет (D91, D148, D129).
- **QU-R15.** Для каждого ученика кабинет показывает «план на <время последнего расчёта>» (D91).

### Права

- **QU-R16.** Роль worker читает журнал и каталог через представления без ПДн и не имеет доступа к таблицам ПДн; запись только в `compute.*` и в статус своих заданий. Тест CI проверяет права (D92).

## 4. Таблицы примеров

Файл `queue.examples.yaml` (D133). Ключевые строки:

| Правило | Ситуация | Ожидаемый результат |
|---|---|---|
| QU-R1 | транзакция сдачи ДЗ откатилась | задания нет |
| QU-R2 | ученик сдал ДЗ | задание `model` |
| QU-R2 | репетитор сдвинул дату экзамена | задание `plan` |
| QU-R3 | ученик дал один ответ | задания нет |
| QU-R5 | `plan` и `model` одного ученика ожидают | одно задание `model` с максимальным `trigger_event_id` |
| QU-R6 | расчёт на версии 6 готов после записи плана версии 7 | план версии 6 не записан |
| QU-R7 | ученика архивировали при ожидающем задании | задание отменено |
| QU-R8 | worker упал во время расчёта | через 120 с задание взял другой экземпляр |
| QU-R9 | два задания одного ученика | выполняются по очереди |
| QU-R10 | во время расчёта пришло новое событие | результат не записан, задание начато заново |
| QU-R12 | пятая ошибка подряд | `failed`, тревога владельцу |
| QU-R14 | событие необработано 16 минут | одна тревога репетитору |
| QU-R16 | worker читает таблицу ПДн | отказ базы |

## 5. Ошибки

| Ситуация | Поведение |
|---|---|
| Задание без события | не создаётся (QU-R1) |
| Устаревшая версия каталога | результат отбрасывается, расчёт повторяется |
| Исчерпаны попытки | `failed`, тревога; повторный запуск оператором |
| Worker остановлен | план устаревает, данные не теряются |
