## 1. Назначение

Описывает, как платформа запускается, обновляется, резервируется, восстанавливается и наблюдается на одном сервере. Здесь только эксплуатационные правила; бизнес-логика живёт в своих модулях.

## 2. Вход и выход

| Вход | Откуда | Контракт |
|---|---|---|
| Образы сервисов с тегами версий | CI | — |
| Подписанный артефакт каталога | CI ([loader](../catalog/loader.md)) | `catalog.schema.json` |
| Секреты | файл на сервере вне git | — |

| Выход | Куда | Контракт |
|---|---|---|
| Работающие окружения prod и staging | пользователи | — |
| Резервные копии | хранилище S3-совместимое, другой провайдер | — |
| Тревоги | служебный чат Telegram ([notifications](notifications.md), NT-R21) | — |
| Журналы без ПДн | файлы сервера | — |

## 3. Правила

### Состав и окружения

- **OP-R1.** Сервисы выпуска 1: `web`, `core` (Go), `content` (загрузчик каталога, разовый контейнер), `db` (PostgreSQL). `worker` и `llm` добавляются в выпусках 2 и 4 (D33).
- **OP-R2.** Prod и staging работают на одном сервере на отдельных поддоменах и отдельных регистрируемых доменах для cookie (D128, D166). У staging свой бот и отдельная сеть Docker; токены служб различаются по окружению и по методам (D170).
- **OP-R3.** Локальная разработка использует тестовый вход без Telegram; он недоступен в prod и staging.

### Секреты

- **OP-R4.** Секреты лежат в файле на сервере вне git (права 600, Compose secrets); копия — в менеджере паролей пользователя; для каждого секрета есть чек-лист замены (D130).
- **OP-R5.** Ключ подписи каталога лежит в секретах CI, публичный ключ — на сервере (D215). Ключ шифрования резервных копий хранится и вне сервера (D111).
- **OP-R6.** В git не попадают секреты и данные учеников; публичный репозиторий содержит код, спецификации и небольшой синтетический каталог (D142).

### Развёртывание

- **OP-R7.** Перед запуском сервисов выполняется разовый шаг миграции; миграции только расширяющие (expand-only); откат = предыдущие теги образов (D127).
- **OP-R8.** Каталог применяется разовым контейнером: сначала на staging, на prod — автоматически через 10 минут после чистой загрузки и проверок staging, если не остановлен командой `hold` (D191, D216).
- **OP-R9.** Каждый выпуск образов имеет тег версии; тег `latest` в prod не используется.

### Резервные копии и восстановление

- **OP-R10.** Архив WAL и ежедневная зашифрованная полная копия уходят в хранилище другого провайдера; восстановление на момент времени возможно; срок хранения 30 дней (D111, D148).
- **OP-R11.** Каждую ночь в одноразовом контейнере выполняется проверка восстановления с пересчётом производных данных из журнала; провал даёт тревогу (D111, D129).
- **OP-R12.** После любого восстановления заново применяется журнал отзыва согласия, чтобы обезличенные данные не вернулись (D168).
- **OP-R13.** Цель восстановления после полной потери сервера — не более 24 часов: стек поднимается скриптом из git и копии с хранилища. Раз в квартал пользователь выполняет настоящее развёртывание на новой машине и записывает время (D143).
- **OP-R14.** Во время простоя ДЗ продолжается через PDF (D143, [web](web.md), WB-R28).

### Наблюдаемость

- **OP-R15.** Журналы структурированные, без ПДн; записи и сообщения не содержат имя, Telegram id и дату рождения: допустимы внутренний id ученика и псевдоним (D38, D168, PV-R27, PV-R28).
- **OP-R16.** Тревоги в служебный чат: сервис недоступен, диск > 80 %, сбой копии или проверки восстановления, неудачная загрузка каталога, неудачный пакет перепроверки, задание в `failed`, «Это не я» (D129, NT-R21). Тревога о лаге пересчёта (старейшее необработанное событие старше 15 минут) уходит **репетитору**, а не в служебный чат ([queue](queue.md), QU-R14, [notifications](notifications.md)); тревога о бюджете LLM идёт в служебный чат; обе — с выпусков 2 и 4 (D129, D148).
- **OP-R17.** Доступность проверяется внешним запросом к странице состояния раз в минуту; тревога при трёх подряд неудачах (D249).
- **OP-R18.** Журналы сервисов хранятся 30 дней, затем удаляются (D250).

### Доступ

- **OP-R19.** Доступ на сервер только по ключам SSH, без пароля; вход под root закрыт; открыты порты 80, 443 и SSH (D251).
- **OP-R20.** Служебные команды (`tutorctl`: создание и восстановление репетитора, возобновление пакета перепроверки, повторный запуск задания очереди в состоянии `failed`: `tutorctl queue retry --job <id>`) запускаются только на сервере (AU-R32, AU-R33, D238).

Файл `ops.examples.yaml` (D133). Ключевые строки:

## 5. Ошибки

| Ситуация | Поведение |
|---|---|
| Миграция упала | сервисы не запускаются, остаются прежние теги, тревога |
| Загрузка каталога не прошла | prod не меняется, тревога |
| Копия не создана | тревога, повтор в следующем окне |
| Хранилище копий недоступно | тревога; WAL копится на диске до 80 % |

## 6. Вне рамок

- Выбор провайдера сервера и хранилища, имена доменов — решает пользователь при развёртывании.
- Рабочая нагрузка и масштабирование: один сервер (D143).
- Обработка очереди и пересчёт — [queue](queue.md).
- Содержимое тревог — [notifications](notifications.md).

## 7. Открытые вопросы

Открытых вопросов нет. По умолчанию, для ревью напарника: D249 (проверка доступности раз в минуту), D250 (журналы 30 дней), D251 (SSH по ключам, порты 80/443/SSH).
