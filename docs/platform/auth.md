# Вход и права

| Поле | Значение |
|---|---|
| Область | platform |
| Владелец (утверждает) | напарник (D144) |
| Реализуют | core (Go), web |
| Выпуск | 1 |
| Решения | D17, D40, D86, D93, D94, D108, D109, D121, D128, D130, D139, D145, D148, D154, D166, D169, D170, D189, D194 |
| Статус | на ревью |

## 1. Назначение

Отвечает на три вопроса: **кто это** (вход через Telegram), **что ему можно** (роли и единая проверка прав) и **как долго он это может** (сеансы). Паролей в выпуске 1 нет (D86). Согласие родителя и обезличивание описывает [privacy](privacy.md); здесь только его влияние на вход.

## 2. Вход и выход

| Вход | Откуда | Контракт |
|---|---|---|
| `POST /auth/telegram` — данные виджета Telegram (`id`, `auth_date`, `hash` и остальные поля) и необязательный `invite_token` | web | `core-api.yaml` |
| `GET /invite/{token}` — страница приглашения | web | `core-api.yaml` |
| Действия репетитора: создать приглашение, отвязать Telegram, перевыпустить приглашение, отозвать сеансы | web | `core-api.yaml` |
| Нажатие «Это я» / «Это не я» в боте | Telegram (webhook с секретным токеном) | `internal-api.yaml` |
| Служебные токены сервисов | `content`, `worker` | `internal-api.yaml` |

| Выход | Куда | Контракт |
|---|---|---|
| Cookie сеанса и cookie устройства | web | — |
| Кто делает запрос (роль, id, владелец) для каждого обработчика | остальные модули `core` | — |
| События `account_bound`, `session_revoked`, `device_confirmed` | журнал, outbox ([notifications](notifications.md)) | `events.schema.json` |

## 3. Правила

### Роли и права

- **AU-R1.** Ролей две: `student` и `tutor`. Родитель — не роль, а тот, кто даёт согласие по ссылке (D108, D93).
- **AU-R2.** У каждого ученика ровно один репетитор-владелец (`owner_tutor_id`); поле есть в схеме с первого дня (D108).
- **AU-R3.** Каждый обработчик перед чтением или записью данных вызывает единую функцию `Authorize(actor, action, object)`. Права зависят только от роли, id актора и владельца объекта (D169).
- **AU-R4.** Репетитор получает доступ только к ученикам с `owner_tutor_id` = его id и к их объектам; ученик — только к своим. Остальное — `403`. Ответ одинаков для чужого и для несуществующего объекта, чтобы не раскрывать существование (AC-R3, AT-R23).
- **AU-R5.** Таблица прав `auth.examples.yaml` перечисляет для каждого маршрута `core-api.yaml` правило доступа. Тест CI обходит все маршруты и падает, если у маршрута нет записи или обработчик не вызывает `Authorize` (D169, D133).
- **AU-R6.** Ключи идемпотентности привязаны к пользователю: чужой ключ не возвращает чужой результат (D169, D121).
- **AU-R7.** Служебные запросы (`content`, `worker`) аутентифицируются отдельными токенами в заголовке `Authorization: Bearer`. Токен привязан к сервису и окружению, хранится в базе в виде хеша и разрешает фиксированный набор методов: `content` — загрузка каталога (`catalog:announce`), перепроверка (`recheck:write`, `recheck:read`) и импорт плана (`plan:import`); `worker.recalc` — чтение представлений и запись в `compute.*`; `worker.agent` — предложения агента. Остальное — `403` (D170).

### Приглашение

- **AU-R8.** Приглашение создаёт только репетитор для своего ученика, и только когда у ученика есть действующее согласие родителя ([privacy](privacy.md), D93). Без согласия — `423 consent_missing`.
- **AU-R9.** Токен приглашения — 256 случайных бит; в базе хранится только его хеш (SHA-256); в логи он не пишется (D145).
- **AU-R10.** Приглашение действует 72 часа и используется один раз. Просроченное или использованное — `410`, сеанс не создаётся (D148). Страница `GET /invite/{token}` ничего не меняет (D145).
- **AU-R11.** У ученика одно действующее приглашение. Перевыпуск отзывает прежнее, привязку Telegram и все сеансы ученика (D154).

### Вход через Telegram

- **AU-R12.** Сервер проверяет данные виджета по спецификации Telegram: строка проверки из полей по алфавиту, `hash = HMAC_SHA256(строка, SHA256(токен бота))`. Несовпадение — `401 login_invalid`.
- **AU-R13.** Данные принимаются, только если `now − auth_date ≤ 300` секунд, иначе `401 login_stale` (D148).
- **AU-R14.** Данные входа передаются только в теле POST, в адрес и в логи не попадают (D94).
- **AU-R15.** Сервер сохраняет **только** `telegram_id`; имя, фамилию, username и фото из ответа Telegram отбрасывает. `telegram_id` хранится в таблице ПДн (D139).
- **AU-R16.** Один `telegram_id` принадлежит ровно одному пользователю (ученику или репетитору). Привязка занятого аккаунта — `409 telegram_already_bound`.
- **AU-R17.** Первый вход ученика по приглашению: проверки AU-R12–R13 → приглашение действует (AU-R10) → согласие действует → `telegram_id` привязывается к ученику, приглашение гасится, создаётся сеанс. Репетитору уходит сообщение «аккаунт привязан» (D93, D102).
- **AU-R18.** Повторный вход без приглашения: по `telegram_id` находится пользователь; ученик со статусом не `active` или без действующего согласия получает `423` (учётная запись закрыта, обратитесь к репетитору).
- **AU-R19.** Виджет запрашивает право бота писать пользователю (`request_access=write`) (D189).
- **AU-R20.** Не более 10 запросов в минуту с одного IP на `/auth/*` и `/invite/*`; сверх — `429` с `Retry-After` (D17, D145, D237).

### Сеансы

- **AU-R21.** Идентификатор сеанса — 256 случайных бит; в базе хранится хеш; создаётся заново при каждом входе и привязке (D166).
- **AU-R22.** Cookie сеанса: имя с префиксом `__Host-`, `Secure`, `HttpOnly`, `SameSite=Lax`, `Path=/`, без `Domain` (D166).
- **AU-R23.** Срок сеанса фиксированный от момента входа: ученик — 90 дней, репетитор — 7 дней; продления нет (D86, D93, D154).
- **AU-R24.** Каждый изменяющий (не GET, HEAD или OPTIONS) запрос обязан нести заголовок `X-CSRF-Token`, совпадающий с токеном сеанса, и `Origin` с нашего домена, иначе `403 csrf` (D166). Запросы до появления сеанса (`POST /auth/telegram`, `POST /auth/dev`, `POST /consent/{token}`) токена не имеют и проверяются только по `Origin`.
- **AU-R25.** Сеанс отзывается автоматически при: отвязке Telegram, перевыпуске приглашения, отзыве согласия, архивации, обезличивании (D109, D145, D154). Репетитор может отозвать все сеансы своего ученика; пользователь может выйти — отзывается текущий сеанс.
- **AU-R26.** У ученика не более 5 действующих сеансов: при шестом входе самый старый отзывается (D237).
- **AU-R27.** Вход ученика с другого устройства допускается без подтверждения (D93 требует подтверждения только для репетитора).

### Устройства репетитора

- **AU-R28.** Устройство определяется cookie `__Host-device` — случайные 128 бит, срок действия 400 дней, выдаётся при первом входе; в базе хранится хеш и дата подтверждения.
- **AU-R29.** Вход репетитора с неизвестным устройством создаёт сеанс в состоянии `pending`: прав у него нет, пока репетитор не нажмёт «Это я» в боте в течение 10 минут; иначе сеанс отклоняется (D93, D148).
- **AU-R30.** Нажатие «Это не я» отзывает все сеансы репетитора, снимает доверие со всех устройств и шлёт тревогу в служебный чат (D129).
- **AU-R31.** Самый первый вход репетитора, у которого нет ни одного подтверждённого устройства, подтверждает устройство автоматически (доверие при первом входе); учётная запись и так создана командой на сервере (D108, D238).

### Учётные записи и восстановление

- **AU-R32.** Первый репетитор создаётся командой на сервере (`tutorctl create --telegram-id <N>`), других способов создать репетитора в выпуске 1 нет (D108).
- **AU-R33.** Если репетитор потерял доступ к Telegram, команда `tutorctl rebind --tutor <id> --telegram-id <N>` меняет привязку, отзывает все сеансы и доверие к устройствам (D154, D238). Команда пишет в журнал событие `tutor_rebound`.
- **AU-R34.** Ученик, не имеющий Telegram, в выпуске 1 не поддерживается (D86); пароль и Mini App — позже.

### Окружения и секреты

- **AU-R35.** Токен бота читается из секрета при старте; ротация токена (замена и перезапуск) делает недействительными входы в момент замены, а действующие сеансы не затрагивает (D94, D130). У staging свой бот и своя пара домен/токен (D128).
- **AU-R36.** Для локальной разработки есть вход без Telegram `POST /auth/dev`; сервер отказывается стартовать, если он включён при окружении не `local` (D128, D166).
- **AU-R37.** В журналы приложения не пишутся данные входа, токены и содержимое cookie (D94, D145).

## 5. Ошибки

| Ситуация | HTTP | Код | Поведение |
|---|---|---|---|
| Неверная подпись входа | 401 | `login_invalid` | — |
| Устаревшие данные входа | 401 | `login_stale` | предложить войти ещё раз |
| Приглашение просрочено или использовано | 410 | `invite_gone` | сообщить ученику связаться с репетитором |
| Нет согласия / учётная запись закрыта | 423 | `consent_missing` / `account_locked` | показать причину |
| Аккаунт Telegram уже привязан | 409 | `telegram_already_bound` | — |
| Нет прав | 403 | `forbidden` | одинаково для чужого и несуществующего |
| Нет CSRF-токена или чужой `Origin` | 403 | `csrf` | — |
| Слишком много запросов | 429 | `rate_limited` | `Retry-After` |
| Устройство репетитора не подтверждено | 401 | `device_pending` | показать «подтвердите в Telegram» |
