# Проверка ответов

| Поле | Значение |
|---|---|
| Область | platform |
| Владелец (утверждает) | напарник (D144) |
| Реализуют | core (Go) |
| Выпуск | 1 |
| Решения | D11, D12, D17, D80, D90, D103, D104, D117, D121, D123, D136, D137, D139, D164, D169, D180, D182, D185 |
| Статус | на ревью |

## 1. Назначение

Принимает ответ ученика на вариант из выдачи, проверяет его **синхронно** по правилам пакета предмета ([answer-rules](../catalog/answer-rules.md)), решает, сколько попыток осталось и что показать ученику, и **в той же транзакции** передаёт результат в журнал попыток ([attempts](attempts.md)). Это самый горячий путь платформы: от него зависят честность баллов и данные для модели знаний.

Сама оценка (нормализация, баллы, ловушки) — чистая функция из [answer-rules](../catalog/answer-rules.md). Этот модуль отвечает за всё вокруг неё: права, лимиты, порядок действий, идемпотентность, видимость результата.

| Выдача, её вид, версия каталога, состояние | `core.*` ([attempts](attempts.md), [homework](../personalization/homework.md)) | — |
| Вариант: ключ, опции, ловушки, формат | `catalog.*` на версии выдачи | `catalog.schema.json` |
| Правила пакета предмета (форматы, баллы) | `catalog.*` | `subject-package.schema.json` |

| Выход | Куда | Контракт |
|---|---|---|
| Ответ ученику (см. ниже) | web | `core-api.yaml` |
| Попытка и наблюдение | журнал попыток ([attempts](attempts.md)) | `events.schema.json` |
| Внутренний вердикт диагностике (не виден клиенту) | модуль диагностики (выпуск 2) | — |

### Ответ ученику

```json
{
  "status": "malformed | accepted | scored",
  "hint": "введите целое число",          // только при malformed
  "item_state": "open | final",
  "attempts_left": 1,
  "verdict": "correct | partial | wrong",  // только при scored
  "points": 2, "max_points": 2,            // только при scored
  "show": { "key": "12", "solution_block": "ct-math:M10.B09" }   // только когда AC-R7 разрешает
}
```

## 3. Правила

### Порядок обработки

- **AC-R1.** Запрос обрабатывается в одной транзакции базы в таком порядке: (1) права, (2) идемпотентность, (3) выдача и вариант существуют и принадлежат этому ученику, (4) выдача открыта, (5) элемент выдачи не закрыт, (6) нормализация ввода, (7) оценка, (8) запись попытки и наблюдения, (9) ответ. Любая ошибка на шагах 1–6 откатывает транзакцию, ничего не записывая.
- **AC-R2.** Запросы к одному элементу выдачи сериализуются блокировкой строки элемента (`SELECT … FOR UPDATE`). Два одновременных ответа на часть В дают попытки с номерами 1 и 2 и никогда две попытки с номером 1 (D121).

### Права

- **AC-R3.** Ответить может только ученик-владелец выдачи; репетитор через этот метод ответ не отправляет. Любое обращение к чужой выдаче — `403` без раскрытия, существует ли объект (D108, D169).

### Идемпотентность

- **AC-R4.** Запрос обязан нести `idempotency_key`. Повтор запроса с тем же ключом и тем же телом возвращает **сохранённый ответ** и не создаёт попытки (D121). Тот же ключ с другим телом — `409 idempotency_conflict`. Ключ привязан к ученику и элементу выдачи и хранится, пока жива выдача.

### Состояние и лимиты

- **AC-R5.** Лимиты попыток на один элемент выдачи, на сервере (D17, D104): часть А — 1; часть В в ДЗ — 2; любой элемент теста (срез, пробник, диагностика, РТ) — 1. Номер попытки растёт только на ответы, прошедшие нормализацию; `malformed` номера не тратит.
- **AC-R6.** Элемент становится `final`, когда ответ верен (`correct`) или попытки исчерпаны. Ответ на `final`-элемент — `409 item_closed`. Ответ после «Сдать» — `409 assignment_closed`; ответ после срока — см. AC-R16.

### Что видит ученик

| Вид выдачи | После ответа | После финальной неудачи | После финальной удачи |
|---|---|---|---|
| ДЗ, часть А | вердикт сразу | ключ и решение сразу | вердикт |
| ДЗ, часть В, попытка 1 неверна | только «неверно», `attempts_left: 1` | — | вердикт |
| ДЗ, часть В, попытка 2 неверна | — | ключ и решение | вердикт |
| Срез, пробник, РТ | только `accepted` | — | — |
| Диагностика | только `accepted` | — | — |

- **AC-R7.** Правила показа — таблица выше (D12, D104). Для выдач вида «тест» (срез, пробник, РТ, диагностика) вердикт, баллы и ключ клиенту до закрытия выдачи не отдаются; итог показывается после «Сдать» ([attempts](attempts.md)).
- **AC-R8.** `partial` показывается как «частично верно» с баллами; ловушка (`trap_id`) ученику не показывается, она нужна для анализа (D11).
- **AC-R9.** Ключ и опции с пометкой «верная» никогда не попадают в ответ, пока AC-R7 не разрешил `show.key` (D17).

### Запись

- **AC-R10.** Попытка записывается с полями: ученик, элемент выдачи, вариант, версия каталога выдачи (D117), сырой ввод, нормализованный ввод, номер попытки, вердикт, баллы, `trap_id`, источник и место (D137), версия правил пакета (`rules_version`, D141), `idempotency_key`. Попытка неизменяема (D35, D182).
- **AC-R11.** Наблюдение для модели знаний (D180) пишется в момент, когда элемент стал `final`: балл первой попытки, итоговый балл, метки ловушек, источник, место. Если элемент не `final`, наблюдение не пишется.
- **AC-R12.** Источник и место определяет сервер по виду выдачи; клиент их не присылает (D137).
- **AC-R13.** Для диагностики в той же транзакции внутренний вердикт передаётся модулю диагностики, который выбирает следующий элемент (D78, D90); клиенту вердикт не возвращается.

### Версия данных

- **AC-R14.** Для проверки используются вариант и ключ **в версии каталога, на которой выдана выдача** (D117). Исправление ключа в более новой версии доходит до уже записанных попыток через перепроверку ([recheck](recheck.md), D123), а не через этот модуль (D226).

### Ограничения скорости и сроки

- **AC-R15.** Не больше 60 запросов в минуту от одного ученика на этот метод; сверх — `429 rate_limited` с заголовком `Retry-After` (D17, D224).
- **AC-R16.** Ответ после срока выдачи принимается и помечается `late: true` в попытке; срок не блокирует ответы (D225).
- **AC-R17.** Таймеров в платформе нет: сервер не ограничивает время ответа ни в одной части ДЗ, а время получения каждого ответа только записывается в попытку. Задания формата ЦТ в рецепте ДЗ — обычные задания формата ЦТ (D227).

## 5. Ошибки

| Ситуация | HTTP | Код | Поведение |
|---|---|---|---|
| Нет прав / чужая выдача | 403 | `forbidden` | ничего не раскрывается |
| Выдача или элемент чужие или не существуют | 403 | `forbidden` | ответ одинаков (AU-R4) |
| Ввод не по формату | 200 | `status: malformed` | подсказка, попытка не создана |
| Элемент закрыт | 409 | `item_closed` | — |
| Выдача сдана | 409 | `assignment_closed` | — |
| Тот же ключ, другое тело | 409 | `idempotency_conflict` | — |
| Слишком много запросов | 429 | `rate_limited` | `Retry-After` |
| Сбой записи | 503 | `unavailable` | транзакция откатывается; повтор с тем же ключом безопасен |
