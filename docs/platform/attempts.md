## 1. Назначение

Хранит **факты** об ученике: выдачи, ответы, сдачу, споры и ручные вердикты. Это неизменяемый журнал в схеме `core.*`, единственный источник истины об ученике (D35); всё остальное (модель знаний, план) из него вычисляется. Модуль отвечает за события жизни выдачи, «Сдать», итог для ученика, споры и каноническое **наблюдение** для модели знаний. Приём и проверку одного ответа описывает [answer-check](answer-check.md).

## 3. Правила

### Журнал

- **AT-R1.** Журнал — только добавление. Роль базы приложения имеет право `INSERT` и `SELECT` на таблицы журнала и не имеет `UPDATE` и `DELETE`; проверка прав — тест CI (D35, D92).
- **AT-R2.** Каждая запись журнала получает `journal_seq` — число из единой монотонной последовательности `core` — и время на сервере. Эта последовательность — «водяной знак» для пересчётов (D89, D156).
- **AT-R3.** Вердикт попытки не хранится в самой попытке, а вычисляется из журнала: оценка при записи, перепроверка и ручной вердикт добавляются отдельными записями `attempt_verdict` с возрастающим `seq`; текущий вердикт — запись с наибольшим `seq` (D22, D138).

### События выдачи

Состояния выдачи: `draft` → `issued` → `submitted`; из `issued` можно перейти в `withdrawn`.

| Событие | Кто | Что записывает |
|---|---|---|
| `assignment_issued` | репетитор | вид выдачи, ученик, предмет, версия каталога, срок, место (`home`/`lesson`), **полный снимок** вариантов и правил (D164) |
| `assignment_withdrawn` | репетитор | причина |
| `assignment_submitted` | ученик | число отвеченных и пропущенных элементов |
| `deadline_changed` | репетитор | новый срок |

- **AT-R4.** Черновик (`draft`) — не факт и в журнал не пишется: его редактирует репетитор (убрать или добавить вариант, срок), пока не выдаст (D195). Первое событие выдачи — `assignment_issued`.
- **AT-R5.** `assignment_issued` содержит полный снимок: id вариантов в порядке выдачи, для каждого — формат ответа, правила оценки, версию правил пакета, источник элемента (`new_topic`, `review`, `ct_format`, `reinforcement`, `unsolved`, `threshold`), и версию каталога выдачи. Дальнейшие версии каталога на выдачу не влияют (D117, D164).
- **AT-R6.** Отозвать выдачу можно только пока в ней нет ни одного ответа ученика; иначе `409 has_answers` (D195).
- **AT-R7.** Срок по умолчанию — начало следующего урока по этому предмету (D107, D146). После выдачи срок можно только продлить (событие `deadline_changed`), сократить нельзя; ответы после срока всё равно принимаются (D225, D231).
- **AT-R8.** В выпуске 1 платформа выдаёт только ДЗ; срезы, пробники и диагностика проходят по PDF, ответы не вносятся (D192), а правила для этих видов выдач включаются с выпуском 2. Источник попытки (`homework`, `checkpoint`, `mock`, `diagnostics`, `rt`) определяется видом выдачи; ученик его не присылает (D137, D182). Место: ДЗ — `home`, срез — `lesson` (срез проходит как этап урока, D153), пробник и РТ — `home`; репетитор может изменить место при выдаче.

### Элементы и попытки

- **AT-R9.** Элемент выдачи — один вариант. Состояние элемента `open` / `final` (см. [answer-check](answer-check.md), AC-R6). Элемент без ответов на момент «Сдать» получает отметку `skipped`.
- **AT-R10.** Попытка (`attempt_recorded`) содержит поля из AC-R10 и ссылку на выдачу; попытки без выдачи (кроме импорта РТ) не бывают (D182).
- **AT-R11.** **Итог элемента** вычисляется по порядку попыток: элемент заканчивается на первой попытке, чей текущий вердикт `correct`; последующие попытки в итог не входят. Если все попытки не `correct` — итог берётся по лучшему вердикту; баллы первой попытки и итоговые баллы сохраняются отдельно (D45, D180).

### «Сдать»

- **AT-R12.** Сдать выдачу может только ученик-владелец. Сдача окончательна; после неё ответы не принимаются (`409 assignment_closed`), оспорить и нажать «не понял» можно (D104).
- **AT-R13.** Если на момент «Сдать» есть элементы без ответа, сервер отвечает `409 unanswered_confirmation_required` с числом оставшихся (`left: N`); повтор запроса с `confirm_unanswered: true` сдаёт выдачу (D104).
- **AT-R14.** «Сдать» идемпотентно по ключу запроса (D121): повтор возвращает сохранённый итог и не создаёт второго `assignment_submitted`.
- **AT-R15.** После `assignment_submitted` в одной транзакции: все `open`-элементы получают `skipped` и становятся `final`; для всех элементов формируются наблюдения (AT-R20); в outbox ставится сообщение репетитору «ученик сдал ДЗ: результат и ссылка» (D102); с выпуска 2 ставится задание пересчёта «модель и план» (D87, D156, D175). Кроме того, при «Сдать» для элементов, чьи ключи исправлялись в версии новее версии выдачи, выполняется перепроверка (RC-R18, [recheck](recheck.md)).
- **AT-R16.** Итог для ученика: по каждому элементу результат, для неудач — ключ и решение, кнопка «не понял»; для выдач вида «тест» (срез, пробник, РТ, диагностика) вердикты и баллы показываются **только теперь** (D104).
- **AT-R17.** Нажатие «не понял» (`did_not_understand`) на элемент сданной выдачи добавляет вариант в список «разобрать на уроке» репетитора; повторное нажатие на тот же элемент ничего не меняет (D104).

### Споры и ручной вердикт

- **AT-R18.** Ученик может оспорить итог элемента сданной выдачи кнопкой «оспорить» (D22): событие `dispute_opened`: причина из списка (`key_wrong` — ключ неверен, `statement_error` — ошибка в условии, `equivalent_answer` — мой ответ эквивалентен, `other` — другое) и необязательный текст до 300 символов. Текст видит только репетитор, и он проходит фильтр личных данных (D139, D232). Один открытый спор на элемент.
- **AT-R19.** Репетитор решает спор одним из двух способов (D138): (а) исправляет ключ в каталоге обычным путём PR, после загрузки перепроверка обновляет вердикты всех попыток варианта ([recheck](recheck.md)), а спор закрывается ссылкой на `correction_id`; (б) создаёт `manual_verdict` для одной попытки: вердикт, баллы и причина. Ручной вердикт — факт (D175): он добавляет запись `attempt_verdict` и порождает новое наблюдение; прежний вердикт остаётся в журнале. Ученик видит новый итог в кабинете; Telegram-сообщения ему об этом не приходит, а репетитору приходит одно сообщение со списком изменённых ДЗ (D176, D233).

### Наблюдение для модели знаний

- **AT-R20.** Когда элемент стал `final` (ответ верный, попытки исчерпаны или выдача сдана), записывается `observation` версии 1: ученик, тип задания (по варианту), подвариант, вариант, источник, место, балл первой попытки, итоговый балл, максимум, метки ловушек, признак `skipped`, признак `late`, версия каталога, версия правил (D180).
- **AT-R21.** Перепроверка или ручной вердикт, меняющие итог элемента, добавляют новое наблюдение с тем же элементом и возрастающей `revision`; потребитель берёт последнюю ревизию (D123, D180).
- **AT-R22.** Наблюдение пишет `core` (Go); Python его только читает через представление без ПДн, личные данные в наблюдение не попадают (D92, D139).

### Чтение

- **AT-R23.** Ученик видит только свои выдачи и попытки, репетитор — выдачи и попытки своих учеников; остальное — `403` (D108, D169).
- **AT-R24.** Репетитор видит сырые попытки ученика **до** «Сдать» (D81); это чтение, события оно не создаёт.
- **AT-R25.** При обезличивании (D109) журнал не меняется: удаляется только запись ПДн и связь псевдонима; попытки остаются под внутренним id.

## 5. Ошибки

| Ситуация | HTTP | Код | Поведение |
|---|---|---|---|
| Отзыв выдачи с ответами | 409 | `has_answers` | — |
| Сдать без подтверждения при пропусках | 409 | `unanswered_confirmation_required` | в ответе `left` |
| Ответ после «Сдать» | 409 | `assignment_closed` | — |
| Второй открытый спор на элемент | 409 | `dispute_exists` | — |
| Срок короче текущего | 409 | `deadline_shorter` | — |
| Текст спора длиннее 300 или с личными данными | 422 | `dispute_text_invalid` | — |
| Спор по не сданной выдаче | 409 | `not_submitted` | — |
| Чужая выдача или попытка | 403 | `forbidden` | — |
| Сбой записи | 503 | `unavailable` | откат; повтор с тем же ключом безопасен |
