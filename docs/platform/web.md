| Поле | Значение |
|---|---|
| Область | platform |
| Владелец (утверждает) | оба: экраны и тексты — пользователь, реализация — напарник (D144) |
| Реализуют | web (React + TypeScript, PWA); PDF рендерит core (Go) |
| Выпуск | 1 |
| Решения | D38, D40, D43, D81, D82, D104, D105, D106, D121, D135, D136, D140, D145, D166, D167, D189, D192, D195, D228, D232, D246–D248, D265, D266 |
| Статус | на ревью |

## 1. Назначение

Описывает, **что видят и делают** репетитор и ученик в выпуске 1: экраны, состав каждого экрана, поведение при ошибках и плохой сети, вывод блоков и PDF. Бизнес-правила (проверка, права, сроки) живут в своих модулях; здесь только то, как они показываются.

Общие требования (D40): сначала телефон (mobile first), приложение-страница (PWA) без нативных приложений, один адрес для всех. Внешний вид (цвета, шрифты) в эту спецификацию не входит.

## 2. Вход и выход

| Вход | Откуда | Контракт |
|---|---|---|
| Данные для экранов | HTTP API `core` | `core-api.yaml` |
| Тексты блоков и виджеты | `catalog.*` через API | `catalog.schema.json` |
| Действия пользователя | клавиатура, касания | — |

| Выход | Куда | Контракт |
|---|---|---|
| Запросы к API с cookie сеанса и `X-CSRF-Token` | `core` | `core-api.yaml` |
| PDF-файлы | пользователь | — |

## 3. Правила

### Общие

- **WB-R1.** Верстка рассчитана на экран от 360 пикселей по ширине; все действия доступны без горизонтальной прокрутки. Зона касания кнопок не меньше 44 × 44 пикселя (D40).
- **WB-R2.** Весь интерфейс на русском языке. Время показывается в часовом поясе Europe/Minsk; сервер хранит UTC.
- **WB-R3.** Каждый запрос, изменяющий данные в сеансе, несёт `X-CSRF-Token` и идёт с нашего домена; запросы до входа (вход, страница согласия) проверяются только по `Origin` (D166, AU-R24).
- **WB-R4.** В клиент никогда не попадают ключи ответов, пометки «верная опция» и решения, пока API их не вернул по правилам [answer-check](answer-check.md) (AC-R9). Репетитор видит ключи только на экранах подготовки (WB-R22).
- **WB-R5.** Приложение работает как PWA: устанавливается на главный экран, кеширует оболочку и открытые страницы ДЗ (D40).
- **WB-R6.** Коды ошибок API показываются понятным текстом из таблицы на странице «Ошибки» этой спецификации; технические сообщения не показываются.

### Вход (ученик и репетитор)

- **WB-R7.** Страница приглашения показывает кнопку «Войти через Telegram» (виджет с запросом права писать, D189), краткое объяснение и ничего не меняет при открытии (D145).
- **WB-R8.** Для ошибок входа есть отдельные экраны: приглашение просрочено или использовано; нет согласия; учётная запись закрыта (архив, отзыв); ссылка согласия недействительна или просрочена; устройство репетитора ждёт подтверждения в Telegram («подтвердите вход в боте»).
- **WB-R9.** Страница согласия показывает действующий текст и одну кнопку (дать, отозвать или отменить отзыв в течение 7 дней); репетитор отменяет отзыв кнопкой в карточке ученика (PV-R18); состояние меняет только нажатие (D145, PV-R11).

### Ученик: экраны

| Экран | Состав |
|---|---|
| Главная | список выдач: открытые, сданные; у каждой предмет, срок, сколько отвечено; ближайший урок |
| Урок | конспект урока из блоков (ученику — после проведённого урока, D265); кнопка «Скачать PDF»; если блоки не готовы, урок из файла урока видит только репетитор, ученику ничего не показывается (D140, D266) |
| Выдача (ДЗ) | список задач с состоянием: не отвечено, верно, неверно, частично, закрыто; кнопка «Сдать» |
| Задача | условие, поле ответа по формату (WB-R10…R14), оставшиеся попытки, результат по правилам AC-R7 |
| Итог | после «Сдать»: результат по задачам, решения неудач, кнопки «не понял» и «оспорить» (D104, D232) |
| Профиль | имя, выход, кнопка «выйти на всех устройствах» |

- **WB-R10.** `ct.choice1` — переключатели с вариантами 1–5; выбор отправляется кнопкой «Ответить».
- **WB-R11.** `ct.choiceN` — флажки с вариантами 1–5; число верных не показывается, если условие задания его не называет.
- **WB-R12.** `ct.match` — для каждой буквы список цифр; пока выбраны не все буквы, кнопка «Ответить» недоступна.
- **WB-R13.** `ct.digits` — поле, принимающее только цифры, цифровая клавиатура; повтор цифры блокируется с подсказкой.
- **WB-R14.** `ct.integer` — числовое поле с цифровой клавиатурой и отдельной кнопкой «−»; запятая и точка блокируются с подсказкой «введите целое число». Ввод не по формату не отправляется и попыткой не считается (D136, AR-R8).
- **WB-R15.** После ответа показывается результат ровно по таблице видимости [answer-check](answer-check.md) (AC-R7): в части В после первой ошибки — только «неверно» и «осталась 1 попытка». Ответ «принят» без вердикта относится к выдачам вида срез, пробник, диагностика: в выпуске 1 они проходят по PDF и в платформе не выдаются (D192), экран ответа на них появится с выпуском 2.
- **WB-R16.** «Сдать» показывает подтверждение с числом неотвеченных задач (`left: N`) (AT-R13); после сдачи ответы нельзя менять.
- **WB-R17.** «Не понял» и «оспорить» доступны только на экране итога. Спор: выбор причины из списка и необязательный текст до 300 символов (D232).

### Ученик: плохая сеть

- **WB-R18.** Каждый ответ уходит с ключом идемпотентности, созданным на устройстве (D121). Если связи нет, ответ остаётся в очереди устройства со статусом «не отправлено», и отправляется, когда связь вернётся; повторная отправка дубля не создаёт.
- **WB-R19.** Пока ответ не отправлен, вторая попытка по этой задаче недоступна, а для задач части В показывается «ждём связь».
- **WB-R20.** Очередь неотправленных ответов хранится на устройстве, не содержит личных данных и очищается после отправки или выхода.

### Репетитор: экраны

| Экран | Состав |
|---|---|
| Ученики | список учеников с показателями: следующий урок, ДЗ ждёт просмотра/сдано/просрочено, открытые споры, «не доставлено», предупреждения |
| Ученик | карточка: расписание, план по урокам (статусы), выдачи, сырые попытки (D81), список «разобрать на уроке», согласие и приглашение, архив |
| Урок | состав урока (этапы, блоки, практика), снимок, две отметки (D82), перенос, отмена, пропуск (D105, D106, D268) |
| Подготовка | задачи урока, ДЗ или среза с ключами и решениями до урока (D38) |
| Просмотр ДЗ | собранный черновик: убрать или добавить вариант, срок, «выдать» (D195) |
| Итоги ДЗ | результаты по задачам, споры, ручной вердикт, отчёт перепроверки (D138, RC-R20) |
| Новый ученик | имя, дата рождения, ссылка согласия, приглашение |
| Сеансы | устройства, сеансы, «отозвать все» |

- **WB-R21.** Экран «Ученики» — стартовый для репетитора; сортировка по ближайшему уроку.
- **WB-R22.** Экран «Подготовка» — единственное место, где репетитор видит ключи и решения до того, как их увидел ученик; ключ и решение скрыты за кнопкой «показать», чтобы случайно не показать их с экрана.
- **WB-R23.** Выдать ДЗ можно только из просмотра черновика кнопкой «Выдать»; после выдачи кнопка заменяется на «Отозвать» (пока нет ответов) (D195, AT-R6).
- **WB-R24.** Репетитор может открыть «Итоги ДЗ» ученика до его «Сдать»: сырые попытки показаны, но помечены «ещё не сдано» (D81, AT-R24).
- **WB-R25.** Предупреждения (`variants_needed`, `plan_does_not_fit`, `consent_outdated`) показываются плашкой вверху карточки ученика и на экране «Ученики» (NT-R17).

### Блоки, формулы, PDF

- **WB-R26.** Блоки выводятся из Markdown с формулами LaTeX через KaTeX с `trust: false`; сырой HTML не допускается; SVG проходит очистку; на странице действует строгая политика CSP без встроенных скриптов (D135, D167).
- **WB-R27.** Виджеты выводятся компонентами библиотеки по паре `{widget, params}`; у каждого виджета есть статичная картинка для печати (D43, D135).
- **WB-R28.** PDF формирует сервер из той же вёрстки: ровно три вида: конспект урока, листок ДЗ (условия без ключей), бланки среза, пробника и диагностики (D40, D192, D248).
- **WB-R29.** В PDF нет ключей и решений; PDF репетитора с ключами в выпуске 1 нет (D248).

### Состояния и ошибки

- **WB-R30.** У каждого экрана есть три состояния: загрузка, пусто, ошибка. Ошибка сети показывает «Нет связи» и кнопку «Повторить».
- **WB-R31.** Завершённые действия подтверждаются на экране (выдано, сдано, отозвано); сообщение об ошибке стоит рядом с полем или кнопкой, вызвавшими её.

## 6. Вне рамок

- Внешний вид: цвета, шрифты, анимации.
- Карта освоения и прогноз, кабинет родителя, нативные приложения (D40).
- Редактор каталога в браузере (D4): каталог правится только через PR.
- Правила проверки, права, сроки — их модули.
