## 1. Сервисы

                  ┌──────────────┐
 ученик/репетитор │  web (React) │  Telegram-бот ◀──── outbox
                  └──────┬───────┘        ▲
                         │ HTTPS          │
                  ┌──────▼────────────────┴───┐
                  │  core (Go)                 │  все транзакции ученика
                  │  вход · права · попытки ·  │  пишет: core.*

                  │  ДЗ · диагностика · outbox │
                  └──────┬──────────▲──────────┘

## 2. Данные: схемы и правило одного писателя

У каждой таблицы ровно один писатель (D92). Читать могут многие.

| Схема | Пишет | Что лежит | Читает |
|---|---|---|---|
| `catalog.*` | только CI-загрузчик | темы, элементы, типы, подварианты, варианты, опции, блоки, тесты, появления, пакет предмета, версии и карта переноса | core, worker |
| `core.*` | только Go | ученики, ПДн (отдельная таблица), согласия, сеансы входа, расписание, уроки и снимки, отметки, выдачи, журнал попыток, импорт РТ, вердикты, правки, статичный план, outbox | worker — через представления без ПДн |
| `compute.*` | только worker | состояние знаний, прогноз, план (неизменяемые снимки) | Go — через представления, только SELECT |
| `queue.*` | вставка — функцией (Go и worker); аренда и статус — только worker | задания пересчёта и агента | — |

Факты и расчёты разделены по схеме CQRS: Go пишет факты, worker строит из них производные. Производные можно пересчитать из журнала в любой момент (D35, D178).

Личные данные хранятся только в таблице ПДн. Всё остальное ссылается на внутренний id ученика, а наружу — на псевдоним (D165, D168).

## 3. Основные потоки

### Ответ ученика в ДЗ (выпуск 1)
1. `web` отправляет ответ с ключом идемпотентности (D121).
2. `core` в одной транзакции: проверка по правилам пакета предмета (D80, D103), запись неизменяемой попытки, каноническое наблюдение (D180).
3. Ответ показывается сразу. В части В после первой ошибки — только «неверно» (D104).

### Сдача ДЗ
1. «Сдать» → событие `homework_submitted` (D104).
2. Outbox: сообщение репетитору (D102).
3. С выпуска 2 — задание пересчёта в `queue.*` (D87, D156).

### Отметка урока и сборка ДЗ
1. Репетитор ставит две отметки: теория и практика (D82).
2. `core` переносит необъяснённое в следующий урок (D96), собирает ДЗ по рецепту урока: один список задач (D146, D229, D230).
3. Репетитор просматривает, правит и выдаёт ДЗ (D195: можно убрать или добавить вариант, изменить срок). Выдача — неизменяемое событие со снимком (D164).

### Изменение каталога
1. PR в приватный репозиторий каталога (D142) → CI: схема, правила ответа, проверка ключей (D119, D150, D151).
2. CI собирает подписанный артефакт, одноразовый контейнер загружает его сначала в staging, потом по команде в prod (D191).
3. Загрузчик сообщает `core` о новой версии, `core` пишет событие и задания ученикам (D173). Исправленный ключ запускает перепроверку (D123).

### Пересчёт (выпуск 2+)
1. `recalc` арендует задание (D125, D148), берёт блокировку ученика (D89).
2. Читает журнал через представления, считает, пишет снимок плана только при fast-forward (D89, D124).
3. При первом запуске проигрывает журнал каждого ученика с нуля (D178).

## 4. Границы доверия

| Граница | Правило | Решения |
|---|---|---|
| Браузер → core | вход через Telegram, cookie `__Host-`, SameSite=Lax, CSRF, единая проверка прав | D86, D94, D166, D169 |
| Ответы до попытки | ключи никогда не уходят во фронтенд, лимит попыток на сервере | D17 |
| Контент → браузер | санитайзер, KaTeX без trust, CSP | D167 |
| worker → core | только внутренний API с сервисным токеном; к ПДн доступа нет | D92, D170 |
| Всё → LLM | только псевдоним, внешние тексты помечены как данные | D17, D170 |
| Репозитории | код публичный, каталог с ключами и заметки — приватные | D142 |

## 5. Окружения и эксплуатация

- **prod** и **staging** на одном сервере, но staging на отдельном домене и в отдельной сети; у staging свой тестовый бот. Локальная разработка — со входом без Telegram (D128, D166).
- Миграции только расширяющие, запускаются одноразовым шагом до старта сервисов (D127).
- Бэкапы: архив WAL и ежедневная копия у другого провайдера, хранятся 30 дней, ночная проверка восстановления (D111, D148). При полной потере сервера подъём на новой машине за ≤ 24 ч, репетиция раз в квартал (D143).
- Тревоги — в служебный Telegram-чат (D129, D177).

## 6. Контракты

Все границы описаны в [`contracts/`](contracts/) (D97):
- OpenAPI — HTTP-API `core`, включая внутренний;
- JSON Schema — события очереди, формат каталога, представления `compute.*` (D157).

Типы для Go, Python и TypeScript генерируются из контрактов, ручные дубли запрещены. Совпадение кода со схемами проверяет CI.
