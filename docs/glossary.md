# Глоссарий

> Каждое слово определено один раз (D77, D112, D200). Спецификации, код, тесты и промпты агентов пользуются только этими значениями. Если слова нет в глоссарии, его сначала добавляют сюда, а уже потом используют.
>
> В старых решениях (D1–D71) слова иногда значат другое; как их читать, сказано в последнем разделе.

## Каталог: что знать

| Термин | Значение | Не путать с |
|---|---|---|
| **каталог** | Общий для всех учеников набор: темы, элементы, типы заданий, подварианты, варианты, блоки. Хранится в git (приватный репозиторий) и загружается в `catalog.*`. Один на пакет предмета. | модель знаний (это про ученика) |
| **пакет предмета** | Данные предмета поверх ядра: каталог, форматы ответа, правила баллов и нормализации ввода, guess/slip, число попыток, ценность типа для цели. Первый пакет — ЦТ. | пакет оптимизатора (D68), пакет контекста агента (D15) |
| **тема** | Крупный раздел программы, например «Тригонометрия». Код в плане — `M14`, в каталоге — постоянный id. | |
| **элемент** | Знание внутри темы, например Т2 «основное тождество» (D70). На элементы ссылаются предпосылки. | пункт спецификации, часть ответа |
| **пункт спецификации** | Пункт спецификации теста РИКЗ (например, п. 4.2). | элемент |
| **тип задания** | Что проверяется (D3): один основной элемент, остальные — предпосылки (D149). | вариант, позиция |
| **подвариант** | Структурная разновидность типа (что дано, что найти, формулировка). Варианты внутри подварианта отличаются только числами. Постоянный id. | вариант |
| **вариант** | Конкретный экземпляр задачи с числами, ключом и постоянным id. | тест, опция |
| **шаблон** | Параметрическое описание подварианта; CI разворачивает его в варианты (выпуск 2). Сервер код шаблонов не исполняет. | |
| **опция** | Вариант ответа в части А. | вариант |
| **ловушка** | Заранее известный неверный ответ (опция части А, типичный неверный ответ части В, неверная часть составного ответа) с id причины ошибки. | |
| **часть ответа** | Пара в В1 или цифра в В2 — элемент составного ответа (D23). | элемент |
| **позиция** | Место в тесте: А1…А10, В1…В20. Позиция — свойство появления, а не типа. | тип задания |
| **тест** | Целый экзаменационный вариант ЦТ, ЦЭ или РТ. Сущность каталога. | вариант (это задача), программный тест |
| **сессия** | Экзаменационная сессия: год и этап (ЦТ, ЦЭ, РТ-n), в ней выходят один или несколько тестов. | сеанс входа, сессия агента |
| **появление** | Факт: тип задания встретился в тесте такой-то сессии на такой-то позиции. Из появлений считаются частоты (D187). | |
| **страховка** | Типы с частотой 0 (есть в спецификации, но не встречались в 2023–2026). Под них отдельная квота часов, только уровень «база» (D69). | |
| **блок** | Кусок библиотеки: теория, правило, разобранный пример, типичная ошибка, виджет. Постоянный id. | этап урока, серия |
| **профиль** | Описание программы для составителя: источники и роль каждого (граница, названия, порядок, задания). | |

## Ученик и обучение

| Термин | Значение | Не путать с |
|---|---|---|
| **файл урока** (в документах также «L-файл») | Исходный файл одного урока плана в `ct-2027`: `math/plan/L01.md … L31.md`, `physics/plan/L01.md … L32.md` (L — от lesson). Содержит цель, ход по минутам, задачи, домашнюю работу и заметки для генерации. Не путать с шаблоном урока в каталоге. | урок, шаблон урока |
| **урок** | Занятие ученика с репетитором в конкретную дату по одному предмету. | |
| **этап урока** | Часть урока по времени (например, «8–13 мин: разбор ДЗ»). Содержит блоки и варианты практики. | блок |
| **снимок урока** | Неизменяемая запись опубликованного урока: этапы, блоки, варианты практики, версия каталога (D120, D164). | |
| **отметки урока** | Две отметки репетитора: последний объяснённый блок теории и последняя решённая задача практики (D82). | |
| **выдача** | Набор вариантов, выданный ученику. Вид выдачи (ДЗ, срез, пробник, диагностика) задаёт число попыток, показ ответов и вес (D104). | |
| **ДЗ** | Выдача вида «домашняя работа», собранная по рецепту урока (D146). | |
| **рецепт ДЗ** | Описание, из чего собирается ДЗ урока: список серий задач с источником (новая тема, повторение, формат ЦТ), числом задач и сложностью, плюс бюджет часов. ДЗ одно, без дней и без частей (D146, D229, D230). | |
| **серия** | Подряд идущие варианты одного типа (например, 5 задач А3). | блок |
| **срез** | Контрольная выдача по расписанию из резерва невиданных вариантов; одна попытка, результат в конце, полный вес. Проходит как этап урока (D153). | пробник |
| **пробник** | Полный тест в формате ЦТ в финальной фазе; одна попытка, результат в конце, полный вес. Импортированная РТ имеет тот же вес. | срез |
| **диагностика** | Адаптивный входной тест (бинарный поиск по ветвям графа, D90). Выпуск 2. | |
| **попытка** | Неизменяемая запись журнала: ученик, вариант, выдача, версия каталога, сырой ответ, источник и место. Верно или неверно — вычисляется (D22, D182). | |
| **наблюдение** | Каноническое представление попытки для модели знаний, его пишет Go (D180). | попытка |
| **журнал** | Неизменяемая последовательность фактов и ограничений по ученику (D35, D87). | |
| **факт** | Событие журнала о том, что произошло: сдача ДЗ, отметка урока, попытка теста, перепроверка, ручной вердикт (D87, D175). | ограничение |
| **ограничение** | Событие журнала, меняющее только условия плана: правка репетитора, цель, дата, бюджет, расписание, отмена урока, новая версия каталога (D87, D175). | факт |

## Модель знаний и план

| Термин | Значение | Не путать с |
|---|---|---|
| **модель знаний** | Оценка того, что из каталога уже знает конкретный ученик: вероятность p по каждому типу. Выпуск 3. | каталог |
| **уровень освоения** | «база» или «автоматизм» по типу; автоматизм никогда не раньше базы (D71). | уровень сложности блока |
| **оптимизатор** | Алгоритм: каталог + модель знаний + цель + часы → план (D5, D68). Выпуск 2. | |
| **план** | Что учить и в каком порядке. В выпуске 1 — статичный план из `ct-2027` (D100), с выпуска 2 — неизменяемые снимки в `compute.*` (D157). | |
| **горизонт** | Уроки 1–2 заморожены; до +42 дней — поблочно; дальше — недельные вехи (D148). | |

## Люди, доступ, данные

| Термин | Значение | Не путать с |
|---|---|---|
| **репетитор** | Роль: ведёт своих учеников. У ученика ровно один репетитор-владелец (D108). | |
| **ученик** | Роль: решает выдачи. | |
| **ПДн** | Личные данные: имя, Telegram id, дата рождения, контакты родителя, школа. Хранятся в отдельной таблице (D139, D194). | |
| **псевдоним** | Случайный короткий код ученика для всего, что уходит наружу (агент, заметки, логи). Хранится рядом с ПДн и удаляется вместе с ними (D165). | внутренний id |
| **согласие** | Согласие родителя на обработку данных: дата, версия текста, способ (D93, D145). | |
| **сеанс входа** | Сессия в браузере после входа через Telegram (cookie): ученик — 90 дней, репетитор — 7 дней (D86, D93). | сессия |

## Разработка

| Термин | Значение | Не путать с |
|---|---|---|
| **таблица примеров** | Таблица «вход → ожидаемый выход» в спецификации модуля, YAML рядом со спецификацией; из неё генерируются тесты (D72, D133). | |
| **программный тест** | Автотест кода. В документах всегда «программный тест» или просто «тест кода». | тест (экзамен) |
| **сессия агента** | Отдельный запуск ИИ, который пишет тесты или код (D72). | сессия |
| **бриф** | Задание для агента, собранное скриптом из шапки спецификации модуля (D155). | |
| **задание очереди** | Фоновая задача для worker в `queue.*` (D156). | задача |
| **задача** | Только слово интерфейса для ученика. В документах — «вариант». | задание очереди |
