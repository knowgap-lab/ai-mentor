# Платформа подготовки: журнал решений (интервью 2026-11-01)

Контекст: репетитор готовит учеников к ЦТ/ЦЭ (Беларусь): 30 заданий — А1–А10 выбор из 5 вариантов (в А6/А10 бывает несколько верных), В1 соответствие (частичный балл), В2 набор цифр (частичный балл), В3–В20 целое число; максимум 50 первичных → 100 тестовых. Сейчас несколько учеников (сведения об учениках в репозиторий не вносятся, D142). Репозиторий /home/stranger/projects/tutoring: ct-2027/ (граф 82 темы graph/graph.json, карточки тем */topics/*.md, планы уроков */plan/L*.md, research/*.md, tools/build.py), 7-grade/, docs/architecture.md (СТАРОЕ предложение: Astro + статический сайт + Supabase — заменяется). Кода платформы нет.

Новые требования пользователя (после первого раунда):
- Это реальный бизнес репетитора И тема курсовой: архитектура должна обобщаться на другие области (например, изучение языка программирования), а не только ЦТ.
- Пользователь интересуется TDD при разработке с ИИ: сначала тесты, потом код.

| D68 | Ценность предпосылок | Оптимизатор оценивает пакеты «тип + неизученные предпосылки»: выгода = прирост ожидаемых баллов / (часы типа + часы неизученных предпосылок); жадно берёт лучший пакет; выбранные предпосылки становятся оплаченными, остальные пакеты пересчитываются. Ценность предпосылки приходит только от типов, вошедших в план при цели ученика. Тесты: (1) предпосылка только для невыбранных типов в план не попадает; (2) тема никогда не раньше предпосылок; (3) общая предпосылка оплачивается один раз; (4) повышение цели только добавляет темы. |
| D69 | Квота страховки | Отдельный бюджет часов на типы с частотой 0 (в спецификации, но не в тестах 2023–2026): только уровень «база», ближе к концу курса, ближайшие к уже освоенному. Динамическая: базовая доля плавно растёт с целью (~1 % при 60 → ~8 % при 100); отстаёт от цели → квота 0; опережает с запасом → часть свободных часов в страховку; ручная настройка репетитора важнее автоматики. Тесты: прогноз ниже цели → 0; цель 100 > цель 65 при прочих равных; ручное значение побеждает. |
| D70 | Глубина темы | Тема делится на элементы знания (пример: тригонометрия Т1 определения и значения, Т2 тождество, Т3 приведение, Т4 сложение/двойной угол, Т5 сумма↔произведение, понижение степени). Предпосылки ссылаются на элемент, а не на тему. Правило дробления: части темы с разными наборами зависимых типов — разные элементы; с одинаковыми — сливаются. Проверки CI: каждая предпосылка указывает на элемент. Три измерения состояния: глубина (элементы), уровень освоения (база/автоматизм), ценность (от выбранных типов, D68). Миграция 82 тем = дробление на элементы. |
| D71 | Порядок уровней освоения | Подтверждено пользователем как обязательное. Тесты: (1) «автоматизм» типа никогда не раньше его «базы»; (2) при малом бюджете план в основном из «баз»; (3) при равной цене автоматизм раньше у более частого типа; (4) автоматизм для типов из квоты страховки не планируется. В кабинете репетитора у типа два состояния: «база освоена» и «автоматизм». |
