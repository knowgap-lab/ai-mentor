# R4-09 Переход от выпуска 1 к выпуску 2

1. **[critical] Когда появляется compute.*, у импортированного статичного плана нет ни владельца, ни таблицы** (D100, D126, D92, D76, A7, D127, D124). Рекомендация: в выпуске 1 план лежит в core.* как неизменяемый импорт; worker при первом запуске записывает его в compute.* как версию плана 0, а таблица в core остаётся эталоном только для чтения.
2. **[critical] Не определено, как оптимизатор «адаптирует» статичный план** (D100, D5, D8, D68, A7, D105, D106, D120). Рекомендация: опубликованные и замороженные уроки, а также ручные переносы становятся ограничениями; дальше статичный план служит стартовой точкой, и оптимизатор отходит от него только при выигрыше выше порога гистерезиса.
3. **[high] У статичного плана как эталона нет замороженной копии и метрики сравнения** (D100, D99, D30, D35). Рекомендация: неизменяемый снимок импорта (хеш файлов) и отчёт для репетитора — расхождения по порядку тем, часам и датам; это мониторинг, а не тест.
4. **[high] Нет начальной загрузки для первого запуска worker на данных выпуска 1** (D126, D89, D91, D92, D124, D125, D127). Рекомендация: команда bootstrap ставит одно задание «initial» на ученика; пока пересчёта не было, Go показывает импортированный план с пометкой «не пересчитан»; оповещения о задержке — только для новых событий.
5. **[high] Диагностика для уже занимающегося ученика** (D95, D90, D41, D27, D71, D81). Рекомендация: пройденные темы засеваются отметками репетитора; диагностика идёт только по непройденным веткам и только на невиданных вариантах.
6. **[medium] Шаблоны рядом с готовыми вариантами; переход перепроверки из синхронного режима в очередь** (D101, D27, D37, D39, A6, D115, D126, D123, D87, D92). Рекомендация: готовым вариантам при загрузке назначается подвариант; CI отбрасывает сгенерированные дубли; пул и резерв считаются по типу. Перепроверка остаётся в Go, в очередь он ставит только пересчёт.
