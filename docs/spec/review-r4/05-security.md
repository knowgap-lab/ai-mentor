# R4-05 Безопасность и приватность (повторная проверка)

1. **[critical] Из-за публичного репозитория S8 больше не работает: ключи ответов и каталог видны всем** (S8, D17, D98, D101, D118, D119). Рекомендация: каталог с ключами хранить в отдельном приватном репозитории, в публичном держать только код и синтетический демо-каталог.
2. **[high] Заметки репетитора и данные об ученике оседают в истории git, которую нельзя обезличить** (D84, D98, D139, D109, D110, S8). Квазиидентификаторы (Минск, ЦТ-2027, целевой балл) уже есть в документах. Рекомендация: заметки хранить в core.*, в PR оставлять только id; данные о текущем ученике убрать из публичного репозитория.
3. **[high] Та же ссылка отзывает согласие, и удаление происходит сразу и необратимо; токены передаются в URL** (D93, D109, D110, D86, D94, D17). Рекомендация: действие только по POST после нажатия кнопки; отзыв подтверждает репетитор, анонимизация откладывается на 7 дней; токены хранить хешированными, в логи не писать, ограничить число попыток.
4. **[high] Для cookie-сессий не заданы правила CSRF и SameSite, id сессии не меняется; staging — соседний поддомен** (D86, D93, D94, D128, D17). Рекомендация: префикс __Host-, SameSite=Lax, проверка Origin и CSRF-токен на всех POST, новый id сессии при входе и привязке; staging на отдельном домене.
5. **[high] Блоки Markdown + LaTeX + SVG из ИИ-контента — путь для XSS** (D135, D43, D83, D113, D98, D120). Рекомендация: CI отклоняет сырой HTML и опасные элементы SVG; KaTeX с trust:false; санитайзер при рендере; строгий CSP.
6. **[high] ПДн за пределами таблицы ПДн; восстановление из бэкапа отменяет обезличивание** (D109, D111, D102, D129, D91, D94, D139). Рекомендация: сообщения и логи ссылаются только на псевдоним; журнал отзывов повторно применяется после любого восстановления; бэкапы хранятся 30 дней.
7. **[medium] D108 проверяет только владельца-репетитора; доступ ученика и косвенные пути не покрыты** (D108, D121, D122, D138, D92, D123, D79). Рекомендация: единый слой авторизации в Go по (роль, tutor_id, student_id); ключ идемпотентности привязан к пользователю; таблица прав, из которой генерируются тесты.
8. **[medium] Внутренние API без аутентификации; контекст агента открыт для внедрения инструкций** (D92, D123, D91, D128, D130, D79, D88, D113). Рекомендация: у каждого сервиса и окружения свой токен с узким набором методов; prod и staging в разных Docker-сетях; внешние тексты в промпте помечены как данные.
