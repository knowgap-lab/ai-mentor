# R3-14 Составитель, eval, соответствие курсовой

1. **[high] Эталон собирается одним из сравниваемых подходов** (D83, D98, I1, Q3). Рекомендация: отдельный отложенный набор, размеченный репетитором вручную без скилла (2 сессии ≈ 60 заданий + элементы спецификации одного предмета). (Пользователь ранее отложил этот вопрос до catalog/eval.)
2. **[high] Тема курсовой против D83: локальные модели, «проверка», срок** (D83, D32, D85, D28, Q3, A3). Скилл Claude работает только на Claude, поэтому локальную модель на агентной стороне не проверить. Рекомендация: агент = свободный цикл tool-calling на тех же инструментах через общий адаптер (локальная модель и Claude), скилл — только верхняя планка; «проверка» = критик и поиск внесённых в каталог ошибок; фаза 2 начинается после выпуска 1, веха — весна 2027.
3. **[high] Что должен содержать PR скилла, чтобы его принял CI** (D98, D97, D85, D56, D27, D4, I1). Рекомендация: у каждого элемента, темы и типа цитата, task_rules, предпосылки на уровне элементов; скилл ставит временные ключи, а вечные id выдаёт CI при слиянии; профиль лежит рядом с каталогом.
4. **[medium] Правило сопоставления в eval и набор метрик** (D83, D98, I1). Рекомендация: эмбеддинги + ИИ-судья на спорных парах + выборочная ручная проверка; метрики — точность и полнота, каппа, подтверждённые предпосылки, ноль циклов, время, вызовы модели, вопросы репетитору; 3+ прогона.
5. **[medium] Заметки репетитора: схема, где хранятся, утечка в eval** (D84, D98, D92, D83, S8). Рекомендация: YAML рядом с изменением в репозитории каталога, фильтр ПДн в CI; заметки по отложенному эталонному набору не используются для настройки.
