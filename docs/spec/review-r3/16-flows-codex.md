# R3-16 Сквозные сценарии (Codex, gpt-5.6-terra)

Пройдено 8 сценариев. Без пробелов оказался только №3 (отметка урока и перенос).

1. **[critical] Исправление ключа: нет контракта перепроверки, совместимого с владением core.*** (сценарий 7, loader → attempts; D57, D75, D76, D92, D87). Рекомендация: внутренний API Go с correction_id и состоянием пакета, перепроверка возобновляется после сбоя.
2. **[critical] Версия каталога не защищает от устаревшего плана** (сценарий 6, loader → plan; D57, D87, D89, D21). Рекомендация: catalog_version передаётся в событие, во вход и в результат плана.
3. **[major] Брошенная диагностика не оформлена как событие и триггер** (сценарий 4, diagnostics → queue; D78, D87, D90). Рекомендация: события diagnostic_abandoned / diagnostic_resumed с версией сессии.
4. **[major] Повтор HTTP-запроса тратит вторую попытку или даёт двойной Submit** (сценарий 2, web → attempts; D11, D17, D80, D87). Рекомендация: Idempotency-Key для ответа и для Submit. (Совпадает с R3-09 №2.)
5. **[major] У импорта бланка РТ нет уникального ключа** (сценарий 5, web → attempts; D88, D53, D89). Рекомендация: уникальный ключ «ученик + сдача + вариант», идемпотентный upsert.
6. **[major] Не определён переход от свежих P к очереди агента** (сценарий 8, knowledge-model → agent; D14, D76, D91, D15). Рекомендация: после commit пересчёта создаётся событие AgentTrigger с ревизиями журнала и плана.
7. **[major] Публикации урока не хватает контракта снимка блоков** (сценарий 1, schema → conspect; D43, D21, D85, D97). Рекомендация: при атомарной публикации сохраняется снимок: id блоков, их порядок и catalog_version.
