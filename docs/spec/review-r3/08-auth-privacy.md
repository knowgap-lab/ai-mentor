# R3-08 Вход, роли, личные данные

1. **[critical] Нет матрицы прав и фиксированного набора ролей** (D17, D13, D40, D74, D93, D79, S5). Рекомендация: роли student и tutor; у ученика один владелец-репетитор, репетитор видит только своих; admin и передачу учеников делать позже, но поле владельца в схеме есть сразу.
2. **[critical] Отзыв согласия и уход ученика: удаление, обезличивание, архив** (D18, D93, D17, D92, S6, D84, D86). Рекомендация: уход = архив (вход заблокирован, сессии отозваны, данные хранятся); отзыв согласия = удаление строки ПДн и Telegram id, попытки остаются под псевдонимом; ПДн уходят из бэкапов по сроку хранения копий.
3. **[high] Как убедиться, что согласие дал родитель, и когда его спрашивать снова** (D93, D17, D28, D86). Рекомендация: родитель входит через Telegram, его id хранится как ПДн вместе с версией текста; согласие запрашивается заново при новой версии текста и при 18-летии; текущий ученик тоже проходит процедуру.
4. **[high] Жизненный цикл сессий и восстановление доступа репетитора** (D86, D93, D94, S5). Рекомендация: фиксированный срок от входа; отвязка, перевыпуск приглашения, отзыв согласия и архив отзывают все сессии; репетитор восстанавливает доступ CLI-командой на сервере.
5. **[medium] Что такое псевдоним и какие поля считаются ПДн** (D17, D15, D92, D98, D86, D38). Рекомендация: псевдоним — постоянный случайный короткий код; ПДн = имя, Telegram id, контакты родителя, школа; фильтр заменяет имена из таблицы ПДн и блокирует сохранение при телефонах или @username.
