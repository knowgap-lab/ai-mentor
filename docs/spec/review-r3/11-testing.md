# R3-11 Стратегия тестирования

1. **[critical] Для заморозки тестов не определены границы, способ контроля и исключения; S1 (сливает репетитор) против D99 (сливает владелец)** (D30, D72, D99, D97, S1). Рекомендация: пути замороженных файлов перечислены в CODEOWNERS; при N > 0 в PR с кодом CI блокирует слияние; ошибочный тест исправляется отдельным PR с одобрения владельца.
2. **[high] Нет канала, формата и записи для спорных случаев, которые поднимает ИИ** (D72, D73, D74, D77). Рекомендация: блок «Открытый вопрос Q-n» в спецификации модуля блокирует тесты этого правила; ответ владельца становится строкой таблицы с ID правила, существенный ответ — ещё и записью D-n.
3. **[high] Уровни тестов, исполнение таблиц на двух языках, среда интеграционных тестов** (D30, D89, D90, D92, D97, D98). Рекомендация: таблицы в YAML/CSV рядом со спецификацией, тесты Go и Python генерируются из них; интеграционные тесты и D89 — на настоящей PostgreSQL в контейнере с точками синхронизации; данные только синтетические.
4. **[medium] Откуда берутся ожидаемые значения для эталонов оптимизатора и шаблонов** (D30, D68, D71, D80, D99, S2). Рекомендация: маленькие сценарии (3–6 типов) сравнивают точный план, посчитанный вручную; большие проверяют только инварианты и сверяются с независимым решателем.
5. **[medium] Сборка брифов агентов и разделение сессий тестов и кода** (D72, D73, D77, S1). Рекомендация: бриф собирается скриптом из шапки модуля (правила, таблицы, контракты, глоссарий, разрешённые пути); тестовые пути закрыты на запись для сессии кода хуком или CODEOWNERS.
