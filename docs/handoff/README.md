# Журнал передачи состояния (handoff)

Нужен, чтобы **любой** агент или человек мог понять, на каком мы этапе, что делали последним и что дальше, не читая переписку и не завися от чьей-то памяти. Принцип как у журнала предзаписи в базах данных (WAL): сначала записываем намерение, потом результат; запись только добавляется, прошлое не правится.

## Устройство

| Что | Где | Назначение |
|---|---|---|
| Сводка | [LATEST.md](LATEST.md) | одна страница: текущее состояние, что в работе, что дальше. Агент обновляет её в конце сессии |
| Записи | [entries/](entries/) | по файлу на каждое событие «начал» и «закончил». Только добавляются |
| Шаблон | [TEMPLATE.md](TEMPLATE.md) | форма записи |

Один файл на запись, а не один общий: когда два агента или два человека работают одновременно, в git не возникает конфликтов слияния.

## Имя записи

`entries/YYYY-MM-DD-HHMM-<агент>-<слаг>.md`, например `2026-11-08-2139-claude-loader-spec.md`.
`<агент>` — кто пишет (`claude`, `codex`, `grok`, `human-<имя>`). `<слаг>` — короткое описание латиницей. Время локальное, часы и минуты; по имени файла записи сортируются в порядке времени.

## Правила

1. **Перед работой** создайте запись со статусом `начал`: что беретесь сделать, какие файлы затронете, на какую запись опираетесь.
2. **После работы** создайте новую запись со статусом `закончил`, `прервано` или `заблокировано`. В ней: что сделано, что не сделано, следующий шаг, открытые вопросы. На запись `начал` ссылайтесь, саму её не правьте.
3. Затем обновите [LATEST.md](LATEST.md). Это единственный файл журнала, который перезаписывается.
4. Записи содержат состояние и указатели («см. D216», «см. loader.md §3»), а не аргументы. Решения и их причины — в [журнале решений](../decisions/log.md); если в работе принято решение, сначала запишите его там.
5. Ссылайтесь на файлы и номера правил, а не пересказывайте их.
6. Не кладите в записи секреты, сведения об учениках, куски переписки (репозиторий публичный, D142).
7. Если вы нашли запись `начал` без пары `закончил` и ей больше суток, считайте сессию оборванной: проверьте `git log` и `git status`, допишите запись `прервано` от своего имени и продолжайте.
8. Не меняйте старые записи. Ошибку исправляйте новой записью, которая на неё ссылается.

## Формат записи

Запись начинается с блока в начале файла (frontmatter), затем разделы по шаблону. Поля блока:

| Поле | Значения |
|---|---|
| `status` | `начал` · `закончил` · `прервано` · `заблокировано` |
| `agent` | кто пишет |
| `date` | `YYYY-MM-DD HH:MM` |
| `task` | коротко, что за задача |
| `refs` | список файлов, решений и записей, на которые опирается |
| `touches` | список файлов, которые запись меняет или собирается менять |

## Проверка

Перед коммитом записи убедитесь:
- у файла верное имя по шаблону выше;
- заполнены все поля блока;
- в записи `закончил` есть раздел «Дальше»;
- `LATEST.md` обновлён и ссылается на эту запись.

(Скрипт проверки появится вместе с остальной инфраструктурой; пока проверяйте руками.)
