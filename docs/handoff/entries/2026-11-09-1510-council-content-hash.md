# Консилиум: хеш сущности и контейнер артефакта

**Вопрос.** LD-R3 не называет алгоритм `content_hash`. Контейнер в тексте спецификации уже `catalog-N.tar.zst`. Подпись minisign в этот пакет не входит.

**Позиции.**
- Консерватор: SHA-256 компактного UTF-8 JSON (ключи по кодам Unicode, без пробелов) и tar+zstd из стандартной библиотеки. Особое мнение не требовалось.
- Прагматик: то же. Загрузчик на Go хеширует байты файла сущности в архиве и не собирает JSON заново.
- Критик: SHA-256 от RFC 8785, чтобы числа `1` и `1.0` не расходились. Особое мнение.

**Решение.** Принято мнение двоих: компактный JSON и стандартный zstd. Запись D275. Особое мнение критика записано в той же строке. До первой ревизии в базе выбор обратим.

**Проверки.** Исходники прочитаны членами консилиума. Код артефакта ещё не написан.
