# MVP ИИ-ментора: проект

Статус: черновик 1, 2026-10-20. Основа — `README.md` (концепция A «карта пробелов»
+ C «кабинет репетитора», режим 1). Пилот — один ученик, готовящийся к ЦТ-2027 по
математике и физике (данные: репозиторий `tutoring/ct-2027`).

## 1. Что MVP должен доказать

MVP — не продукт, а эксперимент. Он отвечает на четыре вопроса; каждому — метрика
и порог «работает / не работает». Через 6 недель живого использования решаем, что
развивать.

| # | Гипотеза | Метрика | Порог успеха |
|---|---|---|---|
| H1 | Оценка освоения по узлам меняет решения репетитора | доля недель, когда план следующего урока изменён по отчёту системы; доля узлов, где оценка системы и мнение репетитора расходятся, и кто оказался прав по следующему тесту | ≥ 1 изменение в 2 недели; система права в ≥ половине расхождений |
| H2 | Сбор данных почти бесплатен для репетитора | минуты в неделю, которые репетитор тратит на ввод | ≤ 10 мин/нед |
| H3 | Адаптивная домашка эффективнее статичной | точность по узлу через 1–2 недели после темы; сравнение с узлами, которые шли по статичному плану (до запуска MVP) | рост точности на повторных задачах ≥ 15 п.п. |
| H4 | Ученик реально занимается в системе | дней с занятием в неделю, задач в неделю | ≥ 4 дней, ≥ 60 задач |

Если H2 или H4 провалены — дальнейшее не имеет смысла, чиним их первыми.

## 2. Что входит и что нет

**Входит:** граф тем и банк типов задач (импорт из `ct-2027`), генерация задач из
шаблонов с вычисленным ответом, проверка итогового ответа, модель освоения по узлам,
выбор задач для ежедневной практики, веб-тренажёр для ученика, Telegram-бот для
репетитора (ввод данных и отчёты) и ученика (напоминания), объяснение ошибок через LLM.

**Не входит (сознательно):** проверка хода решения и фото тетради (концепция B),
построение графа из произвольной программы (будет вторым flow), несколько учеников и
роли родителя, оплата, сравнение конвейера и агента (это исследовательская часть
курсовой — делается на данных, которые соберёт MVP), DKT.

## 3. Принципы (из README, обязательны)

1. **Ядро не знает предмета и экзамена.** Граф, освоение, выбор задач, проверка
   ответа работают с абстрактными узлами и типами задач. ЦТ — это «слой экзамена»
   (позиции А1–В20, формат ответа) и контент, подключаемые как данные.
2. **Решает код, LLM объясняет.** Правильность ответа, оценка освоения, выбор задач —
   детерминированный код. LLM пишет объяснения и (офлайн) черновики шаблонов задач.
3. **Прозрачность.** Любое число в отчёте раскрывается до ответов, из которых оно
   получилось.
4. **Данные появляются сами.** Ученик решает в тренажёре — ответы пишутся
   автоматически. Репетитор только подтверждает или поправляет.

## 4. Пользователи и потоки

### Ученик (веб-тренажёр)
1. Открывает ссылку из бота → видит «сегодняшнюю сессию»: 15–25 задач, ~45–60 минут.
2. Решает в тетради, вводит итоговый ответ (число, дробь, вариант 1–5, `А1Б3В4`).
3. Сразу видит верно/неверно. При ошибке: правильный ответ + короткое объяснение
   (LLM, опирается на карточку темы) + кнопка «посмотреть теорию» (раздел карточки).
4. В конце — итог сессии и карта прогресса по темам.

### Репетитор (Telegram)
- `/lesson` после урока: «прошли M12, тест 2/3, путает ОДЗ» — текстом или голосом.
  Бот превращает это в структурированные события (LLM) и **показывает на
  подтверждение** перед записью.
- `/report` (и автоматически перед уроком): освоение по темам урока и повторения,
  что выросло/упало, 3 рекомендации к уроку, расхождения «система vs ваша отметка».
- `/plan`: какой следующий урок по плану, есть ли смысл сдвинуть.

### Ученик (Telegram)
- Ежедневное напоминание со ссылкой на сессию, итог дня, серия дней подряд.

## 5. Доменная модель

```text
Subject(id, title)                         # math, physics
Node(id, subject, title, tier, prereqs[],  # из front matter карточек
     exam_positions[], card_ref)
TaskType(id, node_id, bank_no, level 1..3, # строка банка в карточке
         exam_position?, answer_format, template_id?)
Template(id, task_type_id, code, status)   # параметрический генератор, проверен человеком
TaskInstance(id, template_id, params, text, answer, seed)
Attempt(id, student, instance, given, correct, duration_s, source, at)
Mastery(student, node, p, n_attempts, last_attempt_at)   # производное, пересчитывается
PlanLesson(subject, n, week, kind, topics[], review[])   # из plan/LNN.md
TutorEvent(id, kind, payload, confirmed, at)             # отметки репетитора
```

`Mastery` — не источник правды, а кэш: всегда можно пересчитать из `Attempt` и
`TutorEvent`. Это важно для прозрачности и для экспериментов с моделями освоения.

## 6. Ключевые технические решения

### 6.1 Откуда берутся задачи — параметрические шаблоны (ключевое)

Каждый тип задачи из банка карточки становится **шаблоном**: маленькой функцией
Python, которая генерирует параметры, текст условия и вычисляет ответ.

```python
@template("M02.bank.7", answer="fraction")
def add_unlike_fractions(rng):
    a, b = rng.choice(DENOMS, 2, replace=False)
    p, q = rng.integers(1, a), rng.integers(1, b)
    return f"Вычислите {p}/{a} + {q}/{b}", Fraction(p, a) + Fraction(q, b)
```

- Шаблоны пишет LLM **офлайн** по строке банка и примеру, человек (или второй прогон)
  проверяет. Во время работы LLM задачи не генерирует → ответы всегда верные,
  задачи бесплатные и мгновенные.
- Ограничения параметров («числа чистые», «ответ части В — целое») — в коде шаблона,
  проверяются тестом на 1000 случайных генераций.
- Задачи, которые плохо параметризуются (геометрия с рисунком, качественные вопросы
  физики), в MVP берутся как **фиксированные экземпляры** из карточек и РЕШУ ЦТ.

Почему не LLM на лету: каждая генерация требует проверки, стоит денег и времени, а
ошибка в ответе подрывает доверие ученика сильнее, чем что-либо ещё.

### 6.2 Проверка ответа

Нормализация ввода (запятая/точка, `1/2`, `0,5`, `-3`, пробелы) → сравнение по
формату: целое — точно; дробь/десятичное — через `Fraction`/SymPy с допуском формата;
выражение — `sympy.simplify(a - b) == 0`; вариант А — номер; соответствие — строка.
Частичный балл как на ЦТ (В1, В2) — поддерживается форматом.

### 6.3 Модель освоения — BKT с заданными параметрами

- По узлу: P(L0), P(T), P(G), P(S). Параметры **не обучаются** на одном ученике (данных
  мало), а задаются по уровню задачи и узла: например P(G)=0,2 для варианта из 5,
  P(G)=0,02 для числового ответа; P(S)=0,1; P(T)=0,15; P(L0) из отметки репетитора
  или диагностики (0,1 по умолчанию).
- Задача уровня 3 обновляет и пререквизиты узла с коэффициентом 0,3 (облегчённый
  FIRe из README).
- Забывание: эффективное освоение `p·exp(−Δt/τ)`, τ ≈ 21 день, — источник
  интервального повторения.
- Узел «освоен» при p ≥ 0,85 в двух разных днях.
- Реализация — своя (~80 строк), чтобы было объяснимо; pyBKT — для курсовой, когда
  данных станет больше и параметры можно будет оценивать.

### 6.4 Выбор задач на сессию

Детерминированная политика (воспроизводима по seed, логируется):

1. Кандидаты: узлы, которые уже введены уроками по плану, и у которых все
   пререквизиты с p ≥ 0,6.
2. Корзины: 50 % — узлы текущего урока; 30 % — повторение (эффективное p упало
   ниже 0,7 или давно не было); 20 % — смешанные задачи формата ЦТ по пройденному.
3. Внутри узла — уровень задачи, при котором прогноз успеха 0,7–0,85
   («граница понимания»).
4. Ограничения: не больше 6 задач одного узла подряд, перемешивание (interleaving)
   в корзинах 2–3.

### 6.5 LLM — только за интерфейсом

`LLMClient.complete(prompt, schema)` с двумя реализациями: облачная (сейчас) и
Ollama (для курсовой). Использования: (а) объяснение ошибки — промпт содержит
условие, ответ ученика, верный ответ и раздел «Типичные ошибки» карточки;
(б) разбор заметки репетитора в события — строгая JSON-схема, подтверждение
человеком; (в) офлайн — черновики шаблонов. Все промпты и ответы логируются: это
готовые данные для исследования «конвейер vs агент».

```text
ct-2027 (git) ──импорт──▶ content/ (узлы, типы, шаблоны, карточки)

   Telegram-бот ◀──┐            ▼
   (aiogram)       ├──▶ FastAPI ──▶ core/ (граф, BKT, выбор, проверка) ──▶ PostgreSQL
   Веб-тренажёр ◀──┘     │
   (React + TS)          └──▶ LLMClient (облако → Ollama)
```

| Часть | Выбор | Отклонение от README |

| Ядро | Python 3.12, чистые функции, без фреймворков | — |
| API | FastAPI | — |
| БД | PostgreSQL (pgvector не нужен в MVP: RAG заменён прямой ссылкой на раздел карточки) | pgvector позже |

## 8. Этапы реализации (каждый — отдельный промпт для Cursor)

| Этап | Результат | Критерий приёмки |
|---|---|---|
| S0 | Репозиторий, Docker Compose, схема БД, импорт узлов/типов/плана из `ct-2027` | импорт 82 узлов, 63 уроков и всех строк банков; тесты зелёные |
| S1 | Движок шаблонов и проверки ответов; шаблоны для узлов первых 4 недель (M01–M05, M08, P01–P05) | на каждый шаблон 1000 генераций без ошибок ограничений; ответы сверены с банком |
| S2 | BKT, забывание, политика выбора + симулятор «виртуального ученика» | на симуляции освоение сходится к истинному; выбор соблюдает пререквизиты и доли корзин |
| S3 | Веб-тренажёр: сессия, ввод ответа, мгновенная проверка, карта прогресса | сессия проходится с телефона; все попытки в БД |
| S4 | Telegram-бот: напоминания, `/lesson` с подтверждением, `/report` | отчёт строится из реальных попыток; заметка → события только после подтверждения |
| S5 | Объяснения ошибок через LLM, логирование промптов | объяснение опирается на карточку; лог пригоден для анализа |
| S6 | Деплой, бэкапы, метрики H1–H4 | ученик работает с телефона по ссылке; дашборд метрик |

S0–S2 — без интерфейса, полностью проверяемы тестами. Ученик подключается после S3.

## 9. Риски MVP

| Риск | Ответ |
|---|---|
| Ученик не будет заходить (H4) | ежедневное напоминание, короткие сессии, серия дней, репетитор видит активность |
| Шаблоны не покрывают геометрию и качественную физику | фиксированные экземпляры из карточек и РЕШУ ЦТ; честно меряем долю покрытия |
| BKT с заданными параметрами врёт | прозрачность (разворот до попыток) + сравнение с отметками репетитора (H1) |
| Перегрузка разработкой | S0–S2 сначала, интерфейсы минимальные, всё лишнее — в «не входит» |
| Данные несовершеннолетнего | в облачную LLM уходят только условие и ответы, без имени; согласие родителей |
