## 1. Коротко

- **Ядро:** граф тем с пререквизитами. У каждого ученика или студента есть оценка освоения **от 0 до 1 по каждому узлу**. Сверху работает LLM-ментор, который объясняет пробелы и замечания понятным языком.
- **Режим 1 (продукт / бизнес):** подготовка к экзаменам по математике и физике (ЦЭ/ЦТ в Беларуси, ОГЭ/ЕГЭ в России) через частных репетиторов и самостоятельно.
- **Режим 2 (рекомендуется для курсовой):** преподаватель задаёт ключевые темы курса (например, C++). Сервис строит граф и путь обучения, ведёт освоение каждого студента и **проверяет код только по критериям уже освоенных тем**.
- **Исследование:** сравнение конвейерного и агентного подходов на локальных моделях по качеству, времени и надёжности, плюс оценка уверенности (в том числе Jev).
- **Главный принцип:** решают детерминированные проверки (граф, правила, тесты, SymPy, clang-tidy), а LLM только объясняет.

## 2. Что означает тема

| Слово | Смысл |
|---|---|
| ИИ-ментор | Не просто «правильно / неправильно», а объяснение: что не так, почему и как исправить |
| Проверка учебных программ | Неоднозначно, см. трактовки ниже |
| Локальные языковые модели | Открытые LLM на своём компьютере или сервере (Ollama, llama.cpp, vLLM): данные не уходят наружу, нет платы за API |
| Конвейерный подход | Жёсткая последовательность шагов, заданная заранее |
| Агентный подход | Модель сама решает, какие инструменты вызвать и в каком порядке |

**Трактовки «учебной программы»:**

1. Учебная программа дисциплины как документ вуза (в РФ — РПД, рабочая программа дисциплины; в РБ — «учебная программа по учебной дисциплине»). Проверка на соответствие стандарту, сходимость часов, связь компетенций с темами.
2. Программа подготовки ученика к экзамену: темы, порядок, часы. Проверка по графу и спецификации экзамена.
3. Курс программирования: **учебная программа курса** (список тем → граф) **и программы студентов** (код). Название темы покрывает этот вариант в обоих смыслах.

Рекомендация: для курсовой взять **трактовку 3** (данные и сервер кафедры рядом), а трактовку 2 развивать как продукт. Движок у них общий.

## 3. Почему не «просто чат с нейросетью»

Сценарий «объясни задачу по шагам» уже закрыт: ChatGPT Study Mode и Gemini Guided Learning (2025). Ещё один «умный репетитор в чате» проиграет.

Чего у чата нет и что составляет ценность продукта:

1. **Память об ученике** на месяцы: что знает, где ошибается, как растёт.
2. **Проверенная база:** официальные спецификации, задания с ответами, материалы курса, а не «по памяти».
3. **Детерминированная проверка:** вычисления через SymPy, код через тесты, линтеры и анализ AST.
4. **Измерение:** освоение по темам, прогноз результата, прогресс в цифрах.
5. **Несколько ролей:** ученик, репетитор или преподаватель, родитель.
6. **Действие во времени:** план → задания → проверка → перестройка плана.

## 4. Концепции продукта

Итог мозгового штурма.

| Концепция | Суть | Нельзя заменить чатом? | Статус |
|---|---|---|---|
| **A. Карта пробелов** | Граф + адаптивная диагностика, поиск первопричины пробела, задания «на границе понимания» | Да | **Выбрана как ядро** |
| **B. Рукописные решения** | Фото тетради → распознавание формул (LaTeX) → пошаговая проверка через SymPy | Да | Развитие после A |
| **C. Кабинет репетитора** | Программа под ученика, домашки, отчёты; данные собираются автоматически | Да | Развитие после A |
| **D. Навигатор к цели** | Любая цель → программа из официальных источников | Частично | Позже: высокая конкуренция |
| **E. Маркетплейс программ** | Репетиторы делятся проверенными программами | — | Экосистема, когда будут пользователи |
| **F. Тренажёр формата ЦЭ/ЦТ** | Прогноз балла | Частично | Как функция, не как продукт |
| **G. Режим преподавателя (программирование)** | Темы курса → граф → путь → проверка кода по уровню | Да | **Рекомендован для курсовой** |

### Принципы, которые выросли из обсуждения

- **Узкий вход, универсальный движок.** «Для всех» сразу не работает: универсальный инструмент уже есть, это ChatGPT. Универсальным делается движок (граф + освоение + ментор), а на рынок заходят через узкий сценарий.
- **Платформа и экосистема — результат, а не старт.** Порядок: инструмент → регулярные пользователи → платформа.
- **Преподавателю и репетитору лень вводить данные.** Они должны появляться сами: решения в приложении, фото тетради, 30-секундное голосовое после урока, которое LLM превращает в отметки на графе. Человек только подтверждает или поправляет.
- **Прозрачность, а не чёрный ящик.** Урок Knewton: больше 180 млн долларов инвестиций и провал из-за непрозрачных алгоритмов.
- **Самообучение работает только у мотивированных.** Нужен слой мотивации: цель (экзамен), прогноз балла, прогресс, родитель как наблюдатель.

## 5. Ядро: граф знаний и модель освоения

### Граф

- **Узел** — тема или навык (например, «тригонометрия: формулы приведения», «C++: RAII и умные указатели»).
- **Ребро «пререквизит»** — что нужно знать до этой темы.
- **Граф «поглощения»** (идея Math Academy) — какие старые темы автоматически повторяются при решении задачи по новой. Нужен для интервального повторения: решение продвинутой задачи засчитывается и её пререквизитам с понижающим коэффициентом (алгоритм FIRe).
- **Слои экзаменов:** граф предмета один, а задания ЦЭ/ЦТ, ОГЭ и ЕГЭ привязаны к его узлам. Новый экзамен — это новый слой, а не новый продукт.
- **Построение:** LLM генерирует черновик графа из программы или списка тем, человек проверяет. Пять лет назад студенту-одиночке это было недоступно.

### Освоение 0–1 по узлу

- Вручную оценки не ставятся. Значение обновляется по фактам: ответы, тесты, сданный код, квизы.
- **Курсовая: BKT** (Bayesian Knowledge Tracing). Четыре понятных параметра: начальное знание, вероятность научиться, угадать, ошибиться. После каждого ответа значение пересчитывается по формуле Байеса. Работает на малых данных, легко объясняется. Пример порога: Plario считает тему освоенной при уверенности от 0,9.
- **Диплом: DKT** (Deep Knowledge Tracing): рекуррентная сеть по истории ответов. Это и есть «своя нейросеть».

### Задания «на границе понимания»

1. Граф определяет **доступные** темы: все пререквизиты освоены.
2. Модель освоения предсказывает **вероятность успеха** на конкретном задании.
3. Политика выбора берёт задания из доступных тем с вероятностью успеха в целевом коридоре: не слишком легко и не слишком трудно. Стартовая гипотеза для экспериментов — около 85% успеха («правило 85%», исследование 2019 года).
4. Плюс интервальное повторение, чтобы освоенное не забывалось.

## 6. Режим 1: подготовка к экзаменам (математика и физика)

**Для кого:** частные репетиторы (сам автор — репетитор по математике и физике, 9 и 11 класс), ученики, которые готовятся сами, родители.

**Что делает ИИ-ментор («проверка учебной программы» в буквальном смысле):**

- получает программу подготовки (темы, порядок, часы) и результаты диагностики ученика;
- сверяет её с графом и спецификацией экзамена: в спецификации ЦЭ/ЦТ прямо сказано, что содержание соответствует учебным программам по предмету;
- находит непокрытые темы, нарушенный порядок пререквизитов, перекосы по часам и темы, на которые уходит время, хотя на экзамене они почти не встречаются;
- выдаёт объяснимый отчёт: что не так, почему, что изменить.

**Почему ниша:** под ЦЭ/ЦТ адаптивных и ИИ-продуктов не найдено. Математика и физика в одном графе дают реальное отличие, потому что физика постоянно упирается в математические пробелы (тригонометрия, векторы, уравнения).

**Вход:** сначала на себе и знакомых репетиторах, модель B2B2C через репетитора, оплата в BYN через ЕРИП. Слой ОГЭ/ЕГЭ — вторым этапом.

## 7. Режим 2: курс программирования (режим преподавателя)

### Сценарий

1. **Старт курса.** Преподаватель вводит 10–15 ключевых тем (например, C++). LLM разворачивает их в граф с пререквизитами, преподаватель одобряет одной кнопкой.
2. **Путь обучения.** По графу сервис строит, что и в каком порядке изучать, дополнительные материалы и практику.
3. **Освоение 0–1 по узлу** для каждого студента, обновляется автоматически (BKT).
4. **Проверка кода по уровню.** К узлам привязаны детерминированные правила: проверки clang-tidy и анализ синтаксического дерева. **Правило активно, только если тема освоена.**
5. **Код как доказательство.** Правильное использование темы в коде повышает её освоение без отдельных тестов.
6. **Сигнал «не по уровню».** Резкий скачок выше текущего уровня (освоение шаблонов 0,2 и вдруг идеальные variadic templates) — повод попросить студента объяснить решение. Это не доказательство списывания.

### Пример

```text
Узел «RAII и умные указатели»: освоение 0.85 → правило активно
Код студента:  int* a = new int[n]; ... delete[] a;
Ментор:        «RAII ты уже прошёл — здесь лучше std::vector<int> a(n), память освободится сама»

Тот же код при освоении 0.1 → без штрафа, тема ещё впереди
```

### Почему именно так

- Готового продукта, который проверяет код по освоенному **конкретным студентом**, не найдено ни на Западе, ни в РФ/РБ.
- Решают правила, LLM только объясняет. CodeStylist (Purdue, 2026): правильность замечаний LLM 60,7%. Codaveri: 9% замечаний оказались галлюцинациями.
- Научная опора: **KCGen-KT** (2025) извлекает компоненты знаний из AST решений и отслеживает освоение (AUC 0,821).
- Вход в вуз: не заменять Контест или Moodle, а сделать **надстройку** (импорт задач и вердиктов, сверху граф, освоение и ментор). В БГУ прямо писали, что ни одна из используемых систем не покрывает всех потребностей.

## 8. Конвейер vs агент: исследовательская часть

**Главный вопрос:** какой подход точнее находит проблемы (в программе подготовки или в коде) на локальной модели и какой ценой по времени.

| | Конвейер | Агент |
|---|---|---|
| Как работает | Фиксированные шаги: разбор → сопоставление с графом → проверки → отчёт | Модель сама вызывает инструменты (граф, база знаний, тесты, данные ученика) |
| Плюсы | Предсказуемый, быстрый, легко отлаживать, хорош на слабых моделях | Гибкий, может перепроверить себя и сделать шаг, которого нет в схеме |
| Минусы | Жёсткий | Медленнее, ошибается в планировании, маленьким моделям тяжелее |
| Реализация | Чистый Python | LangGraph или собственный harness |

Тезис для проверки: в работе ASEE 2026 сделан вывод, что хорошую масштабируемую обратную связь даёт конвейер с жёстко заданным процессом, а не просто «сила» модели. Можно подтвердить или опровергнуть его на своих данных.

**Данные:** реальные программы подготовки и лабораторные плюс образцы с намеренно внесёнными ошибками. Для каждого — эталонный список проблем, размеченный вручную. Цель — 30–50 образцов.

**Метрики:** точность и полнота найденных проблем, доля ложных замечаний, время ответа, число вызовов модели.

**Сравнения:**
- конвейер против агента;
- 2–3 локальные модели разного размера;
- опционально облачная модель как верхняя планка.

**Оценка уверенности** (насколько хорошо разные сигналы ловят ошибки ментора):
- локально: вероятности токенов, многократный прогон с голосованием;
- **Jev** (TypeSafe, сентябрь 2026): модель, которая выдаёт калиброванные вероятности вместо текста. В независимом тесте она отмечала неуверенность в 34,7% случаев против 2,7% у Claude Haiku, и её низкая вероятность хорошо предсказывала собственные ошибки.
- Применение в продукте: замечание с низкой уверенностью уходит преподавателю или репетитору. Jev можно использовать и как классификатор «тема в этом коде использована правильно / неправильно / не использована» с вероятностью-весом для оценки освоения.
- Ограничение: Jev облачная, поэтому ей отправляются только обезличенные фрагменты.

## 9. Архитектура

```text
            ┌──────────────────────┐
  Вход ───▶ │  Ментор-конвейер     │ ──┐
 (программа │  (шаги заданы)       │   │
  / код /   └──────────────────────┘   ├──▶  Отчёт: проблемы, что изменить
  ответы)   ┌──────────────────────┐   │       и почему, карта пробелов
       ───▶ │  Ментор-агент        │ ──┘              │
            │  (сам выбирает шаги) │                  │ низкая уверенность
            └──────────┬───────────┘                  ▼
                       │ используют           Проверка человеком
                       ▼                     (репетитор / преподаватель)
  ┌─────────────────────────────────────────────────────────┐
  │ Общие инструменты                                         │
  │  • Граф тем (пререквизиты, поглощение, слои экзаменов)   │
  │  • Модель освоения 0–1 (BKT → DKT)                       │
  │  • База знаний + RAG (спецификации, материалы курса)     │
  │  • Детерминированные проверки (SymPy, тесты, clang-tidy) │
  │  • Локальная LLM (Ollama)                                │
  └─────────────────────────────────────────────────────────┘
```

Оба ментора получают одинаковый вход и пользуются одними инструментами, поэтому их можно честно сравнить.

## 10. Технологический стек

| Компонент | Выбор | Почему |
|---|---|---|
| Модели | Локальные через Ollama (Qwen, Llama, Gemma); облако опционально | Данные студентов не уходят наружу, нет платы за API |
| Конвейер | Чистый Python | Прозрачная базовая линия для сравнения |
| Агент | **LangGraph** (или собственный harness) | Циклы, состояние, пауза «спросить человека» — ровно функция «неуверенно → человеку». Свой harness лучше для понимания внутреннего устройства агентов |
| Хранилище | **PostgreSQL + pgvector** | Граф, освоение и векторы в одной базе вместо трёх систем |
| Граф в прототипе | NetworkX | Быстро; Neo4j — только если вырастет |
| RAG | Эмбеддинги + pgvector (или Chroma / Qdrant) | Для материалов и спецификаций. Сам граф и оценки освоения — не векторы |
| Модель освоения | BKT (pyBKT) → DKT на PyTorch | Курсовая → диплом |
| Проверки | SymPy (математика), тесты, clang-tidy, анализ AST (код) | Детерминированное ядро |
| Распознавание рукописи (позже) | Визуальная модель + дообучение LoRA (CROHME, затем почерк учеников) | Распознавание отдельно, проверка через SymPy отдельно |
| Интерфейс | FastAPI + фронтенд на TypeScript (или Streamlit для прототипа) | |
| Развёртывание | Сервер кафедры (нужна GPU) | |

**Обязателен ли Python?** Нет, но для ML-части практически незаменим: PyTorch, SymPy, pyBKT, LangGraph. Фронтенд можно на TypeScript; для Java есть LangChain4j, но ядро с моделью знаний лучше держать на Python.

**Локальные модели не обязательны, но в Беларуси это преимущество.** По закону РБ о персональных данных передача в страны без «надлежащей защиты» (США туда не входят) требует согласия субъекта или разрешения регулятора. Код и данные студентов логично обрабатывать на сервере кафедры.

**Что такое RAG:** перед ответом система находит нужные куски в своих документах и даёт их модели вместе с вопросом, как экзамен с открытой книгой. Документы режутся на фрагменты → каждый превращается в вектор → по запросу ищутся самые близкие по смыслу → они вставляются в промпт. Ответы опираются на источники, а обновление знаний — это просто замена документа.

### Ключевые игроки

- **Math Academy.** Не стартап в венчурном смысле: семейная компания Math Academy, LLC без инвесторов. Основатели Jason и Sandy Roberts, началось в 2013 году с программы в Пасадене, онлайн с 2021–22 годов. Безубыточна с 2022–23 года при нулевых затратах на рекламу. $49 в месяц, только английский, оплата через Stripe. «Beta» на сайте — постоянный статус, пока дописываются курсы. Граф из тысяч тем, алгоритм повторения FIRe, LLM не использует. Готовит курсы ML и Computer Science с интерфейсом для кода — следить.
- **ALEKS (McGraw Hill).** Теория пространств знаний, десятки миллионов учеников, продажи школам и вузам. Недавно часть оценочного движка заменили нейросетью.
- **Squirrel AI (Китай).** Привлёк больше 180 млн долларов, оценка выше 1 млрд. Математика разбита на 10 000+ «точек знаний», работает через офлайн-центры.
- **Knewton.** Больше 180 млн долларов инвестиций, активы проданы Wiley. Урок: непрозрачный «чёрный ящик».
- **Яндекс Учебник.** Бесплатная платформа ЕГЭ, «Репетитор AI» на Alice AI с октября 2025 года, с сентября 2026 года встроен в Алису. Главный бесплатный конкурент в нише «ИИ-ментор по ЕГЭ».
- **Plario.** Единственный найденный в РФ продукт с публично описанным графом навыков и вероятностной моделью знаний (BKT). Маленький, вузовская алгебра, без экзаменов и LLM.
- **Hyperskill (JetBrains Academy).** Карта знаний с пререквизитами. Пути под проекты собирают методисты вручную, курс из списка тем преподавателя не генерируется. Продажи в РФ прекращены в 2023 году.
- **Яндекс SourceCraft.** Бесплатное ИИ-ревью кода для вузов, промпт настраивается, 20+ вузов. **Главный риск для режима 2:** может добавить персонализацию.
- **ИИ-преподаватель МФТИ/МГТУ (2023).** Концептуально ближе всех к режиму 2: индивидуальная программа и оценка кода по уровню. Массовым не стал, текущий статус неизвестен.
- **GitHub Classroom** закрыт в августе 2026 года, **Replit Teams for Education** — в 2024. Западные инструменты для вузов уходят или недоступны.

### Выводы

- Механику «граф + диагностика + повторения» на английском уже сделали хорошо. Выигрывать за счёт самого алгоритма бессмысленно.
- Свободно: русскоязычный граф с экзаменационными слоями (особенно ЦЭ/ЦТ), прозрачный LLM-ментор поверх графа, режим для репетитора с автоматической картой знаний, проверка кода по освоенному конкретным студентом.
- Монетизация в вузах медленная (гранты, НИР, пилоты на кафедрах). В B2C через репетиторов быстрее.

## 13. Риски

| Риск | Что делаем |
|---|---|
| Локальная модель выдумывает проблемы | Решают правила и вычисления в коде; неуверенные замечания уходят человеку |
| Мало данных для оценки | Свои программы и лабораторные плюс образцы с внесёнными ошибками |
| Граф строить долго | Один раздел или курс; черновик через LLM, ручная проверка |
| Не хватает мощности | Небольшие квантованные модели; GPU кафедры |
| Права на задания | Только открытые материалы (ФИПИ, РИКЗ, спецификации) и свои задания |
| Данные несовершеннолетних и студентов | Обезличивание, локальная обработка |
| Яндекс (SourceCraft, Учебник) добавит персонализацию | Скорость, ниша ЦЭ/ЦТ и репетиторов, глубина графа, прозрачность |
| Мотивация при самообучении | Цель-экзамен, прогноз балла, прогресс, родитель или репетитор в контуре |

## 14. План работ

### Этапы курсовой

1. **Обзор:** аналоги, подходы к автоматической проверке, локальные модели.
2. **Данные:** граф одного курса или раздела (40–60 узлов), спецификация или материалы, задания, 30–50 образцов с эталонной разметкой.
3. **Детерминированное ядро:** 10–15 правил, привязанных к узлам графа; BKT по сданным работам.
4. **Ментор-конвейер:** первая рабочая версия.
5. **Ментор-агент:** на LangGraph, с теми же инструментами и данными.
6. **Эксперименты:** конвейер vs агент, сравнение моделей, оценка уверенности (локально vs Jev).
7. **Интерфейс и записка:** веб-интерфейс, пояснительная записка, презентация.

### Первые шаги (до кода)

- [ ] Обсудить с преподавателем трактовку и пилотный курс.
- [ ] Поговорить с 10–15 репетиторами и учениками о главных болях (проверка спроса для режима 1).
- [ ] Выбрать раздел или курс и набросать граф.
- [ ] Поднять Ollama и проверить 2–3 модели на своём железе.

## 15. Перспектива: диплом и продукт

- **Диплом:** собственная нейросеть knowledge tracing (DKT) на накопленных данных «задание → ответ» и подбор заданий «на границе понимания». Возможно, обучение с подкреплением для выбора маршрута.
- **Самостоятельная подготовка:** адаптивная диагностика и карта пробелов без репетитора.
- **Кабинет репетитора:** данные собираются сами, репетитор только подтверждает.
- **Рукописные решения:** распознавание фото тетради и пошаговая проверка через SymPy.
- **Несколько экзаменов и предметов:** один граф, слои ЦЭ/ЦТ, ОГЭ, ЕГЭ; затем другие предметы и возрасты.
- **Экосистема:** обмен проверенными программами между репетиторами.
- **Web3 (далёкое «потом»):** в ядре не нужен. Теоретически уместен только для проверяемых сертификатов достижений или репутации репетитора.

## 17. Глоссарий

| Термин | Значение |
|---|---|
| РПД | Рабочая программа дисциплины (РФ); в РБ — «учебная программа по учебной дисциплине» |
| ЦЭ / ЦТ | Централизованный экзамен / централизованное тестирование (Беларусь) |
| ОГЭ / ЕГЭ | Основной / единый государственный экзамен (Россия) |
| Граф знаний | Темы-узлы и связи-пререквизиты между ними |
| Освоение (mastery) | Оценка 0–1 того, насколько тема усвоена |
| BKT | Bayesian Knowledge Tracing — вероятностная модель освоения с четырьмя параметрами |
| DKT | Deep Knowledge Tracing — нейросеть (RNN/LSTM), предсказывающая успех по истории ответов |
| RAG | Retrieval-Augmented Generation — генерация с поиском по своим документам |
| Векторная база | Хранилище «отпечатков смысла» текстов для поиска по близости |
| Конвейер | Фиксированная последовательность шагов обработки |
| Агент | LLM, которая сама планирует шаги и вызывает инструменты |
| Harness | Цикл «модель → вызов инструмента → результат → модель», обвязка агента |
| LangGraph | Фреймворк для агентов в виде графа состояний (Python, есть JS-версия) |
| Ollama | Инструмент для запуска локальных LLM |
| LoRA | Лёгкое дообучение части весов модели |
| SymPy | Python-библиотека компьютерной алгебры |
| clang-tidy | Статический анализатор кода C/C++ |
| AST | Синтаксическое дерево программы |
| Jev | Модель TypeSafe (2026), выдающая калиброванные вероятности вместо текста |
| FIRe | Алгоритм интервальных повторений Math Academy, засчитывающий повторение пререквизитам |
