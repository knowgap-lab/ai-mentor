# Бриф: G2, журнал попыток

Для агента-исполнителя. Источник правды — `docs/platform/attempts.md` и `docs/platform/attempts.examples.yaml`. Этот бриф задаёт только интерфейс и имена таблиц. Оценку ответа не писать: её делает `core/internal/answerrules`.

## Пути

`core/internal/attempts/`, миграция `migrations/02001_attempts.sql` (диапазон 02000–02099).

## Таблицы

Схема `core`. Журнал — только добавление (AT-R1): у роли `core_app` на таблицах `attempts`, `attempt_verdict`, `journal_event`, `observation` есть `SELECT` и `INSERT` и нет `UPDATE` и `DELETE`.

- `attempts`: `id` text, `assignment_id` text, `item_id` text, `raw_input` text, `journal_seq` bigint
- `attempt_verdict`: `attempt_id` text, `seq` int, `verdict` text, `points` int, `reason` text null
- `journal_event`: `journal_seq` bigint, `kind` text, `payload` jsonb, `at` timestamptz
- `observation`: `assignment_id` text, `item_id` text, `revision` int, `first_attempt_points` int, `total_points` int, `max_points` int
- `assignment`: `id` text, `student_id` text, `state` text, `kind` text, `catalog_version` int, `deadline` timestamptz, `place` text, `snapshot` jsonb
- `assignment_item`: `assignment_id` text, `item_id` text, `state` text, `skipped` boolean
- `dispute`: `assignment_id` text, `item_id` text, `state` text, `reason` text, `resolved_by` jsonb null
- `homework_draft`: `id` text, `items` jsonb. Это не журнал.
- `outbox`: `id` text, `kind` text, `payload` jsonb

`journal_seq` берётся из одной последовательности `core.journal_seq`.

Черновик в `journal_event` не пишется (AT-R4).

## Интерфейс для тестов

Пакет поднимает обработчики HTTP на `httptest` и ходит в базу через `core/internal/dbtest`. Перед сценарием тест кладёт `given` функцией `Seed(db, given)`. Поля `given` — как в примерах: `assignment`, `item`, `draft`, `attempt`, `dispute`, `actor`, `student`, `catalog_correction`, `observations`, `manual`.

Операции из примеров: `manualVerdict`, `patchHomeworkDraft`, `getAssignment`, `withdrawAssignment`, `extendDeadline`, `submitAssignment`, `didNotUnderstand`, `openDispute`, `listAttempts`.

Заголовок шага `Idempotency-Key` обязателен для `submitAssignment`. Повтор с тем же ключом и тем же телом возвращает тот же ответ и не пишет второе событие (AT-R14).

Текст спора длиннее 300 символов или содержащий телефон (9 и больше цифр после удаления пробелов, скобок, плюса и дефисов) — `422` и код `dispute_text_invalid`.

«Сдать» без `confirm_unanswered`, если есть элементы без ответа, — `409 unanswered_confirmation_required` и `details.left`. С подтверждением — событие `assignment_submitted`, элементы без ответа становятся `skipped`, в `outbox` одно сообщение `homework_submitted`, заданий пересчёта нет.

Чужой ученик на `listAttempts` — `403 forbidden`.

`Anonymise` удаляет персональную строку и не меняет число строк журнала (AT-R25).

Итог элемента (AT-R11): элемент заканчивается на первой попытке, чей текущий вердикт `correct`. Баллы первой попытки и итог хранятся отдельно. Если верных нет, итог — лучший вердикт. В тестах `wrong` даёт 0 баллов, `correct` для части В — 2 из 2. Это цифры из строк at-11 и at-20, не новая шкала.

## Тесты

Один тест на каждый id из `attempts.examples.yaml`, имя содержит id и номер правила (`TestAT_R6_at06a`). Файл примеров не менять. База — `dbtest`. Если Docker недоступен, `t.Skip`.

Тест-исполнитель реализацию не пишет. Сборка может быть красной из-за отсутствия пакета.
