# Бриф: S1, сборка сервера

Для тест-исполнителя, затем для код-исполнителя. Инструкция — `briefs/ORCHESTRATOR-RELEASE1-FINISH.md`, пакет S1. Источники: `docs/01-architecture.md`, `docs/contracts/core-api.yaml`, `docs/contracts/internal-api.yaml`, `docs/platform/auth.md` (AU-R7), `deploy/secrets.md`, `docs/platform/ops.md` (OP-R17).

## Пути

Только `core/cmd/server/` и `core/internal/compose/`.

Модули `lessons`, `homework`, `plan`, `conspect`, `privacy`, `auth`, `answercheck`, `attempts` уже имеют `Handler() http.Handler`. Их код не менять. У `notify`, `recheck` и `telegram` HTTP-обработчика нет: не импортировать их «для галочки» и не объявлять их маршруты. Их подключат пакеты S2 и S6.

## Как собрать

Один маршрутизатор. Шаблоны `net/http` (`http.ServeMux`), как у модулей. Chi не добавлять.

`rootHandler` в режиме local (`ENV=local`, `AUTH_DEV_MODE=true`, `DATABASE_URL` задан) поднимает те же сервисы, что сейчас, и дополнительно `lessons`, `homework`, `plan`, `conspect`, `privacy`.

`isAPI` (или замена) возвращает истину для уже покрытых префиксов и для `/consent`, `/invite`, `/me/sessions`, `/rechecks`, `/tests`, `/telegram`, `/status`, `/internal`. Запрос к этим путям не отдаёт SPA.

Сохранить текущую раздачу `compose.Handler`: `/me` и `/auth/` — вход; `POST` с суффиксом `/answer` — проверка ответа; `GET /students` и `GET /assignments` — как сейчас; всё, что сегодня падает в журнал попыток, остаётся журналу. В том числе `PATCH /lessons/{lesson}/homework-draft` и `POST /assignments/{id}/withdraw`.

Новые пути, которых журнал сейчас не обслуживает, отдать обработчику модуля:

| Метод и путь | Модуль |
|---|---|
| `GET /consent/{token}`, `POST /consent/{token}` | privacy |
| `PUT /students/{id}/schedules/{subject}` | lessons |
| `GET /lessons/{lesson}`, `POST /lessons/{lesson}/move`, `POST /lessons/{lesson}/cancel`, `POST /lessons/{lesson}/marks` | lessons |
| `GET /students/{id}/plans/{subject}` | plan, не lessons (один и тот же шаблон объявлен в обоих; у контракта это план) |
| `GET /students/{id}/plans/{subject}/divergence`, `PUT /students/{id}/plans/{subject}/order` | plan |
| `GET /lessons/{lesson}/homework-draft`, `POST /lessons/{lesson}/homework-draft/issue` | homework |
| `GET /lessons/{lesson}/conspect`, `GET /lessons/{lesson}/conspect.pdf` | conspect |

`GET /status` — по схеме `internal-api.yaml`, операция `getStatus`: без токена и без cookie, тело `{"status":"ok"}`. Если база из `DATABASE_URL` не отвечает, `503` и код из схемы `Error`. Это OP-R17 и контракт, не новая методика.

Внутренний API (`/internal/`) — отдельный обработчик. Сеансовая cookie его не авторизует (AU-R7). Заголовок `Authorization: Bearer` сравнивать с `CONTENT_API_TOKEN` за постоянное время. Нет заголовка или токен не совпал — `401` и JSON `{"code":"unauthorized"}`. Совпал, а маршрута ещё нет — `404` и JSON, не HTML. Не писать в коде строки маршрутов `announceCatalogVersion`, `startRecheck`, `getRecheckState`, `importPlan`, пока нет обработчика: опись считает такую строку за подключённую операцию.

Таблицу служебных токенов в базе не заводить: миграции этого пакета нет. Имя токена взято из `deploy/secrets.md`.

## Тесты

Файл `core/cmd/server/mount_test.go`. Поднять `rootHandler` с тестовой базой `core/internal/dbtest` (если Docker недоступен — `t.Skip`). На каждую строку таблицы выше — один запрос через этот обработчик: ответ не SPA. SPA — это `Content-Type` с `text/html` или тело с `id="root"`. Для пути без сеанса допустимы `401` или `404` с JSON.

Отдельно:

- `GET /status` без cookie — `200` и `{"status":"ok"}`, когда база доступна.
- `POST /internal/catalog-versions` без `Authorization` — не SPA и `401`.
- тот же путь с cookie сеанса и без Bearer — `401`.
- `GET /not-a-screen` — по-прежнему SPA.

Замороженные тесты и `core/internal/e2e` не менять. Имена новых тестов содержат `S1`.

Тест-исполнитель реализацию не пишет. Красный тест из-за отсутствия раздачи — норма.
