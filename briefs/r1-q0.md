# Бриф: Q0, линтеры и чистая установка

Для код-исполнителя. Инструкция — `briefs/ORCHESTRATOR-RELEASE1-FINISH.md`, пакет Q0. Поведение программы не менять. Замороженные тесты не менять (D131).

Рабочий каталог — корень переданного worktree. Корень репозитория с общим `.venv` — каталог, в котором лежит эта ветка интеграции; Python ставить в тот `.venv`, не создавать второй.

## Пути

Только эти пути и точечные правки нетестового кода, которые потребует линтер:

- `tools/check-code.sh`
- `tools/requirements.txt`
- `core/go.mod`, `core/go.sum`
- `core/.golangci.yml`
- `ruff.toml` в корне
- `web/package.json`, `web/package-lock.json`
- нетестовые `*.go`, `*.py`, `*.ts`, `*.tsx` — только строки, без которых линтер не проходит

Не менять: `*_test.go`, `*.examples.yaml`, `docs/contracts/`, `docs/platform/`, `docs/personalization/`, `docs/catalog/`, `legal/`, `docs/decisions/log.md`, `docs/handoff/`.

## Что сделать

1. Закрепить `golangci-lint` v2 как инструмент в `core/go.mod` (`go get -tool github.com/golangci/golangci-lint/v2/cmd/golangci-lint@v2.6.2`, затем `go mod tidy`). Версию не поднимать выше v2.6.2 в этом пакете.
2. Конфиг `core/.golangci.yml` для v2. Включить только: staticcheck, errcheck, gosec, govet, ineffassign, unused. Остальные линтеры не включать.
3. `*_test.go` исключить из прогона линтера одной настройкой конфига. Причина: тесты заморожены, комментарий `nolint` в тесте был бы правкой теста. В отчёте написать эту причину. Сгенерированных каталогов в репозитории нет.
4. Исправить все замечания линтера в нетестовом коде без смены наблюдаемого поведения. Подавление — только `//nolint:<линтер> // <причина>` на конкретной строке, когда правка изменила бы поведение, зафиксированное тестом, или когда срабатывание ложное. Не глушить весь файл.
5. Если замечание нельзя исправить без правки замороженного теста, не трогать тест. Написать в отчёте `ОШИБКА ТЕСТА: <файл>, правило линтера, почему`.
6. Добавить `ruff==0.14.14` в `tools/requirements.txt` и установить его в существующий `.venv` командой `pip install -r tools/requirements.txt`. Конфиг `ruff.toml` в корне: проверка и формат для `content/`, `tools/`, `deploy/`. Не менять смысл Python-кода; поправить только то, что просит ruff (импорты, формат).
7. В `tools/check-code.sh`:
   - `golangci-lint` запускать как `go tool golangci-lint run ./...` из `core/`; отсутствие инструмента — ненулевой код (уже так, не возвращать пропуск);
   - `govulncheck` закрепить инструментом `golang.org/x/vuln/cmd/govulncheck` той версии, которую выберет `go get -tool` на момент запуска, и вызывать `go tool govulncheck ./...` из `core/`; ненулевой код при уязвимости;
   - `npm audit --omit=dev` в `web/`: ненулевой код, если есть high или critical;
   - `go test -race` только для пакетов, чьи тесты не запускают внешний процесс (`exec.Command`, `docker`, Postgres). Список пакетов определить по коду тестов, не по догадке, и вписать его в скрипт явно. Пакеты с внешним процессом по-прежнему идут в обычный `go test ./...` без `-race`.
8. `web/package.json` и lock: на чистом `web/node_modules` команда `npm ci --ignore-scripts` должна давать рабочий `vitest` (`npm test`). Первый заход ломался на `dompurify` и `react-markdown`. Зависимости не убирать. Чужие postinstall не запускать. Новые зависимости — только если без них `npm ci --ignore-scripts` не собирает тесты; лицензия MIT, BSD, Apache-2.0 или ISC; версия закреплена.

## Приёмка

Из корня worktree, `PATH` с `.venv/bin` впереди:

```bash
(cd web && rm -rf node_modules && npm ci --ignore-scripts && npm test)
bash tools/check-code.sh
```

`git diff` по `*_test.go` пуст. Сеть продукта (Telegram и прочие сервисы) не вызывать. `git commit` и `git push` не делать.
