# Общие правила пакетов S3–S8 и W0 доделки выпуска 1

Читается вместе с брифом пакета (`briefs/r1-<пакет>.md`). Правила проекта — `AGENTS.md`. Роли и правило библиотек — `briefs/CURSOR-SETUP.md`, разделы 4, 6, 7.

## Работа в worktree

- Работайте только в своём worktree (абсолютный путь дан в запросе) и только в путях брифа. Основное дерево и чужие worktree не трогать.
- Python и линтеры: `export PATH="/home/stranger/projects/university/coursework/ai-mentor/.venv/bin:$PATH"`.
- `golangci-lint` запускается как `go tool golangci-lint run ./...` из `core/`.
- База для тестов: `core/internal/dbtest` поднимает свой контейнер `postgres:16.15` на случайном порту на каждый тест. Соседям это не мешает. Образы не скачивать (`--pull never`).
- Вложенных субагентов нет: вы никого не запускаете.

## Имена, чтобы слияния не конфликтовали

- Новые тестовые файлы носят имя пакета: `rules_s4_test.go`, `harness_s4_test.go`. Существующие тестовые файлы заморожены: не менять, не переименовывать.
- Новые вспомогательные функции, типы и переменные в тестах начинаются с `s4`/`S4` (свой номер пакета). Тесты правил называются `Test<ПРАВИЛО>_S4_…`, например `TestLS_R5_S4_AddLesson`.
- Миграции — только расширяющие (D127), только в своём диапазоне, только схема `core` (D92). Миграция нужна лишь тогда, когда правило требует хранить новое.

## Тест через собранный сервер

Для каждой **новой** операции пакета тест-исполнитель пишет один тест в новом файле `core/cmd/server/mount_<пакет>_test.go` по образцу `core/cmd/server/mount_test.go`: запрос через `rootHandler`, ответ не от SPA (`Content-Type` не `text/html`, в теле нет `id="root"`), статус не `404` от неизвестного маршрута. Имя теста содержит `S3`…`S8`. Эти тесты остаются красными после кода пакета: зелёными их делает оркестратор коммитом подключения. Код-исполнитель их не чинит и сервер не трогает. Обработчики вешаются на `Handler() http.Handler` своего модуля.

## События журнала

Новое событие пишется так же, как их пишет модуль сейчас (`core.journal_event`, поля `kind` и `payload`). `kind` — имя типа из `docs/contracts/events.schema.json`, `payload` проходит схему `$defs/<тип>_payload`. Типов и полей вне схемы нет. Конверт (`schema_version` и остальное) добавит пакет S7 после вас.

## Контракт и ошибки

- Метод, путь, тело, статусы, поля и коды ошибок — ровно по `docs/contracts/core-api.yaml` и `internal-api.yaml`. `docs/contracts/`, спецификации, `*.examples.yaml`, `legal/` не менять.
- Все изменяющие запросы требуют сеанса, CSRF и проверки Origin так, как это делает модуль `core/internal/auth` (AU-R24). Чужой и несуществующий объект неразличимы (AU-R4).
- В ответах до попытки нет ключей (WB-R4). В логах нет имён учеников, токенов и секретов.
- Данные в тестах только выдуманные.

## Если правило и замороженный тест расходятся

Тест не менять. Сначала искать правку, совместимую с тестом. Если её нет — строка `ОШИБКА ТЕСТА: <тест>, <правило>, почему` в отчёте, эту часть не делать, остальное довести до зелёного. Неоднозначное правило — строка `ВОПРОС: …; варианты: …`, не выбирать самому.
