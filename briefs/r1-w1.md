# Бриф: W1, страница задачи

Для агента-исполнителя. Экран одной задачи. Ключ не рисуется, пока его нет в ответе API.

## Источники

- `docs/platform/web.md`: WB-R4, WB-R10…WB-R15, WB-R26
- `docs/platform/answer-check.md`: AC-R7, AC-R9

## Пути

Только `web/src/task/` и тесты `web/src/task/*.test.tsx`. Общие файлы `web/src/main.tsx` и `web/src/App.tsx` можно дополнить маршрутом `/task/:assignmentId/:itemId`.

## Поведение

Страница получает условие и формат. Кнопка «Ответить».

- `ct.choice1` — переключатели 1–5 (WB-R10).
- `ct.choiceN` — флажки 1–5, число верных не пишется (WB-R11).
- `ct.integer` — поле и кнопка «−»; точка и запятая не уходят на сервер, подсказка «введите целое число» (WB-R14).
- После ответа текст берётся из тела ответа. Если в теле нет `show`, на странице нет ключа и слова «решение» (WB-R4, AC-R9).
- Часть В, первая ошибка: «неверно» и «осталась 1 попытка», без ключа (WB-R15).
- Условие рендерится как Markdown. Формулы через KaTeX с `trust: false`. Сырой HTML из условия не исполняется (WB-R26).

Зависимости, если их ещё нет: `react-markdown`, `rehype-katex`, `remark-math`, `katex`, `dompurify`. Ставить `npm install --ignore-scripts` в `web/`.

## Тесты

Vitest и Testing Library. Минимум: choice1 отправляет выбранный номер; integer не шлёт «12,0»; ответ без `show` не содержит ключ «12»; ответ с `show.key` его показывает. Имена тестов содержат номер правила (`wb-r4`, `wb-r14`).

Тест-исполнитель компонент не пишет. Команда из `web/`: `npm test -- --run src/task`.

## Запреты

`git commit`, скачивание браузеров, ключи в исходниках страницы.
