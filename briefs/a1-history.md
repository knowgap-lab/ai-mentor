## Интерфейс

```python
check_catalog(path: pathlib.Path, mode: str = "pr", base: pathlib.Path | None = None) -> list[Problem]
```

Прежний вызов из двух аргументов работает как раньше. `base is None` — коды этого брифа не возвращаются.

CLI из `content/`: `python -m catalog_ci check <path> [--mode pr|main] [--base <каталог>] [--json]`. Нет каталога базы — код выхода 2.

Сущности те же, что уже собирает проверка: тема, элемент, тип, подвариант, вариант, блок, тест, шаблон урока, этап. У каждой есть id. Нет поля `status` — сущность считается `active`.

Сравнение идёт по id. Файлы каталога функция не переписывает.

| Код | Когда | Не когда |
|---|---|---|
| `id_removed` | id есть в базе и его нет в результате | сущность осталась со `status: retired` |
| `id_reused` | в базе у id `status: retired`, в результате тот же id есть и статус не `retired` | id в обоих состояниях `active`, даже если тему сменили (CS-R5); retired остался retired |
| `transfer_map_missing` | в результате тип или элемент `retired`, в базе у него были появления или варианты, и в `transfer-map.yaml` результата этот id не встречается ни в `from`, ни в `to`, ни в `subvariants_to` | id есть в карте результата; у retired не было ни появлений, ни вариантов |

Появления типа — id типа в файле теста базы. Варианты типа — файл вариантов базы с полем `type`, равным этому id. У элемента «были варианты или появления», если в базе он `primary_element` типа, у которого были варианты или появления.

Один id может дать только один из `id_removed` и `id_reused`. `transfer_map_missing` может добавиться к другим кодам того же файла, если условия выполнены.

`file` и `pointer` — место id в результате; для `id_removed`, когда файла в результате нет, `file` — путь файла базы относительно базы, `pointer` — указатель id в базе.

## Примеры

- `cs-20`: из результата удалён id, который был в базе → `id_removed`.
- `cs-21`: id retired в базе снова active в результате → `id_reused`.
- `cs-22`: тип перенесён в другую тему, id тот же и не retired → этих трёх кодов нет.
- `cs-30`: тип retired и в базе был в тесте, карты нет → `transfer_map_missing`.
- `cs-31`: деление записано, `subvariants_to` указывает новый тип, id подвариантов в результате те же, что в базе → этих трёх кодов нет. Проверка сама id не меняет; тест сравнивает id в двух копиях каталога.

База для тестов — копия демо-каталога. В демо нет retired-сущностей и карты: тест создаёт их минимальной правкой копий.
