# Бриф: G8, перепроверка ключа

Для агента-исполнителя. Баллы считает уже принятый `core/internal/answerrules.Score`. Сеть нет.

## Источники

- `docs/platform/recheck.md`: RC-R2, RC-R3, RC-R4, RC-R5, RC-R10, RC-R11, RC-R12, RC-R13
- строки примеров с этими номерами в `docs/platform/recheck.md`, раздел «Таблицы примеров»

## Пути

`core/internal/recheck/`, миграция `migrations/07001_recheck.sql`.

## Поведение

`Accept(correctionID int, variants []string) (State, error)`

- Первый вызов отвечает состоянием `pending` (как HTTP 202).
- Повтор с тем же `correction_id` и тем же списком возвращает то же состояние и не создаёт второй пакет (RC-R2).
- `correction_id` меньше уже принятого максимума — ошибка `stale_correction` (RC-R3).
- Неизвестный id варианта — `variant_unknown`, пакет не создаётся (RC-R4).

`Run(correctionID)` пересчитывает попытки этих вариантов:

- Ключ был 12, стал 14, ответ ученика 14: новый `attempt_verdict` correct, баллы 2. Старый wrong остаётся (RC-R10, RC-R12).
- Ответ 12 при новом ключе 14: correct становится wrong.
- Ответ 15 при том же изменении: вердикт wrong не изменился, новой строки вердикта нет (RC-R11).
- Текущий вердикт поставлен вручную: попытка в `skipped_manual`, пересчёта нет (RC-R13).

Оценка идёт через `answerrules.Score` с форматом `ct.integer`.

## Тесты

По одному на RC-R2, RC-R3, RC-R10 (оба направления), RC-R11, RC-R13. Имена содержат номер. База — `dbtest`. Нет Docker — `t.Skip`.
