# Бриф: G1, правила ответа

Для агента-исполнителя. Чистая функция, без базы и HTTP. Эталон поведения — `tools/examples/check_answer_rules.py` и строки `docs/catalog/answer-rules.examples.yaml`. При расхождении прав таблица примеров.

## Источники

- `docs/catalog/answer-rules.md`, AR-R4…AR-R15 (оценка). AR-R16…AR-R20 — проверка каталога, их не реализовывать.
- `docs/catalog/answer-rules.examples.yaml`, все строки `ar-01`…`ar-57`.
- `tools/examples/check_answer_rules.py` — уже принятая чистая функция на Python. Go обязан дать тот же результат на тех же строках.

## Интерфейс

Пакет `core/internal/answerrules`.

```go
type Result struct {
    Status     string // scored | malformed
    Normalized string
    Verdict    string // correct | partial | wrong
    Points     int
    TrapID     string
}

func Score(format string, key any, raw any, traps map[string]string) Result
```

`key` для choice — `[]int`, для integer — `int`, для digits и match — `string`. `raw` — `string` или `[]int`. Пустой `TrapID` в JSON смысла не имеет: при сравнении с примером поле есть только если ловушка сработала.

Неверные форматы не угадывать: неизвестный `format` — паника или ошибка, тесты такой не передают.

## Тесты

`core/internal/answerrules/score_test.go`. Читает YAML из репозитория (`docs/catalog/answer-rules.examples.yaml`) и на каждую строку сверяет `Score` с `expect`. Имя подтеста содержит id и номер правила (`ar-08/AR-R7`). Файл примеров не менять.

Тест-исполнитель не пишет `score.go`. Сборка может быть красной из-за отсутствия `Score`.

## Критерий

`cd core && go test ./internal/answerrules/` зелёный. `gofmt -l` пуст.
