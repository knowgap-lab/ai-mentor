## Пути

`core/internal/privacy/`, миграция `migrations/04001_consent.sql`.

## Таблицы

- `core.consent_link`: `token_hash` bytea primary key, `student_id` text, `kind` text (`parent` или `student`), `expires_at` timestamptz, `created_at` timestamptz. Сырого токена нет.
- `core.consent`: `student_id` text primary key, `version` int, `state` text (`active`, `revoked`, `outdated`, `needs_personal`), `granted_at` timestamptz, `revoked_at` timestamptz null, `anonymise_at` timestamptz null.

ПДн остаются в уже существующей `core.student_pii` (`display_name`, `telegram_id`, `birth_date`). Поля «школа» там нет (PV-R1).

## Поведение

- `CreateLink(student, kind, now)`: токен 32 байта, в базе только SHA-256, срок 14 суток. Ученику меньше 18 лет нельзя создать ссылку `student`. Ученику 18 и старше нельзя создать ссылку `parent` (PV-R12). Возраст — по `birth_date` на момент `now`.
- `GET /consent/{token}` не меняет ни одной строки (PV-R11).
- `POST /consent/{token}` с телом `{"action":"grant"}` ставит согласие `active`. Просроченная ссылка (15-е сутки) — `410`.
- `POST` с `{"action":"revoke"}` ставит `revoked_at=now`, `anonymise_at=now+7 суток`, состояние `revoked` (PV-R17).
- Повторный `grant` в эти 7 суток возвращает `active` и очищает `revoked_at` и `anonymise_at` (PV-R18).
