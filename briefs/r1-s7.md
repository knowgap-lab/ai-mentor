# Бриф: S7, журнал событий

Для тест-исполнителя сейчас. Код-исполнитель запускается позже, после слияния S2–S6: он правит места записи событий в их модулях. Сначала прочитайте `briefs/r1-finish-common.md`. Источники целиком: `docs/contracts/events.schema.json`, `docs/platform/attempts.md` (AT-R1, AT-R3 и остальные правила журнала), `docs/01-architecture.md` (раздел о журнале), `migrations/02001_attempts.sql` (таблица `core.journal_event`).

## Что должно получиться

Каждая запись журнала читается как документ-конверт из `events.schema.json`: `schema_version`, `journal_seq`, `occurred_at`, `actor`, `event_type`, `student_id`, `payload`. Документ проходит схему целиком, включая полезную нагрузку своего типа. Сейчас таблица хранит только `kind`, `payload`, `at`, а часть модулей пишет нагрузку не по схеме.

## Интерфейс (его задаёт этот бриф, тесты пишутся к нему)

Новый Go-пакет `core/internal/events`:

```go
// Documents возвращает все записи журнала конвертами events.schema.json
// в порядке journal_seq. Каждый элемент — один JSON-документ.
func Documents(ctx context.Context, db Queryer) ([][]byte, error)

// Validate проверяет один документ по docs/contracts/events.schema.json.
func Validate(doc []byte) error
```

`Queryer` — интерфейс с методом `Query` из `pgx/v5` (подходит и пул, и транзакция). Схема встраивается в бинарник или читается по пути от корня репозитория; копию схемы руками не писать (D97). Как хранить недостающие поля конверта (новые колонки миграцией `16001…16999` либо иначе) — решает код-исполнитель; миграция только расширяющая, журнал только добавляется (AT-R1).

## Пути

- `core/internal/events/` — пакет и его тесты.
- Новые файлы `events_s7_test.go` в `core/internal/attempts/`, `answercheck/`, `lessons/`, `plan/`, `homework/`, `recheck/`, `privacy/`, `auth/`. Только этот один новый файл в каждом каталоге; существующие тесты и помощники заморожены, пользоваться ими можно.
- Новый файл `core/internal/e2e/events_s7_test.go`.
- Миграции `migrations/16001…16999` (код-исполнитель).

В этих каталогах параллельно работают S2–S6. Их файлы не трогать. Все ваши идентификаторы начинаются с `s7`/`S7`, тесты называются `TestS7_…` или `Test<ПРАВИЛО>_S7_…`.

## Тесты

1. `core/internal/events/`: `Validate` принимает верный документ каждого типа из `oneOf` и отклоняет документ без `schema_version`, с неизвестным `event_type`, с нагрузкой чужого типа, с лишним полем там, где схема его запрещает. Примеры документов стройте по схеме, выдуманными id.
2. В каждом модуле (`events_s7_test.go`): прогнать существующим помощником пакета один-два настоящих пути, которые пишут события (ответ и сдача, выдача ДЗ, отметка и перенос урока, смена порядка плана, перепроверка, согласие и отзыв, вход и отзыв сеанса), затем взять `events.Documents` и проверить `events.Validate` для каждого документа. Плюс: `journal_seq` строго растёт, `occurred_at` не пуст, `student_id` — тот ученик, чьё событие.
3. `core/internal/e2e/events_s7_test.go`: после сквозного прохода все документы журнала проходят схему.
4. AT-R1: у роли `core_app` по-прежнему нет `UPDATE` и `DELETE` на журнал после миграции.

Красные тесты допустимы только из-за отсутствия пакета `events` и из-за того, что модули пишут не по схеме. Если схема не позволяет выразить событие, которое модуль пишет сейчас, — строка `ВОПРОС`, контракт не править.
