## Таблицы

Схема `catalog`, роль `loader` может только `SELECT` и `INSERT`.

- `catalog.revision`: `entity_id` text, `catalog_version_from` int, `content_hash` text, `data` jsonb. Первичный ключ `(entity_id, catalog_version_from)`.
- `catalog.load`: `catalog_version` int primary key, `commit` text, `loaded_at` timestamptz.
- `catalog.core_call`: `id` bigint, `kind` text (`version` или `recheck`), `catalog_version` int, `payload` jsonb.

Повтор той же версии не добавляет строк и не добавляет вызов (LD-R8). Новая ревизия сущности пишется, только если хеш изменился (LD-R6). Старые ревизии не изменяются и не удаляются (LD-R4).

## Интерфейс

```python
def load_artifact(dsn: str, artifact_path: Path, *, environment: str) -> LoadResult
```

`environment` — `staging` или `prod`. В `prod` версия принимается, только если та же версия уже есть в `staging` той же базы. Иначе отказ `not_in_staging`, база не меняется (LD-R15). Для теста достаточно одной базы и колонки `environment` в `catalog.load`.

`LoadResult`: `catalog_version`, `new` (bool), `recheck_ids` (список id вариантов с новым ключом). Если ключ варианта изменился относительно последней ревизии, в `core_call` есть запись `recheck` с этими id и `correction_id = catalog_version` (LD-R12).

Артефакт сначала проходит `catalog_artifact.verify_artifact`. Битый архив — отказ, база не меняется.

Чтение версии N возвращает последнюю ревизию каждого id с `catalog_version_from <= N` (LD-R7).
