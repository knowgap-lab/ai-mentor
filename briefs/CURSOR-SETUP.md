# Cursor: подготовка, модели, effort, библиотеки

Общий файл для обоих оркестраторов (`briefs/ORCHESTRATOR.md`, `briefs/ORCHESTRATOR-RELEASE1.md`). Первая часть для человека, остальные для оркестратора: читайте их перед работой.

## 1. Что поставить до запуска (человеку)

1. **Context7 MCP** — актуальная документация библиотек прямо в контексте агента, чтобы код писался по настоящему API версии, а не по памяти модели. Добавьте в пользовательский `~/.cursor/mcp.json` (не в репозиторий):

   ```json
   {
     "mcpServers": {
       "context7": {
         "command": "npx",
         "args": ["-y", "@upstash/context7-mcp"]
       }
     }
   }
   ```

   Проверка: в настройках Cursor → MCP сервер горит зелёным. Ключ API не обязателен, но с ключом выше лимиты запросов.
2. **Docker запущен**, на машине есть `go`, `node`, `npm`, `psql`, `python3` с `venv` (проверено 2026-11-09: все есть).
3. **Автозапуск команд**: для долгой сессии включите авто-выполнение команд агента со списком разрешённых (`go`, `gofmt`, `npm`, `npx vitest`, `tsc`, `docker`, `psql`, `python3`, `pytest`, `git` без `push`). Запретите `git push`, `gh`, `rm -rf` вне worktree. Иначе агент остановится на первом вопросе о разрешении и будет ждать вас.
4. Модель оркестратора выберите вручную до старта (раздел 3); «Auto» выключите: нужна предсказуемость.
5. Необязательно, по желанию: встроенный браузер Cursor для проверки веб-страниц. Скачивать Playwright и браузеры агент не будет.

О «скилах»: у Claude Code есть отдельные скилы, у Cursor их аналоги называются правилами и навыками агента. Названия в каталоге Cursor я не проверял, поэтому конкретные пакеты не называю. Что работает надёжно и уже есть: `AGENTS.md` (Cursor читает его сам) и Context7. Если захотите добавить рекомендации по стилю кода (Go, React), это отдельные правила в `.cursor/rules/`: скажите, я их напишу под проект.

## 2. Как использовать Context7 (оркестратору и исполнителям)

- Перед тем как писать код с библиотекой (chi, pgx, sqlc, oapi-codegen, React Router, TanStack Query и т. д.), получите документацию нужной версии через Context7 (`resolve-library-id`, затем `query-docs`) и пишите по ней. Версию берите из lock-файла.
- В запросы к Context7 отправляйте только название библиотеки и вопрос по API. Никогда: код проекта, секреты, данные учеников.
- Если Context7 недоступен, используйте документацию из модуля Go (`go doc`) или `node_modules`; не пишите по памяти. Недоступность Context7 не повод останавливаться.

## 3. Модели и effort

Доступные модели (по списку Cursor на 2026-11-09): Claude Fable 5.1, Claude Opus 5.5, Claude Sonnet 5.5, GPT-5.6 Sol, Grok 4.7, Grok 4.6, Gemini 4 Argon, Composer 2.5, Muse Wonder. Раздача ниже моя рекомендация. Про Fable, Opus и GPT-5.6 Sol у меня есть данные из ваших заметок по оркестрации, про Grok 4.7, Gemini 4 Argon, Composer 2.5 и Muse Wonder данных мало, поэтому их роли консервативные.

| Роль | Модель | Effort | Контекст | Почему |
|---|---|---|---|---|
| Оркестратор | Claude Fable 5.1 | High | 500K | Самая сильная на суждении и долгой работе; следит за процессом сутки, пишет брифы и принимает результат |
| Тест-исполнитель | GPT-5.6 Sol | High | 256K | Другое семейство, чем у автора кода: тесты не повторяют те же слепые пятна |
| Код-исполнитель: Go-ядро, безопасность, БД (auth, privacy, attempts, answer-check, recheck, миграции) | Claude Opus 5.5 | High | 256K | Критичные пакеты, ошибка здесь дороже всего |
| Код-исполнитель: веб, загрузчик, уроки/ДЗ/план/конспект | Claude Sonnet 5.5 | High | 256K | Хорошее качество кода быстрее и дешевле Opus |
| Код-исполнитель: механика (Compose, скрипты, шаблоны, простые экраны) | Composer 2.5 | Medium | 256K | Дёшево и быстро; допустимо, потому что результат всё равно закрывают замороженные тесты |
| Ревьюер пакета | GPT-5.6 Sol | High | 256K | Другая модель, чем автор кода (если автор Claude) |
| Ревьюер безопасности и перекрёстное ревью фазы | Grok 4.7 | High | 500K | Третье семейство, большой контекст для чтения всей ветки |
| Повторная постановка после отказа приёмки | та же модель, что была | Extra High | как у роли | Усилие повышаем только на повторе |

Правила раздачи:
- Тесты и код пишут модели **разных семейств**; ревьюер — не то же семейство, что автор кода. Если нужной модели нет, возьмите ближайшую доступную и запишите в отчёт.
- Режим Fast выключен везде.
- Extra High дорог по времени и лимитам: только на повторе и для ревью auth и privacy, если остался запас.
- Если окружение не даёт выбрать модель для субагента, оркестратор запускает субагентов на модели по умолчанию и записывает это в отчёт.

## 4. Правило библиотек: сначала готовое

Если задачу решает зрелая библиотека, берите библиотеку, а не пишите своё. Свой код нужен только там, где работает правило проекта: нормализация и оценка ответов, баллы, права, видимость ключей. Вокруг них (HTTP, БД, сессии, формы, формулы, PWA, таблицы, даты, валидация) берите готовое.

Критерии выбора библиотеки (все обязательны):
1. Поддерживается: релиз или коммит за последний год.
2. Лицензия MIT, BSD, Apache-2.0 или ISC. GPL и AGPL нельзя: репозиторий публичный, и код платформы закрывать лицензией нельзя.
3. Широко используется, без огромного дерева зависимостей для простой задачи.
4. Версия закреплена в lock-файле (`go.sum`, `package-lock.json`, `requirements`); `npm ci --ignore-scripts`; чужие postinstall-скрипты не запускаются.
5. API проверен по актуальной документации (Context7).

Порядок: проверенная стандартная библиотека → зрелая популярная библиотека → свой код. Выбор, влияющий на несколько пакетов (веб-фреймворк, UI-кит, слой доступа к БД, способ PDF), записывается строкой в журнал решений как «default chosen by the orchestrator». Мелкие библиотеки внутри одного пакета записываются в отчёт исполнителя и итоговый отчёт.

Кандидаты по умолчанию (можно заменить на другие, подходящие под критерии):
- **Go:** `net/http` + `chi`, `pgx/v5`, `sqlc` (типобезопасные запросы из SQL), `oapi-codegen` и `kin-openapi` (контракт и проверка запросов), `goose` или `golang-migrate`, `alexedwards/scs` (сессии), защита от CSRF из `filippo.io/csrf` или `gorilla/csrf`, `golang.org/x/time/rate`, `log/slog`, `gopkg.in/yaml.v3`; тесты — `testify`, `go-cmp`, `testcontainers-go`.
- **Web:** Vite, React, TypeScript, React Router, TanStack Query, `openapi-fetch` и `openapi-typescript`, `react-hook-form` + `zod`, один UI-кит на весь веб (Mantine или Tailwind с Radix; выбрать в F0 и записать), `react-markdown` + `remark-math` + `rehype-katex`, `DOMPurify`, `vite-plugin-pwa`, `date-fns`; тесты — `vitest`, `@testing-library/react`.
- **Python:** `psycopg`, `pydantic`, `jsonschema`, `pyyaml`, `pytest`, `hypothesis` (property-based тесты).

Инструменты генерации (sqlc, oapi-codegen и т. п.) закрепляются версией в `go.mod` (директива `tool`) или в `devDependencies`. Устанавливать их разрешено только из публичных реестров по lock-файлам.
