# Бриф: G4, локальный вход

Для агента-исполнителя. Только локальный вход, сеанс, cookie и CSRF. Telegram, приглашения и подтверждение устройства репетитора — пакет G5, их не делать.

## Источники

- `docs/platform/auth.md`: AU-R1…R4, AU-R6, AU-R21…R27, AU-R36, AU-R37
- `docs/contracts/core-api.yaml`: `loginDev`, `logout`, `getMe`, схема `Me`, cookie `__Host-session`
- D272 п.7: до сеанса проверяется только Origin
- D300: сеансы можно хранить через `alexedwards/scs`, если cookie настраивается по AU-R22. Если библиотека не умеет имя `__Host-session` и атрибуты из AU-R22, сеанс хранится в Postgres, а в отчёте написано, почему библиотека не подошла. CSRF — по AU-R24, не по чужой схеме токена.

## Пути

`core/internal/auth/`, миграция `migrations/03001_auth.sql` (диапазон 03000–03099).

## Таблицы

Имена зафиксированы здесь, в спецификации их нет:

- `core.app_user`: `id` text, `role` text (`student` или `tutor`), `owner_tutor_id` text null, `status` text
- `core.user_pii`: `user_id` text, `telegram_id` text. Это персональные данные. Роль `reader` их не читает.
- `core.session`: `token_hash` bytea, `user_id` text, `created_at` timestamptz, `expires_at` timestamptz, `revoked_at` timestamptz null

В `core.session` нет сырого токена. В логах нет токена, cookie и `telegram_id` (AU-R37).

## Поведение

`POST /auth/dev` принимает тело контракта `{telegram_id, role}`.

- Включён только если окружение `local` и `AUTH_DEV_MODE=true`. Иначе обработчик отвечает 403 `forbidden`. Функция старта `RejectDevMode(env, enabled bool) error` возвращает ошибку, если enabled и env не `local`: сервер с ней не запускается (AU-R36).
- До сеанса CSRF нет. Нужен заголовок `Origin`, равный `APP_ORIGIN` (в тестах `http://localhost`). Чужой Origin — 403 `csrf`.
- Успех: 200 и тело `Me` (`user_id`, `role`). `user_id` стабилен для пары (`telegram_id`, `role`): повторный вход того же человека не создаёт второго пользователя.
- Ученик, которого ещё нет, создаётся с `owner_tutor_id` пустым. Репетитор создаётся с пустым владельцем.
- Cookie `__Host-session`: значение — сырой токен (32 байта, hex), атрибуты `Secure`, `HttpOnly`, `SameSite=Lax`, `Path=/`, без `Domain`. В базе только SHA-256 токена.
- Срок: ученик 90 суток, репетитор 7 суток от момента входа, без продления (AU-R23).
- В ответе заголовок `X-CSRF-Token` равен сырому токену сеанса, чтобы клиент мог поставить его в следующий запрос. В `Me` этого поля нет.
- Шестой действующий сеанс ученика отзывает самый старый (AU-R26). У репетитора этого предела в этом пакете нет.

`POST /auth/logout` с сеансом и верным CSRF отзывает текущий сеанс и отвечает 204. Без сеанса — 401.

`GET /me` с сеансом отвечает `Me`. Без сеанса — 401. Просроченный сеанс — 401.

Любой другой POST этого пакета без `X-CSRF-Token`, равного токену сеанса, или с чужим `Origin` — 403 `csrf` (AU-R24).

`Authorize(actor, action, object) error`. Чужой и несуществующий ученик дают одну и ту же ошибку 403 `forbidden` и одно и то же тело (AU-R4). В этом пакете объект — ученик: репетитор видит ученика, у которого `owner_tutor_id` равен ему; ученик видит только себя.

Ключ идемпотентности хранится вместе с пользователем: `Remember(user, key, response)` возвращает прежний ответ тому же пользователю и не возвращает его другому (AU-R6). Отдельного маршрута под это нет.

## Тесты

`core/internal/auth/*_test.go`. На каждое правило из раздела «Поведение» минимум один тест, в имени номер (`TestAU_R36_...`, `TestAU_R24_...`). База — `core/internal/dbtest`. Если Docker недоступен, тест делает `t.Skip` с причиной. Данные только синтетические (`telegram_id` вида `tg-demo-1`).

Тест-исполнитель не пишет реализацию. Сборка может быть красной из-за отсутствия пакета.
