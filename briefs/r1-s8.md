# Бриф: S8, PDF

Для тест-исполнителя, затем для код-исполнителя. Сначала прочитайте `briefs/r1-finish-common.md`. Источники целиком: решение **D301** в `docs/decisions/log.md`, `docs/personalization/conspect.md` (CN-R10, CN-R11, CN-R12, CN-R13, CN-R3), `conspect.examples.yaml`, `docs/platform/web.md` (WB-R28, WB-R29), `docs/platform/ops.md`, `docs/contracts/core-api.yaml` (`getConspectPdf`, `getSheetPdf`, `getTestFormPdf`), `deploy/README.md`, `deploy/compose.prod.yml`, `deploy/compose.staging.yml`.

## Пути

- `core/internal/conspect/` — `getConspectPdf` и правка запасного пути.
- `core/internal/pdf/` — новый Go-пакет: клиент Gotenberg, хранение первого PDF снимка, `Handler()` с `getSheetPdf` и `getTestFormPdf`. Таблицы выдач и попыток читать своим SQL, пакеты `attempts` и `homework` не трогать (там работает S5).
- `core/internal/gotenbergtest/` — помощник тестов по образцу `core/internal/dbtest`: поднимает Gotenberg контейнером на случайном порту, `--pull never`; нет Docker или образа — `t.Skip`. Имя образа с версией помощник читает из `deploy/compose.prod.yml` (сервис `gotenberg`), своей копии версии не держит.
- `deploy/` — сервис `gotenberg` в обоих файлах Compose: образ закреплён точной версией, только внутренняя сеть, наружу порт не публикуется. Новые тесты — `deploy/ops_s8_test.py`; `deploy/ops_test.py` заморожен.
- Миграции `migrations/17001…17999`, один файл `core/cmd/server/mount_s8_test.go`.

## Операции

- `getConspectPdf` `GET /lessons/{lesson}/conspect.pdf` (CN-R10) — сейчас всегда `503`.
- `getSheetPdf` `GET /assignments/{id}/sheet.pdf` (WB-R28) — листок ДЗ без ключей.
- `getTestFormPdf` `GET /tests/{test}/form.pdf` (WB-R28) — бланк.

## Что должно получиться (D301)

- `core` отдаёт Gotenberg тот же HTML, что и веб: всё встроено (стили, шрифты, KaTeX), внешних запросов из документа нет.
- Первый PDF снимка хранится (ключ — id снимка и версия шаблона) и отдаётся теми же байтами при каждом следующем запросе (CN-R12). Даты в метаданных документа — время снимка.
- Gotenberg недоступен или вернул ошибку — `503` и код `pdf_unavailable`.
- Адрес Gotenberg `core` берёт из окружения. Имя переменной — из `deploy/secrets.md` или `deploy/README.md`; если его там нет, добавьте в `deploy/` и напишите строку `ВОПРОС` с выбранным именем.
- В листке ДЗ и бланке нет ключей ответов (WB-R4, WB-R28). Права — как у соответствующих JSON-операций.

## Находки ревью, которые надо закрыть

- CN-R13: запасной файл урока конспект читает из объекта `lesson_file`, а уроки пишут `core.lesson.template` массивом этапов. Читать формат уроков (см. `core/internal/lessons/`, только чтение).
- CN-R3: в переносе нет номера урока-источника, но в схеме `Conspect` такого поля нет. Поле мимо контракта не добавлять; в отчёте — строка `ВОПРОС`.

## Тесты

Один тест на каждый номер CN-R10…R13, WB-R28, WB-R29, плюс: два запроса подряд дают одни и те же байты; ответ начинается с `%PDF-`; Gotenberg по адресу, где никто не слушает, — `503 pdf_unavailable`; чужой ученик и чужой репетитор; в тексте PDF листка нет значения ключа из тестовых данных; HTML, который уходит в Gotenberg, не содержит `http://` и `https://` ссылок на внешние узлы (проверять на подставном сервере вместо Gotenberg). Тесты, которым нужен настоящий Gotenberg, идут через `gotenbergtest` и пропускаются, если образа нет: образ для приёмки скачает оркестратор по D301, исполнитель образы не скачивает.
