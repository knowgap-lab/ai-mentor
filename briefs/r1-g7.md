# Бриф: G7, исходящие сообщения

Для агента-исполнителя. Реальный Telegram не вызывать. Транспорт — интерфейс, в тестах заглушка.

## Источники

- `docs/platform/notifications.md`: NT-R1…NT-R13
- таблица `core.outbox` уже создана в `migrations/02001_attempts.sql` с колонками `id`, `kind`, `payload`

## Пути

`core/internal/notify/`, миграция `migrations/05001_outbox.sql`.

## Схема

Миграция добавляет колонки, не удаляя старые: `dedup_key` text unique, `recipient_kind` text, `recipient_id` text, `template` text, `params` jsonb, `state` text default `pending`, `attempts` int default 0, `next_attempt_at` timestamptz, `created_at` timestamptz, `sent_at` timestamptz null, `last_error` text null.

`params` не принимает ключи `display_name`, `telegram_id`, `name`, `text`. Такая вставка возвращает ошибку `outbox_params_invalid` и ничего не пишет (NT-R4).

## Поведение

- `Enqueue(tx, message)` пишет строку в той же транзакции. Повтор того же `dedup_key` ничего не делает (NT-R3).
- `Dispatch(now, transport)` берёт `pending` с `next_attempt_at <= now`. Одной строке одного получателя за вызов.
- Успех транспорта: `state=sent`, `sent_at=now`. Текст транспорта нигде не сохраняется.
- Ошибка сети: пауза `30s * 2^(attempts-1)`, после 5 попыток `failed` (NT-R8).
- Ответ транспорта «429» с `retry_after`: `next_attempt_at` сдвигается, `attempts` не растёт (NT-R9).
- Ответ «403» или «400»: сразу `failed`, без повтора (NT-R10).
- `CancelPending(studentID)` переводит `pending` этого ученика в `cancelled` (NT-R13).

Часы передаются аргументом `now`, не `time.Now` внутри правил.
