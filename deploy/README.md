# Развёртывание

Здесь будут compose-файлы.

Образ Postgres — официальный `postgres:16`. Точный патч: `16.15` (тег `postgres:16.15` библиотеки `library/postgres` на Docker Hub, сверено 2026-11-09). Локально этого образа нет, есть только `postgres:17`, поэтому в этой сессии образ не скачивался.

`disk-check.sh PERCENT STATE` поднимает одну тревогу, когда процент диска больше 80, и молчит, пока процент не вернётся к 80 или ниже (OP-R16). Процент передаёт расписание сервера, например из `df`. `status-check.sh URL STATE` делает один запрос страницы состояния; расписание сервера вызывает его раз в минуту, тревога «сервис недоступен» — на третьей неудаче подряд (OP-R17). Адрес страницы в git не входит. `log-retain.sh DIRECTORY` удаляет файлы журналов старше 30 дней (OP-R18, D250). `alert-send.sh` печатает текст. В служебный чат он уходит только если `OPS_CHAT_ID` и `TELEGRAM_BOT_TOKEN` уже есть в окружении; значений в скриптах нет.

`compose.prod.yml` и `compose.staging.yml` описывают `web`, `core`, `content`, `db`, `gotenberg` и разовый шаг миграции до `core` и `web`. `gotenberg` (`gotenberg/gotenberg:9.5.0`) остаётся во внутренней сети, порт наружу не публикуется. `core` берёт его адрес из `PDF_GOTENBERG_URL`. У staging своя сеть. Тег образов приложения берётся из `IMAGE_TAG`, база — `postgres:16.15`. `backup.sh` и `restore-check.sh` шифруют копию ключом `BACKUP_ENCRYPTION_KEY` и отдают её в `BACKUP_STORAGE_URL`; значений секретов в git нет, имена — в `secrets.md`. В обоих compose `AUTH_DEV_MODE` выключен. Ночная проверка восстановления запускается по расписанию сервера, не из compose.
