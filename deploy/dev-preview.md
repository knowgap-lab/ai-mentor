# Локальная демонстрация ИИ-ментора

Подготовьте зависимости по разделу [локального запуска](../README.md#локальный-запуск). Для демонстрации нужны Go, Node/npm, локальный Docker Engine 28 или новее, `curl`, `psql` и проектный `.venv`. Запустите из корня рабочей копии:

```bash
bash tools/dev-preview.sh
```

Скрипт соберёт веб-приложение и API, применит миграции в отдельном временном PostgreSQL и заполнит его синтетическим сидом. Сервер напечатает SHA, состояние рабочей копии и адрес с выделенным локальным портом.

Откройте напечатанный адрес в браузере на той же машине. В форме репетитора введите `tg-demo-tutor`. В списке доступен `student-demo` с проведённым синтетическим уроком и уже сданным ДЗ. Черновик проведённого урока доступен по пути `/tutor/lessons/lesson-demo-held/homework`. Для проверки второго сеанса откройте отдельный профиль браузера. Тестовый вход ученика через `POST /auth/dev` использует `{"telegram_id":"tg-demo-student","role":"student"}`.

Сервер и PostgreSQL доступны через `127.0.0.1`. Оставьте их на этом адресе и используйте только локальный браузер. Для демонстрации нужны синтетические данные. Остановите скрипт через `Ctrl+C`. При штатной остановке удаляются временная база, сборка и серверный процесс.

## Проверка выдачи нового ДЗ

Для проверки API используйте отдельные тестовые сеансы репетитора и ученика.
Запросы изменения передают Origin локального адреса и CSRF по контракту.

1. От имени репетитора создайте синтетическому ученику `student-demo` урок по математике со временем начала на два часа раньше. Поставьте отметку `{"coverage":"all"}`.
2. Откройте черновик урока, добавьте вариант `ct-demo:D1.T01.S1.V005` и укажите срок на следующий день. Выдача через `/lessons/{lesson}/homework-draft/issue` должна вернуть 201.
3. От имени ученика откройте новую выдачу, отправьте ответ `13` с ключом идемпотентности и сдайте её. Ожидаемый итог — 2 из 2 баллов.
4. От имени репетитора прочитайте новую выдачу. Ожидаемый статус — `submitted`.
